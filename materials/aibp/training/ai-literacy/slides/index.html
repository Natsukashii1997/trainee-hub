大模型是怎么炼成的：三步

第一步 · 预训练

读海量文本，反复练习预测下一个 Token

实习生：先博览群书

第二步 · 后训练

看示范、被打分，学会听懂指令

第三步 · 使用（推理）

一个 Token 一个 Token 往下生成

第一层：模型本身必须会

概念大白话实习生比喻常见误区
大模型 / LLM从海量文本学出来、能理解和生成语言的模型读书多，但没在你这儿干过以为它在「查数据库」
模型 vs 产品模型是能力；产品是装着模型的软件，常带搜索、文件、记忆实习生本人 vs 加上他的工位和电脑把 ChatGPT（产品）和 GPT（模型）混为一谈
Token处理文字的基本单位；也是 API 计费单位按字数算的工作量一个 Token 就是一个汉字（各模型切法不同）
上下文窗口一次能「看到」的最大内容量，含你的输入和它的输出工作台的大小，放不下就看不见「聊得越久它越懂我」
幻觉生成看似合理、实际错误的内容不懂装懂、自信地答错回答越流畅越可信

4 分钟。可问：「聊很久后 AI 忘了一开始的要求——是哪个概念？」答：上下文窗口（超出窗口的早期内容会被截掉或压缩）。API = 软件之间的调用接口。

第一层：模型本身知道就行

概念大白话实习生比喻常见误区
参数模型内部可调的数值，「千亿参数」说的就是它脑容量参数越多就一定越好用
训练 vs 推理训练是「学」，推理是「用」；你平时用 AI 都是推理上学 vs 上班以为跟它聊天就是在训练它
多模态能处理文字以外的图片、语音、视频还能看图、听录音—
推理模型回答前先内部思考，适合数学、逻辑、规划类难题做题前先打草稿简单问题也用它，又慢又贵
开源 / 闭源开源（多是「开放权重」）能下载自己部署；闭源只能通过官方产品或接口用能不能把实习生请到自己家干活开源等于免费

2 分钟，快速过。补一句：多数产品不会实时学习；开源自己部署要算力，用接口照样付费。

第二层：提示词与上下文必须会

提示词 Prompt

你给 AI 的指令

实习生比喻：你给他的工作交代

× 有万能模板、写得越花哨越好

上下文 Context

模型此刻能看到的全部信息

系统设定对话历史你给的资料工具返回的结果

实习生比喻：交代任务时摊在桌上的所有材料

× 只说「帮我写周报」，不给素材

AI 答非所问，多半是上下文不够，
而不是提示词不够花哨。

开场演示第二次好得多——一半原因在这里。另一半，第五章揭晓。

3 分钟。周报回扣：L1 和 L2 的区别，本质就是上下文给得够不够。

让 AI 用上它本来不知道的资料：五种方式

方式怎么做什么时候用局限
直接给贴进对话或上传文件一次性任务、资料不多受上下文窗口限制，聊完就没了
联网搜索让 AI 实时搜网页再回答需要最新信息来源质量参差，要点开核对
知识库 / RAG先从资料库检索相关片段，再交给模型作依据资料多、要反复查检索错，答案照样错；能减少幻觉，不能消除
记忆 Memory产品存下你的偏好和关键信息，下次自动带上长期用同一个助手不是所有产品都有；记错了要手动改
微调用一批示例数据再训练模型企业、开发者的专门需求成本高，不适合用来「教它新知识」
常见误解想让 AI 懂我们公司，就要微调→想让它知道新资料，用前四种；微调改的是风格和能力

3.5 分钟。RAG = 检索增强生成。新人最容易混的一页，逐行讲。

第三层：工作流 vs Agent必须会

工作流 Workflow

人预先定好步骤，AI 按顺序执行

步骤 1→步骤 2→步骤 3

✓ 可预测、好管理

智能体 Agent

目标→？自己想办法→交付

实习生：交代目标后，自己办成

✓ 更灵活　× 更难预测、成本更高

工具和分身的区别

AI 工具岗位数字分身
存在方式你打开它，它才工作长期运行，出现在消息平台里
职责不承担岗位职责承担岗位的一部分沟通、值班、交付
积累技巧主要留在个人身上角色说明、知识、Skill 沉淀为可交接的资产
人不在时停止继续按规则运行，异常时找人

判断标准：能不能在人不在场时，独立、可靠地承担一个岗位的一部分工作。

参考混沌《数字分身》课程（刘雨飏）的对比并修正

2.5 分钟。修正点：原课程说工具「人走了，用法归零」；其实用法也能沉淀（Skill、项目说明文件）。真正区别是是否长期在岗、是否承担职责。

七层架构：一条消息要走完的路

L1接入层消息从哪里来：聊天软件、邮件、网页输入
L2沟通层理解意图，和人对话模型、提示词、上下文
L3调度层拆解任务、排定顺序、跟踪状态工作流、Agent
L4执行层实际干活，例如调用编程 Agent工具调用
L5能力层听、看、存等专项能力Skill、MCP、多模态
L6记忆层角色设定、长期记忆、项目知识记忆、知识库
L7资产层文件、数据、代码仓库资料来源
治理线贯穿所有层身份与权限人工确认点运行留痕异常处理结果回读

↓ 下行派活：理解需求 → 逐层分解 → 调用能力 → 触达资产　↑ 上行回流：执行结果 → 状态反馈 → 沉淀知识
青色一列＝第三章学过的概念。一门课程提出的教学框架，不是行业标准；只派活不回流，就形不成闭环。

4 分钟。下行：理解需求 → 逐层分解 → 调用能力 → 触达资产；上行：执行结果 → 状态反馈 → 沉淀知识。治理线是我们补的：没有它，分身越能干风险越大。这就是 P29 关系图的「岗位版」。

Hermes Agent：Nous Research 推出的开源 Agent。官方文档列出的能力，可以和七层一一对照。

七层Hermes 里对应的能力
接入层消息网关：Telegram、Discord、Slack、WhatsApp、Teams 等

文档列出的能力 ≠ 开箱即用：取决于部署、配置和授权。
