| 级别 | 做法 | 你的目标 |
|---|---|---|

## 附录 B｜热词速查手册

> 来自定稿 3.6。「课上」一栏：**讲** = 课上讲过；**知道** = 课上没讲，看到时查这里。看新闻、刷帖时遇到新词，先查这张表。

**模型与技术**

| 热词 | 含义 | 为什么值得知道 | 课上 |
|---|---|---|---|
| 混合专家 MoE | 模型内部分成很多「专家」，每次只调用其中一部分 | 让超大模型用得起：参数很大，但每次计算量小；DeepSeek 等国产模型降本的关键之一 | 知道 |
| 蒸馏 | 用大模型的输出去训练小模型 | 小模型也能有接近大模型的能力，便宜、能装进手机 | 知道 |
| 端侧模型 | 直接跑在手机、电脑上的模型 | 不联网也能用，数据不出设备，更保护隐私 | 知道 |
| 思维链 CoT | 让模型把推理过程一步步写出来 | 推理模型「先想再答」的基础；复杂问题更准 | 知道 |
| 温度 Temperature | 控制生成随机性的参数 | 解释「为什么同一个问题答案不一样」；低温更稳定，高温更有创意 | 知道 |
| 世界模型 | 能模拟物理世界如何变化的模型 | 通往机器人、自动驾驶、可交互视频的方向 | 知道 |
| 具身智能 | 有身体的 AI，即机器人 | AI 从屏幕里走到现实世界 | 知道 |
| AGI 通用人工智能 | 在大多数任务上达到或超过人类水平的 AI | 各大公司的长期目标；没有公认标准，听到「AGI 已来」要打个问号 | 讲 |

**用法与资料**

| 热词 | 含义 | 为什么值得知道 | 课上 |
|---|---|---|---|
| 提示词工程 | 研究怎么写指令让模型表现更好 | 普通人提升 AI 效果最直接的手段；模型越强，越看重「交代清楚」，而不是背技巧 | 讲 |
| 上下文工程 | 设计「让模型看到什么」：放哪些资料、按什么顺序、什么时候清理 | 2025 年后 Agent 圈的核心话题：长任务成败往往取决于上下文管得好不好，而不是提示词写得多巧 | 讲 |
| RAG 检索增强生成 | 先检索相关资料，再让模型据此回答 | 让 AI 用上私有、最新的资料，并能标出处；企业知识库问答几乎都基于它；能减少幻觉，不能消除 | 讲 |
| Embedding / 向量检索 | 把文字变成一串数字，按「意思相近」而不是「字面相同」来查找 | RAG 背后的检索技术；所以 AI 搜资料能「意会」 | 知道 |
| 深度研究 Deep Research | AI 自己搜几十上百个网页，写出带引用的研究报告 | 把几小时的资料调研压到几十分钟；仍要核对引用 | 讲 |
| 记忆 Memory | 产品跨对话记住你的偏好和事实 | 让 AI 越用越懂你；也意味着要定期检查它记了什么 | 讲 |

**行动与 Agent**

| 热词 | 含义 | 为什么值得知道 | 课上 |
|---|---|---|---|
| Agent 循环 / Agentic Loop | 想 → 做 → 看结果 → 再想，循环到完成 | Agent 能做长任务、能自我纠错的根本原因 | 讲 |
| Ralph 循环 Ralph Loop | 把同一份任务说明反复交给编程 Agent，每轮从干净的上下文开始只做一件事，靠测试等自动检查判断是否完成（2025 年提出，2026 年初走红） | 让 Agent 无人值守地连续干几小时；前提是有明确的自动验收标准，需求模糊的任务不适用 | 知道 |
| 函数调用 Function Calling | 模型输出一个结构化的「调用请求」，由程序去执行 | 工具调用的技术基础，AI 从「说」到「做」的开关 | 知道 |
| MCP | AI 应用连接外部工具和数据的开放协议 | 工具接一次，各家 AI 都能用 | 讲 |
| A2A | 让不同 Agent 之间互相通信、分派任务的开放协议（Google 发起） | 多 Agent 协作的「通用语言」；MCP 管 AI 连工具，A2A 管 Agent 连 Agent | 知道 |
| Skill | 带说明、脚本和资源的能力文件夹，按需加载 | 把「怎么做一件事」沉淀下来，团队共享、反复复用 | 讲 |
| 子 Agent / 多 Agent | 主 Agent 把子任务派给其他 Agent 并行完成 | 大任务拆开做更快；每个子 Agent 上下文更干净 | 知道 |
| Computer Use / 浏览器 Agent | AI 像人一样看屏幕、点鼠标、敲键盘操作电脑或网页 | 没有接口的软件也能被 AI 操作；目前还慢、还会出错 | 讲 |
| Harness | 包在模型外的运行框架：循环、工具、上下文、权限 | 同一个模型，Harness 不同，表现差别很大；这也是各家 Agent 产品的竞争点 | 知道 |
| Vibe Coding | 用自然语言描述需求，让 AI 写代码，自己不逐行看代码（Karpathy 2025 年提出） | 不会编程的人也能做出小工具；但上线前要有人懂得检查 | 讲 |
| AI 原生 AI Native | 从一开始就围绕 AI 设计的产品或工作方式 | 与「在旧流程上加一个 AI 按钮」相区别 | 知道 |

**质量与安全**

| 热词 | 含义 | 为什么值得知道 | 课上 |
|---|---|---|---|
| 人在回路 Human-in-the-loop | 关键步骤必须由人确认后才继续 | Agent 越能干越需要它；是「放手」和「放心」之间的平衡点 | 讲 |
| 闭环 / 反馈回路 | 执行结果回传，用来检查和改进下一次 | 没有回流的系统不会进步，也发现不了错误 | 讲 |
| 评测 Eval | 用一组固定题目和标准，衡量 AI 做得好不好 | 「感觉还行」不算数；换模型、改提示词前后都要测 | 知道 |
| 护栏 Guardrails | 限制 AI 不做危险或违规事情的规则和检查 | 让 AI 在边界内干活 | 知道 |
| 提示词注入 | 把恶意指令藏进网页、邮件、文件，诱导 AI 执行 | Agent 时代最主要的安全风险之一 | 讲 |
| 对齐 Alignment | 让 AI 的目标和行为符合人类意图与价值观 | 解释 AI 为什么会拒绝某些请求 | 知道 |
| AIGC | AI 生成的内容 | 国内常用说法；涉及内容标识等合规要求 | 知道 |

|---|---|---|---|
| ① | L1 | 大模型、提示词 | 只贴材料加一句话，没有交代格式和要求 |
| ② | L4 | 工作流或 Agent、工具调用、MCP、Skill | 定时自动从多个来源取数据生成初稿，人只做确认 |
| ③ | L2 | 提示词、上下文 | 附了模板、范文和素材，写明格式和约束 |
| ④ | L5 | 记忆、固定角色、长期在岗 | 长期运行、承担沟通（回答追问）、异常时找人 |
| ⑤ | L3 | 知识库 / RAG、办公 AI | 在办公软件里直接读本周纪要和文档 |

**评分要点**（5 题各 2 分，满分 10 分）：
- 级别对：1 分；关键概念对：1 分。
- ② 写成「Agent」或「工作流」都算对：定稿 L4 写的是「工作流或 Agent」，步骤固定的话工作流就够。
- 常见错误：把 ④ 定成 L4。区分点：L4 是「生成初稿发给你确认」，L5 是「长期在岗、承担一部分岗位职责、异常时找人」。

## 课堂练习 2｜四格判断

| # | 参考格子 | 理由 |
|---|---|---|
| ① | A 放心交给 AI | 起草类，一眼能看出好坏，发错代价小 |
| ② | B 抽查 | 翻译质量自己不一定能逐句判断，但只用于了解大意，代价小 |
| ③ | C 逐条核对 | 数字可以对照明细检查，但要交给财务，错了代价大 |
| ④ | D 不要交给 AI 做决定 | 医疗判断，自己难以检查、出错代价大；最多用来辅助理解报告里的名词 |
| ⑤ | A 放心交给 AI | 头脑风暴，好坏自己判断，代价小 |
| ⑥ | C 逐条核对 | 合同要点能对照原文检查，但出错代价大 |

**评分要点**：每题 1 分。② 如果学员说「我外语很好，能逐句检查」而放进 A，理由成立也给分。④ 放进 D 以外的格子不给分——这是底线题。

## 练习 3｜把 L1 升级成 L2

**L1 参考**：`帮我把下面的记录写成周报。`（后面贴上流水账）

**L2 参考提示词**（六要素齐全的一种写法，不是唯一答案）：

```
请把下面这份本周工作记录整理成一份周报。

【背景】这份周报给部门负责人看，用于周一的周会。负责人想快速了解本周进展、风险和下周安排。

【材料】只依据下面这份本周工作记录：
（贴上附录 A 的整周流水账）

【格式】分四段：完成事项 / 关键数据 / 问题与风险 / 下周计划。每段不超过 5 条，每条一句话。

【约束】
1. 只用我给的材料，不要补充材料里没有的内容。
2. 材料里没有提供的数字，写「待补充」，不要自己估算或编造。
3. 意思不确定的地方，原样保留并标注「待确认」。

【验收】每一条都要能在原始记录里找到依据；写完后，列出你标了「待补充」和「待确认」的地方。
```

**核验时应该发现的点**（讲师用；学员能发现 2 个以上即为优秀）：
1. **阅读量对比**：原文只说「比上上个月多一些（具体多少没算）」。如果周报里出现「增长 X%」之类的具体数字，就是编造，应改为「待补充」。
2. **报名人数**：原文是「报名页今天报名 46 人」，只能说明周四当天的情况。如果周报写成「累计报名 46 人」或「报名 46 人」不加限定，就越出了材料范围。
3. **物料时间**：周二说「推迟三天」，周四确认「下周一到」，以周四的信息为准；检查周报有没有把两条写矛盾。
4. **嵌入的计划和想法**：「想做个常见问题文档」是想法，不是已完成事项；检查它有没有被写进「完成事项」。
5. **逻辑越界**：如果周报出现「宣传效果显著」这类评价，原始记录里没有依据，应删掉。

**评分要点**（满分 10 分）：
- 六要素齐全：每项 1 分，共 6 分。「约束」里必须有「没提供的写待补充 / 不要编」这一句，缺这一句「约束」不给分。
- 核验表至少填了 3 项，且至少发现 1 个真实问题：3 分。
- 能说清 L2 比 L1 好在哪（例：格式固定、不编数字、每条可追溯）：1 分。

**检查要点**（讲师或带教人一周后检查用）：

## 自测 8 题

**1. 大模型的知识从哪里来？为什么它会编造？**
来自训练数据中的规律：预训练阶段读海量文本、反复练习预测下一个 Token，知识被压缩进参数。会编造是因为：没有内置的事实核对机制，生成的是「最可能的回答」而不是「正确的回答」；训练和评测往往奖励「猜一个答案」而不奖励「承认不知道」；训练数据有截止日期。
*要点*：答出「训练数据中的规律」+ 至少一个出错原因即可。

**2. ChatGPT 和 GPT 有什么区别？**
GPT 是模型，是能力；ChatGPT 是产品，是装着模型的软件，通常还带搜索、文件、记忆等功能。比喻：实习生本人 vs 实习生加上他的工位和电脑。

**3. 想让 AI 依据你的一份 50 页文档回答问题，可以用哪几种方式？**
- 直接给：上传文件或贴进对话。适合一次性任务；受上下文窗口限制，聊完就没了。
- 知识库 / RAG（或资料问答工具，如 NotebookLM、各产品的文件上传与知识库功能）：适合要反复查；能减少幻觉，不能消除。
- 加分点：指出「微调」不适合用来教它新知识；「联网搜索」查不到你自己的文档。

**4. 工作流和 Agent 的区别是什么？**
工作流由人预先设定步骤，AI 按顺序执行，可预测、好管理；Agent 由模型自己决定下一步做什么、用什么工具，直到完成目标，更灵活，但更难预测、成本更高。口诀：步骤固定 → 工作流；步骤要看情况定 → Agent。能用简单方案就不用复杂方案。
*加分点*：Agent 不是更强的新模型，而是模型 + Harness（运行框架）。

**5. AI 给了你一个统计数据，下一步该做什么？**
按核验四步处理：回到原始来源核对；数字单独重算、重查；有引用就点开，确认存在且确实支持结论；看结论有没有越出材料范围。核实不了的，不用，或标「待补充」。
*要点*：答出「回原始来源核对 / 单独重查」即得分；答「直接用」不得分。

**6. 以下哪些资料可以直接贴进对话助手？**
见课堂练习 5。规则：身份证号、银行卡号、密码、验证码、API 密钥绝对不贴；涉及他人的信息先脱敏；工作资料以单位规定为准；看一眼产品的数据设置。

**7. 周报做到哪一级才需要 Agent？**
L4：每周五自动拉取任务、日程、聊天记录，生成初稿发给你确认。L1–L3 都不需要 Agent。即使到了 L4，如果步骤是固定的，用工作流就够，不一定要 Agent。

**8. 数字分身和数字人有什么区别？**
数字分身讲「替岗位干活」：围绕一个岗位长期运行，有固定角色、知识与记忆、工具、触发方式和结果汇报；数字人讲「长得像人」：有虚拟形象和声音，重点在外表。两者可以结合，但不是一回事。

**自测计分建议**：每题 1 分，6 分及以上算掌握；第 1、4、5、6 题对应「必须会」的内容，错了要回看对应章节（P10–P11、P26、P46、P50）。
