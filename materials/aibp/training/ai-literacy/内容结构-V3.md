## 0｜开场：从一件熟悉的事开始

- ➕ **现场演示（3 分钟）**：把一段凌乱的工作流水账贴给 AI，让它整理成日报。先用一句话的提示，再用结构化的提示，让学员看到两次效果的差别。不解释原理，只留一个问题：「为什么第二次好这么多？」，到第五章揭晓。
- ➕ **一个提问**：「你今天用过 AI 吗？」输入法联想、短视频推荐、导航路线、拍照翻译都算。说明 AI 早就在身边，这门课要做的是**从无意识地用，变成有意识地用好**。
- ✅ **一个事实**：生成式 AI 三年内就被 53% 的人口用上，普及速度快过个人电脑和互联网（斯坦福 AI Index 2026）。
- ➕ **学完能做到**：
  1. 用大白话讲清大模型是怎么来的、为什么会出错
  2. 听到 Token、上下文、RAG、Agent、MCP、Skill 时，知道它指什么、彼此什么关系
  3. 按任务选对一类工具，并能用同一个任务比较两个工具
  4. 交代清楚一个任务，并核验 AI 的结果
  5. 判断什么资料能交给 AI、什么操作必须自己确认
  6. 说清 AI 工具、Agent、数字分身的区别
- ➕ **一句态度**：AI 是很强的助手。问题由你定义，判断由你做出，结果由你负责。

## 一、AI 是什么

### 1.1 一个定义
- ✅ 权威定义（OECD，2024 年更新版）的大意：AI 系统是一种基于机器的系统，根据收到的输入推断如何生成输出，输出可以是预测、内容、建议或决策；不同系统的自主程度不同。
- ➕ 大白话：**AI 是能根据输入，自己「推断」出结果的机器**。和普通软件的区别是：普通软件的每一步都由人写死；AI 的做法是从数据里学出来的。

### 1.2 AI 家族：几个容易混的词
- ➕ 套娃图：**人工智能 ⊃ 机器学习 ⊃ 深度学习 ⊃ 大模型**
  - 机器学习：从数据里学规律，不靠人写规则
  - 深度学习：用多层神经网络学习，是今天主流 AI 的技术基础
  - 大模型：用海量数据训练的超大规模模型；处理语言的叫大语言模型（LLM）
- ➕ 按「做什么」再分两类：
  - **判别式 AI**：做判断、做选择，比如人脸识别、垃圾邮件过滤、短视频推荐
  - **生成式 AI**：生成新内容，比如写文章、画图、作曲、写代码
- ➕ 结论：日常说的「AI」，现在多指**大模型驱动的生成式 AI**，本课只讲这一类。

### 1.3 大模型是怎么炼成的（三步）
- ✅ **第一步：预训练**。模型读海量文本，反复练习一件事：根据前文**预测下一个 Token**。练到足够大、足够多以后，语法、常识、推理套路都被压缩进模型的参数里。
  - ➕ 比喻：实习生先博览群书。
- ✅ **第二步：后训练**。用人工编写的问答示范做微调，再用人类反馈或自动评分做强化学习，让它学会听懂指令、按格式回答、拒绝有害请求。推理模型还额外练习「先想再答」。
  - ➕ 比喻：岗前培训，学会怎么干活、怎么说话。
- ✅ **第三步：使用（推理）**。你输入问题，它一个 Token 一个 Token 地往下生成。生成时带有随机性，所以同一个问题问两次，答案不完全一样。
  - ➕ 比喻：上岗答题。
- ➕ 一个纠正：常听到的「大模型就是猜下一个词」**只说对了一半**。生成方式确实是逐个预测，但经过后训练和推理训练，它已经能遵循复杂指令、分步解题。只用「猜词」来理解它，会低估它的能力。

### 1.4 为什么它像「懂」，又会出错
- ✅ 它的知识来自训练数据中的规律，**没有内置的事实核对机制**，生成的是「最可能的回答」，不保证是「正确的回答」。
- ✅ OpenAI 2025 年的研究指出：训练和评测方式往往奖励「猜一个答案」，而不奖励「承认不知道」，这是幻觉的重要成因。
- ✅ 训练数据有截止日期，之后发生的事它不知道，除非联网搜索。
- ➕ 结论：**流畅不等于正确**。这一点会在第二章、第五章反复出现。

### 1.5 主线：AI 从「会说」到「在岗」

| 形态 | 它做什么 | 例子 | 你和它的关系 |
|---|---|---|---|
| 对话助手 | 回答问题、写一段话 | 豆包、DeepSeek、ChatGPT | 你问它答 |
| 办公内嵌 AI | 在常用软件里帮你完成一步 | 会议软件的自动纪要、文档里的 AI 问答 | 你点它做 |
| 智能体 Agent | 自己规划步骤、调用工具，完成一整件事 | Claude Code、Codex、WorkBuddy、OpenClaw | 你派活，它交付 |
| 数字分身 | 有固定角色，长期在岗，替一个岗位承担一部分工作 | 用 Hermes 等 Agent 搭建的岗位助手 | 你不在，它也在干 |

- ➕ 预告第七章：工具用完就走，分身一直在岗。

## 二、AI 发展到哪一步了

### 2.1 一张路线图
- ➕ 教学地图：**规则系统 → 机器学习 → 深度学习 → 大模型与生成式 AI → 多模态与推理 → 工具调用与 Agent**。这几代技术今天仍然同时存在，不是后者完全取代前者。
- ✅ 关键节点（只讲「从此 AI 多了什么能力」，PPT 只放年份）：

| 年份 | 事件 | 意义 |
|---|---|---|
| 1956 | 达特茅斯会议提出「人工智能」一词 | 学科诞生 |
| 2012 | AlexNet 在图像识别比赛中大幅领先 | 深度学习时代开始 |
| 2016 | AlphaGo 战胜李世石 | AI 进入大众视野 |
| 2017 | 论文《Attention Is All You Need》提出 Transformer | 大模型的技术地基 |
| 2022 | ChatGPT 发布 | AI 第一次「会聊天」，普通人开始用 |
| 2023 | GPT-4 等多模态模型出现 | 能看图、能处理更复杂的任务 |
| 2024 | 推理模型出现（OpenAI o1）；Anthropic 发布 MCP 协议 | 会「先想再答」；连接外部工具有了统一标准 |
| 2025 | DeepSeek-R1 开源，追平当时顶尖模型；Claude Code、Codex 等编程 Agent 普及；Agent Skills 成为开放标准；MCP 捐给 Linux 基金会 | AI 从「会说」走向「会做」 |
| 2026 | 开源个人 Agent OpenClaw（昵称「小龙虾」）爆火，带起 Hermes Agent 等一批同类；大厂跟进推出托管版个人 Agent：国内有腾讯 WorkBuddy、Kimi Claw，海外有 Anthropic Claude Cowork、Meta Muse、xAI Grok Bot | 「个人 Agent 元年」：AI 开始替人长期干活、开始「在岗」 |

### 2.2 现在的状况：四个事实
- ✅ **能力还在加速**：一个代表性编程评测（SWE-bench Verified）上，最好成绩一年内从约 60% 升到接近 100%；在真实电脑任务评测（OSWorld）上，Agent 成功率从 12% 升到约 66%。（AI Index 2026）
- ✅ **中美差距基本抹平**：2025 年以来中美模型多次交替领先。（AI Index 2026）
- ✅ **普及极快**：组织采用率达 88%；五分之四的大学生在用生成式 AI。（AI Index 2026）
- ✅ **能力是「锯齿状」的**：AI 能拿国际数学奥赛金牌，读指针钟表的准确率却只有约 50%；Agent 在结构化任务上仍有约三分之一会失败。（AI Index 2026）
- ➕ 结论：**AI 不是均匀地变强**。它在某件难事上超过人，不代表它在一件简单事上一定靠谱。

### 2.4 能力边界：擅长什么，会在哪里出错（核心页）
- ➕ **擅长**：起草、改写、总结、翻译、归纳结构、出点子、写代码、解释概念、陪练
- ✅ **常见问题**：
  - **幻觉**：编造事实、数据、引用和链接，而且语气很自信
  - **时效**：不联网就不知道训练截止之后的事
  - **精确计算与计数**：大数运算、数字数、字数统计容易错，因为它按 Token 处理文字，而不是一个字一个字地看
  - **不了解你的情况**：你不给背景，它就不知道你的读者、标准和约束
  - **前后不一致**：同一问题多问几次，结论可能不同
  - **偏见**：训练数据里的偏见会带进回答
- ➕ 结论：**AI 的产出是初稿，不是结论。**

### 2.5 对每个人意味着什么
- ➕ 从「人用工具」变成「人带 AI」：能说清楚、可检查的工作逐渐交给 AI；定义问题、做判断、对结果负责留给人。
- ➕ 「会用 AI」的核心不是会多少个工具，而是两件事：**交代清楚**、**检查到位**。
- ✅ 专家与公众看法差距很大：73% 的专家认为 AI 对工作的影响是正面的，公众只有 23%（AI Index 2026）。可以作为讨论题：「你更接近哪一边？为什么？」

## 三、核心概念：一张图串起所有名词

### 3.0 先看一张总图
- ➕ 一次 AI 任务都在走这条路：**输入**（你的指令 + 资料）→ **模型处理** → **输出**（回答或动作）→ **检查**（你核验，或系统回读）
- ➕ 所有名词都挂在这条路上，分三层讲：
  - 第一层 **模型本身**：它是谁、有什么限制
  - 第二层 **怎么给它输入**：提示词、上下文、资料从哪来
  - 第三层 **怎么让它动手**：工具、Agent、Skill
- ➕ 每个概念统一四栏：**大白话 ｜ 实习生比喻 ｜ 常见误区 ｜ 要求**

### 3.1 第一层：模型本身

| 概念 | 大白话 | 实习生比喻 | 常见误区 | 要求 |
|---|---|---|---|---|
| 大模型 / LLM | 从海量文本中学出来、能理解和生成语言的模型 | 实习生的脑子：读书多，但没在你这儿干过 | 以为它在「查数据库」 | 必须会 |
| 模型 vs 产品 | 模型是能力，产品是装着模型的软件，通常还带搜索、文件、记忆等功能 | 实习生本人 vs 实习生加上他的工位和电脑 | 把 ChatGPT（产品）和 GPT（模型）混为一谈 | 必须会 |
| Token | 模型处理文字的基本单位，一个词、一个字或半个字都可能是一个 Token；也是 API 计费单位 | 按字数算的工作量 | 以为一个 Token 就是一个汉字（不同模型切法不同） | 必须会 |
| 上下文窗口 | 模型一次能「看到」的最大内容量，按 Token 计，包含你的输入和它的输出 | 工作台的大小，放不下的就看不见了 | 「聊得越久它越懂我」（超出窗口的早期内容会被截掉或压缩） | 必须会 |
| 幻觉 | 生成看似合理、实际错误的内容 | 不懂装懂、自信地答错 | 回答越流畅越可信 | 必须会 |
| 参数 | 模型内部可调的数值，「千亿参数」说的就是它 | 脑容量 | 参数越多就一定越好用 | 知道就行 |
| 训练 vs 推理 | 训练是「学」，推理是「用」；你平时用 AI 都是推理 | 上学 vs 上班 | 以为跟它聊天就是在训练它（多数产品不会实时学习） | 知道就行 |
| 多模态 | 能处理文字以外的图片、语音、视频 | 不只会读文件，还能看图、听录音 | — | 知道就行 |
| 推理模型 | 回答前先进行一段内部思考，适合数学、逻辑、规划类难题 | 做题前先打草稿 | 简单问题也用推理模型，又慢又贵 | 知道就行 |
| 开源 / 闭源 | 开源（严格说多是「开放权重」）指能下载模型自己部署；闭源只能通过官方产品或接口用 | 能不能把实习生请到自己家干活 | 开源等于免费（自己部署要算力，用接口照样付费） | 知道就行 |

### 3.2 第二层：怎么给它输入

**提示词与上下文**

| 概念 | 大白话 | 实习生比喻 | 常见误区 | 要求 |
|---|---|---|---|---|
| 提示词 Prompt | 你给 AI 的指令 | 你给实习生的工作交代 | 有万能模板、写得越花哨越好 | 必须会 |
| 上下文 Context | 模型此刻能看到的全部信息：系统设定、对话历史、你给的资料、工具返回的结果 | 交代任务时摊在桌上的所有材料 | 只说「帮我写周报」，不给素材 | 必须会 |

- ➕ 关键认知：**AI 答非所问，多半是上下文不够，而不是提示词不够花哨**。这也是开场演示里第二次效果好得多的原因。

**让 AI 用上「它本来不知道的资料」：五种方式**（➕ 新人最容易混，用一张表讲清）

| 方式 | 怎么做 | 什么时候用 | 局限 |
|---|---|---|---|
| 直接给 | 把资料贴进对话或上传文件 | 一次性任务、资料不多 | 受上下文窗口限制，聊完就没了 |
| 联网搜索 | 让 AI 实时搜网页再回答 | 需要最新信息 | 搜到的来源质量参差，要点开核对 |
| 知识库 / RAG | 先从资料库里检索相关片段，再交给模型作为回答依据 | 资料多、要反复查（制度、手册、产品库） | 检索不到或检索错，答案照样会错；能减少幻觉，不能消除 |
| 记忆 Memory | 产品把你的偏好和关键信息存下来，下次对话自动带上 | 长期使用同一个助手 | 不是所有产品都有；记错了要手动改 |
| 微调 Fine-tuning | 用一批示例数据再训练模型，改变它的风格或能力 | 企业、开发者的专门需求 | 成本高，**不适合用来「教它新知识」**；普通用户基本用不到 |

### 3.3 第三层：怎么让它动手

| 概念 | 大白话 | 实习生比喻 | 常见误区 | 要求 |
|---|---|---|---|---|
| 工具调用 | 模型决定调用某个外部功能（搜索、读文件、算数、发消息），拿到结果再继续 | 实习生会用电脑和各种软件 | 以为模型自己就能上网、能算准 | 知道就行 |
| MCP | 一套开放协议，规定 AI 应用怎么连接外部工具和数据源 | 统一规格的插座：工具做成 MCP 接口，各家 AI 都能接 | 以为 MCP 是一个工具或一个产品（它是标准） | 知道就行 |
| 工作流 Workflow | 由人预先设定好步骤，AI 按顺序执行 | 照着 SOP 一步步做 | 把工作流当成 Agent | 必须会 |
| 智能体 Agent | 由模型自己决定下一步做什么、用什么工具，直到完成目标 | 交代目标后，自己想办法办成的实习生 | 以为 Agent 是一个更强的新模型（它是模型加一套运行机制） | 必须会 |
| Agent 循环 Loop | Agent 干活的基本节奏：想一步 → 做一步（调工具）→ 看结果 → 再想下一步，循环到完成或卡住为止 | 实习生边做边看、发现不对就改 | 以为 AI 是「一次想好、一步到位」 | 必须会 |
| Skill | 一个打包好的能力文件夹：说明文档 + 可选的脚本和模板；Agent 需要时才加载 | 岗位作业手册：平时只看目录，用到哪章翻哪章 | 以为 Skill 就是一段提示词（它可以带流程、脚本和资源） | 知道就行 |
| Harness | 包在模型外面的整套运行框架：循环执行、工具、上下文管理、权限与审批 | 实习生的工位、电脑、权限卡和公司制度的总和 | 只理解成「规则」（它是整套运行环境） | 一句话带过 |
| 多 Agent 协作 | 多个 Agent 分工，互相传递任务和结果 | 一个小团队 | — | 一句话带过 |

- ✅ **工作流 vs Agent**（Anthropic 的区分）：工作流的步骤是写死的，可预测、好管理；Agent 的步骤由模型临场决定，更灵活，但更难预测、成本更高。**能用简单方案就不用复杂方案**。
- ➕ 对小白的判断口诀：步骤固定 → 工作流；步骤要看情况定 → Agent。
- ➕ **为什么「循环」是 Agent 的灵魂**：对话助手是「问一次、答一次」；Agent 能在循环里看到自己每一步的结果，出错了自己发现、自己重试，所以能完成几十步的长任务。代价是每转一圈都消耗 Token 和时间，而且可能在错误方向上越走越远，所以要设上限、留人工检查点。

### 3.4 关系图：它们怎么拼成一个 Agent
- ➕ **Agent = 模型（脑子）+ Harness（运行框架）**
  - 输入侧：提示词 + 上下文；资料来自直接提供、搜索、知识库、记忆
  - 行动侧：工具调用；通过 MCP 接入外部工具；按 Skill 的做法干活
  - 管理侧：权限、审批、日志，都属于 Harness
- ➕ 这张图在第七章会再出现：数字分身的七层架构，就是它的「岗位版」。

### 3.5 贯穿案例：周报的五个级别

| 级别 | 做法 | 用到的概念 | 对应形态 |
|---|---|---|---|
| L1 | 把流水账贴给 AI：「帮我写成周报」 | 大模型、提示词 | 对话助手 |
| L2 | 把任务交代清楚：附上模板、范文和本周素材，写明格式和要求 | 提示词、上下文 | 对话助手 |
| L3 | 在常用的文档或会议软件里，让 AI 直接读本周纪要和文档起草 | 知识库 / RAG、办公 AI | 办公内嵌 AI |
| L4 | 每周五自动拉取任务、日程、聊天记录，生成初稿发给你确认 | 工作流或 Agent、工具调用、MCP、Skill | 智能体 |
| L5 | 你的数字分身汇总发出，并回答同事的追问，异常时找你 | 记忆、固定角色、长期在岗 | 数字分身 |

- ➕ 结论：**小白先练熟 L1–L2，看懂 L3–L5**。

### 3.6 热词速查：听到这些词，知道它在说什么、为什么重要
- ➕ 课上只挑标「讲」的几个过一遍，其余发给学员当手册。「价值」一列回答：这个词为什么会火、它解决了什么问题。

**模型与技术**

| 热词 | 含义 | 价值：为什么值得知道 | 课上 |
|---|---|---|---|
| 混合专家 MoE | 模型内部分成很多「专家」，每次只调用其中一部分 | 让超大模型用得起：参数很大，但每次计算量小；DeepSeek 等国产模型降本的关键之一 | 知道 |
| 蒸馏 | 用大模型的输出去训练小模型 | 小模型也能有接近大模型的能力，便宜、能装进手机 | 知道 |
| 端侧模型 | 直接跑在手机、电脑上的模型 | 不联网也能用，数据不出设备，更保护隐私 | 知道 |
| 思维链 CoT | 让模型把推理过程一步步写出来 | 推理模型「先想再答」的基础；复杂问题更准 | 知道 |
| 温度 Temperature | 控制生成随机性的参数 | 解释「为什么同一个问题答案不一样」；低温更稳定，高温更有创意 | 知道 |
| 世界模型 | 能模拟物理世界如何变化的模型 | 通往机器人、自动驾驶、可交互视频的方向 | 知道 |
| 具身智能 | 有身体的 AI，即机器人 | AI 从屏幕里走到现实世界 | 知道 |
| AGI 通用人工智能 | 在大多数任务上达到或超过人类水平的 AI | 各大公司的长期目标；没有公认标准，听到「AGI 已来」要打个问号 | 讲 |

**用法与资料**

| 热词 | 含义 | 价值：为什么值得知道 | 课上 |
|---|---|---|---|
| 提示词工程 | 研究怎么写指令让模型表现更好 | 普通人提升 AI 效果最直接的手段；模型越强，越看重「交代清楚」，而不是背技巧 | 讲 |
| 上下文工程 | 设计「让模型看到什么」：放哪些资料、按什么顺序、什么时候清理 | 2025 年后 Agent 圈的核心话题：长任务成败往往取决于上下文管得好不好，而不是提示词写得多巧 | 讲 |
| RAG 检索增强生成 | 先检索相关资料，再让模型据此回答 | 让 AI 用上私有、最新的资料，并能标出处；企业知识库问答几乎都基于它；能减少幻觉，不能消除 | 讲 |
| Embedding / 向量检索 | 把文字变成一串数字，按「意思相近」而不是「字面相同」来查找 | RAG 背后的检索技术；所以 AI 搜资料能「意会」 | 知道 |
| 深度研究 Deep Research | AI 自己搜几十上百个网页，写出带引用的研究报告 | 把几小时的资料调研压到几十分钟；仍要核对引用 | 讲 |
| 记忆 Memory | 产品跨对话记住你的偏好和事实 | 让 AI 越用越懂你；也意味着要定期检查它记了什么 | 讲 |

**行动与 Agent**

| 热词 | 含义 | 价值：为什么值得知道 | 课上 |
|---|---|---|---|
| Agent 循环 / Agentic Loop | 想 → 做 → 看结果 → 再想，循环到完成 | Agent 能做长任务、能自我纠错的根本原因 | 讲 |
| Ralph 循环 Ralph Loop | 把同一份任务说明反复交给编程 Agent，每轮从干净的上下文开始只做一件事，靠测试等自动检查判断是否完成（2025 年提出，2026 年初走红） | 让 Agent 无人值守地连续干几小时；前提是有明确的自动验收标准，需求模糊的任务不适用 | 知道 |
| 函数调用 Function Calling | 模型输出一个结构化的「调用请求」，由程序去执行 | 工具调用的技术基础，AI 从「说」到「做」的开关 | 知道 |
| MCP | AI 应用连接外部工具和数据的开放协议 | 工具接一次，各家 AI 都能用；生态里已有上万个 MCP 服务 | 讲 |
| A2A | 让不同 Agent 之间互相通信、分派任务的开放协议（Google 发起） | 多 Agent 协作的「通用语言」；MCP 管 AI 连工具，A2A 管 Agent 连 Agent | 知道 |
| Skill | 带说明、脚本和资源的能力文件夹，按需加载 | 把「怎么做一件事」沉淀下来，团队共享、反复复用 | 讲 |
| 子 Agent / 多 Agent | 主 Agent 把子任务派给其他 Agent 并行完成 | 大任务拆开做更快；每个子 Agent 上下文更干净 | 知道 |
| Computer Use / 浏览器 Agent | AI 像人一样看屏幕、点鼠标、敲键盘操作电脑或网页 | 没有接口的软件也能被 AI 操作；目前还慢、还会出错 | 讲 |
| Harness | 包在模型外的运行框架：循环、工具、上下文、权限 | 同一个模型，Harness 不同，表现差别很大；这也是各家 Agent 产品的竞争点 | 知道 |
| Vibe Coding | 用自然语言描述需求，让 AI 写代码，自己不逐行看代码（Karpathy 2025 年提出） | 不会编程的人也能做出小工具；但上线前要有人懂得检查 | 讲 |
| AI 原生 AI Native | 从一开始就围绕 AI 设计的产品或工作方式 | 与「在旧流程上加一个 AI 按钮」相区别 | 知道 |

**质量与安全**

| 热词 | 含义 | 价值：为什么值得知道 | 课上 |
|---|---|---|---|
| 人在回路 Human-in-the-loop | 关键步骤必须由人确认后才继续 | Agent 越能干越需要它；是「放手」和「放心」之间的平衡点 | 讲 |
| 闭环 / 反馈回路 | 执行结果回传，用来检查和改进下一次 | 没有回流的系统不会进步，也发现不了错误（见 7.3） | 讲 |
| 评测 Eval | 用一组固定题目和标准，衡量 AI 做得好不好 | 「感觉还行」不算数；换模型、改提示词前后都要测 | 知道 |
| 护栏 Guardrails | 限制 AI 不做危险或违规事情的规则和检查 | 让 AI 在边界内干活 | 知道 |
| 提示词注入 | 把恶意指令藏进网页、邮件、文件，诱导 AI 执行 | Agent 时代最主要的安全风险之一 | 讲 |
| 对齐 Alignment | 让 AI 的目标和行为符合人类意图与价值观 | 解释 AI 为什么会拒绝某些请求 | 知道 |
| AIGC | AI 生成的内容 | 国内常用说法；涉及内容标识等合规要求（见 6.2） | 知道 |

## 四、AI 工具怎么选

### 4.1 原则：先选类别，再选产品
- ✅ 产品不等于模型：同一个产品可能组合多个模型和功能（搜索、文件、语音、数据分析），同一个模型也可能出现在不同产品里。比较的是「产品能不能完成你的任务」。
- ➕ 下面的产品只作例子，不是排名。

### 4.2 按任务选类别

| 任务 | 工具类别 | 例子 | 重点检查 |
|---|---|---|---|
| 写作、解释、总结、出点子 | 通用对话助手 | 豆包、DeepSeek、千问、Kimi、元宝、ChatGPT、Claude、Gemini | 是否理解任务、中文表现、修改成本 |
| 需要最新信息或带出处 | AI 搜索与深度研究 | 各对话助手的联网搜索 / 深度研究、秘塔 AI 搜索、Perplexity | 引用能否打开、来源是否真的支持结论 |
| 围绕一批资料问答 | 资料问答工具 | NotebookLM、各产品的文件上传与知识库功能 | 是否只依据你的资料、有没有标出处 |
| 会议、文档、表格里的活 | 办公内嵌 AI | 飞书、钉钉、企业微信、WPS、Microsoft 365 Copilot、Notion 自带的 AI | 资料权限、数据保存规则 |
| 表格和数据分析 | 带数据分析功能的助手 | 对话助手的数据分析功能、表格软件里的 AI | 数字、公式、统计口径 |
| 图片、语音、视频 | 多模态生成工具 | ❓ 生图、生视频、语音转写每类挑 1–2 个当月主流产品 | 版权、肖像权、成品质量 |
| 写代码、改项目 | 编程 Agent | Claude Code、Codex、Cursor、Trae | 文件权限、改动是否经过审查 |
| 重复性、多步骤的个人和办公事务 | 个人 / 办公 Agent | WorkBuddy、Kimi Claw、扣子空间、Claude Cowork、OpenClaw、Hermes Agent（详见 4.4） | 权限范围、人工确认、出错怎么恢复 |

### 4.3 对话助手怎么挑
- ➕ 看五点：中文能力、能否联网、能否处理长文档和文件、是否支持图片语音、价格与国内可用性
- ➕ 建议：**先把一个对话助手用熟**，再按需要加第二个，不要同时装十个

### 4.4 Agent 全景：2026 年最热的一类产品
- ➕ 先讲一个现象：2026 年初开源项目 OpenClaw（「小龙虾」）爆火，人们第一次大规模体验到「在聊天软件里给 AI 派活，它在后台替你办完」。随后大厂纷纷推出**免部署、托管式**的同类产品。理解这条线，就看懂了今年的 Agent 热潮。
- ✅ 按「替谁干活、怎么部署」分四类：

**① 编程 Agent：进入代码项目干活**

| 产品 | 出品方 | 特点 |
|---|---|---|
| Claude Code | Anthropic | 读懂代码库、改文件、跑命令和测试；终端、编辑器、桌面、网页都能用 |
| Codex | OpenAI | 读项目、改代码、跑测试，可在本地或云端并行处理多个任务 |
| Cursor、Trae、Kimi Code、CodeBuddy 等 | 各家 | 编辑器型或命令行型的编程助手 |

**② 开源、自部署的个人 Agent：自由度最高，门槛和风险也最高**

| 产品 | 出品方 | 特点 | 注意 |
|---|---|---|---|
| OpenClaw | 开源社区（OpenClaw 基金会） | 跑在自己电脑上，通过 Telegram、WhatsApp、Discord 等聊天软件使用，能接邮件、日程，可换不同模型 | 权限大；安全研究发现第三方 Skill 存在窃取数据和提示词注入问题；维护者自己也提醒不会用命令行的人不要碰 |
| Hermes Agent | Nous Research | 持久记忆、从经验中生成和改进 Skill、定时任务、子 Agent 分工；可部署在云服务器上，通过聊天软件远程使用 | 需要自己部署和配置 |

**③ 大厂托管的个人 / 办公 Agent：下载即用，替你操作各种应用**

| 产品 | 出品方 | 特点 | 国内可用 |
|---|---|---|---|
| WorkBuddy | 腾讯 | 办公 Agent，兼容 OpenClaw 技能和 MCP，可接企业微信、QQ、飞书 | 可用 |
| Kimi Claw | 月之暗面 | 云端免部署版「小龙虾」，面向高级会员 | 可用 |
| 扣子空间 | 字节跳动 | 通用 Agent，可接 MCP | 可用 |
| Claude Cowork | Anthropic | 桌面版 Claude 在你指定的文件夹里干活，面向不写代码的人 | 否 |
| ChatGPT Agent | OpenAI | 在 ChatGPT 里自主浏览网页、执行任务 | 否 |
| Muse | Meta | 2026 年 9 月上线的个人 Agent App，接邮箱、日历、购物等应用，Agent 在云端虚拟机里后台运行，发邮件和下单前需你确认；上线不久即登顶美区应用榜 | 否 |
| Grok Bot | xAI | 2026 年 8 月推出的测试版「AI 队友」，每个 bot 有自己的云电脑，演示一次流程即可学会，付款和对外发消息需你批准；目前只对高价订阅用户开放 | 否 |

**④ AI 浏览器：在浏览器里替你操作网页**
- Perplexity Comet 等：浏览网页时让 AI 直接帮你点、填、比较

- ➕ 一个辨析：X 上常见的「@grok 这是真的吗」是 Grok 在帖子下自动回复，属于对话助手；Grok Bot 才是 Agent。
- ➕ 共同规律，讲给学员：
  - 越能干的 Agent，要的权限越大，**风险也越大**；大厂托管版的价值之一就是替你管好部署和安全
  - 几乎所有产品都把「付款、对外发消息、删除」设为**必须人工确认**，这正是第六章「人在回路」的实例
- ➕ 对小白的建议：先用国内可用、托管式的产品体验（如 WorkBuddy、Kimi Claw、扣子空间），**从权限最小、可撤销的任务做起**；开源自部署的等熟悉后再碰。

### 4.5 怎么比较两个工具
- ➕ **同一个任务、同一份输入、同一套标准**，分别交给两个工具，比较：结果质量、事实依据、返工量、上手难度、价格、数据规则
- ➕ 功能列表长，不代表在你的任务上更好用

### 4.6 怎么收费
- ✅ 三种常见方式：免费版（有额度或功能限制）、按月订阅、按 Token 计费的 API（开发者和 Agent 常用）
- ➕ 提醒：开源软件免费，但它调用的模型、服务器照样可能收费

### 4.7 避坑
- ✅ 不要一开始就开放全部文件和系统权限
- ✅ 删文件、发邮件、对外发布等重要操作，保留人工确认
- ✅ 产品功能更新快，以官方说明为准

## 五、用 AI 完成工作：场景、方法与练习

### 5.1 能做什么：按动作找场景

| 动作 | 典型场景 |
|---|---|
| 写 | 日报周报、邮件、通知、文案、简历、发言稿初稿 |
| 读 | 长文档摘要、合同要点、会议纪要、外文资料翻译 |
| 查 | 资料调研、陌生领域入门、比价与攻略 |
| 理 | 把零散笔记整理成统一格式、提炼结构、做对比表 |
| 算 | 表格清洗、分类统计、出图（数字必须复核） |
| 练 | 模拟面试、口语陪练、让它出题考你 |
| 做 | 做 PPT、写小工具、搭自动化（Agent 级别） |

- ➕ 不同人群各举一例，让每个人都能对上号：职场通用（周报、纪要、邮件）、销售客服（话术、沟通记录整理）、运营市场（文案、选题、数据周报）、学生求职（读论文、改简历、模拟面试）、个人生活（攻略、学习计划、看懂合同和说明书）
- ❓ 每类准备 1 个「AI 初稿 vs 人改后」的对比示例（自己制作，注意脱敏）

### 5.2 先判断：这件事适不适合交给 AI
- ➕ 两个问题，画成四格：
  - **结果好不好检查？**（你能不能一眼看出对错）
  - **出错代价大不大？**

| | 好检查 | 难检查 |
|---|---|---|
| 出错代价小 | ✔ 放心交给 AI（起草、改写、头脑风暴） | 可以用，抽查（翻译、摘要） |
| 出错代价大 | 可以用，逐条核对（数据报表、合同要点） | ✘ 不要交给 AI 做决定（医疗、法律、财务判断）；最多用来辅助理解 |

### 5.3 交代任务：六件事说清楚
- ➕ 把实习生比喻落地：给新人交代任务要说什么，给 AI 就说什么。

| 要素 | 要回答的问题 | 周报例子 |
|---|---|---|
| 任务 | 要做什么 | 把本周工作记录整理成周报 |
| 背景 | 给谁看、为什么 | 给部门负责人看，用于周会 |
| 材料 | 依据什么 | 附上本周工作记录 |
| 格式 | 交成什么样，最好附一个范例 | 分「完成事项 / 关键数据 / 问题与风险 / 下周计划」四段，每段不超过 5 条 |
| 约束 | 不能怎样 | 只用我给的材料；没提供的数字写「待补充」，不要自己编 |
| 验收 | 怎样算合格 | 每条都能在原始记录里找到依据 |

- ➕ 补充说明：
  - 「你是一位资深 XX」这类角色设定可以用，但不是关键，**材料和要求比角色重要得多**
  - 「没提供的写待补充」这一句最值钱，能大幅减少编造
- ➕ 四个好习惯：
  1. **背景给足**：答非所问时先补材料，不要先换说法
  2. **一次只聊一件事**：换话题就开新对话，避免旧内容干扰
  3. **让它先问你**：任务复杂时说「开始前先问我缺什么信息」
  4. **迭代**：第一版不满意，具体指出哪里不对，让它改

### 5.4 检查结果：核验四步
- ➕ **事实**：关键事实回到原始来源核对
- ➕ **数字**：数字和日期单独重算、重查
- ➕ **引用**：链接和出处逐条点开，确认存在且确实支持结论
- ➕ **逻辑**：因果关系、结论是否越出了材料范围
- ➕ 养成**错误记录**的习惯：记下错误类型、在什么情况下出错、怎么发现的。一个月后你就知道 AI 在你的工作里哪里靠得住、哪里靠不住。

### 5.5 现场演示与练习
- ➕ **演示一：写周报**（揭晓开场问题）：同一份流水账，L1 一句话 vs L2 六要素，对比两次结果；再演示核验四步，当场抓出一处问题
- ➕ **演示二：把一份长资料变成能用的东西**：长文 → AI 摘要 → 追问细节 → 生成一页简报或对比表 → 回原文核对关键数字
- ➕ **学员练习**：用六要素重写自己最近一次向 AI 提的问题，对比前后结果，并说出自己检查了哪几项

## 六、安全、合规与责任

> 底线单独成章，但在第四、五章的演示中也要穿插提醒，不要只在最后讲一页。

### 6.1 隐私：什么不能往 AI 里贴
- ➕ 绝对不贴：身份证号、银行卡号、密码、验证码、API 密钥
- ➕ 涉及他人的信息（姓名、电话、聊天记录、照片）先脱敏
- ✅ 看一眼产品的数据设置：很多产品允许关闭「用我的对话改进模型」；不同产品对上传文件的保存规则不同
- ➕ 在职人员：工作资料能不能用、用哪个工具，以所在单位的规定为准

### 6.2 版权、署名与诚信
- ➕ AI 生成的内容可能与已有作品相似；商用的图片、文案要留意版权和肖像权
- ➕ 学习、考试、投稿有各自对 AI 使用的规定，按规定说明 AI 参与了什么
- ✅ 国内规定：《人工智能生成合成内容标识办法》自 2025 年 9 月 1 日起施行，要求 AI 生成的文字、图片、音视频等内容按规定添加标识；发布 AI 生成内容时，留意平台的标识要求
- ❓ 上课前按原文核一遍标识办法的适用对象与具体要求

### 6.3 防骗：AI 也会被用来骗你
- ➕ AI 换脸、仿声已经被用于诈骗；涉及转账、验证码的请求，即使「声音像本人」「视频里是本人」，也要换一个渠道再确认

### 6.4 Agent 的特殊风险
- ✅ **提示词注入**：网页、邮件、文件里可能藏着写给 AI 的指令，诱导 Agent 做你没让它做的事
- ✅ **第三方插件和 Skill 可能有恶意代码**：只装来源可信的
- ➕ 三条原则：权限给最小、重要操作自己确认（即「人在回路」）、定期检查它做了什么

### 6.5 责任在人
- ➕ AI 的产出是草稿；对外发送、做决定、做承诺，由人确认、由人负责

## 七、进阶：数字分身（以 Hermes 为例）

> 定位：让学员看懂 AI 正在往哪里走。只要求理解，不要求搭建。

### 7.1 先分清四个说法

| 说法 | 是什么 | 例子 |
|---|---|---|
| AI 工具 | 你发起一次任务，它给出结果，用完就结束 | 打开对话助手问一个问题 |
| Agent | 围绕一个目标，自己选步骤、调工具 | 让编程 Agent 修一个 Bug |
| 数字分身（岗位分身） | 围绕一个岗位长期运行：有固定角色、知识与记忆、工具、触发方式和结果汇报 | 每天整理行业资讯并推送、在群里答复常见问题的助手 |
| 数字人 | 有虚拟形象和声音的 AI，重点在「外表」 | 虚拟主播、数字人客服 |

- ➕ 数字分身 ≠ 数字人：分身讲的是「替岗位干活」，数字人讲的是「长得像人」，两者可以结合，但不是一回事。

### 7.2 工具和分身的区别
- ✅ 参考《数字分身》课程（混沌，刘雨飏）的对比，加以修正：

| | AI 工具 | 岗位数字分身 |
|---|---|---|
| 存在方式 | 你打开它，它才工作 | 长期运行，出现在消息平台里 |
| 职责 | 不承担岗位职责 | 承担岗位的一部分沟通、值班、交付 |
| 积累 | 技巧主要留在个人身上 | 角色说明、知识、Skill 沉淀为可交接的资产 |
| 人不在时 | 停止 | 继续按规则运行，异常时找人 |

- ✅ 判断标准：**能不能在人不在场时，独立、可靠地承担一个岗位的一部分工作**
- ➕ 修正说明：原课程说工具「人走了，用法归零」。其实工具的用法也能沉淀（Skill、项目说明文件都能共享）；真正的区别在于**是否长期在岗、是否承担职责**。

### 7.3 七层架构：一条消息要走完的路
- ➕ 说明：这是该课程提出的一种**教学框架**，不是行业标准；用它的好处是能把第三章的概念串成一个完整系统。

| 层 | 名称 | 做什么 | 对应第三章概念 |
|---|---|---|---|
| L1 | 接入层 | 消息从哪里来：聊天软件、邮件、网页 | 输入 |
| L2 | 沟通层 | 理解意图，和人对话 | 模型、提示词、上下文 |
| L3 | 调度层 | 拆解任务，排定顺序，跟踪状态（已接收 → 进行中 → 完成 / 失败） | 工作流、Agent |
| L4 | 执行层 | 实际干活，例如调用编程 Agent | 工具调用 |
| L5 | 能力层 | 听、看、存等专项能力 | Skill、MCP、多模态 |
| L6 | 记忆层 | 角色设定、长期记忆、项目知识 | 记忆、知识库 |
| L7 | 资产层 | 文件、数据、代码仓库 | 资料来源 |

- ✅ 原课程强调的两个方向：**下行派活**（理解需求 → 逐层分解 → 调用能力 → 触达资产）、**上行回流**（执行结果 → 状态反馈 → 沉淀知识）。只派活不回流，就形不成闭环。
- ➕ 补一条**贯穿所有层的治理线**：身份与权限、人工确认点、运行留痕、异常处理、结果回读。没有这条线，分身越能干，风险越大。
- ➕ 讲法要点：右列就是 3.4 那张关系图，学员会发现前面学的概念在这里拼成了一个岗位。

### 7.4 用 Hermes 看一个真实的实现
- ✅ Hermes Agent 是 Nous Research 推出的开源 Agent，官方文档列出的能力可以和七层一一对照：

| 七层 | Hermes 里对应的能力 |
|---|---|
| 接入层 | 消息网关：Telegram、Discord、Slack、WhatsApp、Teams 等 |
| 沟通层 / 记忆层 | SOUL.md 设定角色与语气；MEMORY.md、USER.md 跨会话记住偏好、项目和环境 |
| 调度层 | 定时任务；派生子 Agent 并行处理 |
| 执行层 / 能力层 | 60 多个内置工具（搜索、终端、文件、浏览器等）；可连接 MCP；Skill 遵循 Agent Skills 开放标准，能从经验中生成和改进 |
| 治理线 | 命令审批、授权、容器隔离；改文件前自动存档，可回滚 |

- ➕ 提醒：文档列出的能力不等于开箱即用，能否运行取决于部署、配置和授权。
- ❓ 准备一个可公开演示的例子（例如每日资讯简报、定时提醒、群内常见问题答复），使用模拟数据，附演示脚本与效果截图。

### 7.5 什么样的工作适合交给分身
- ➕ 四个条件：输入明确、输出可检查、出错能被发现、高风险动作有人工确认
- ➕ 不适合：需要临场判断、出错代价大、责任不能转移的工作

### 7.6 从小白到会带分身：一条成长路径
- ➕ 五步，与周报五级对应：**会问**（L1）→ **会交代**（L2）→ **会用办公 AI**（L3）→ **会给 Agent 派活**（L4）→ **会设计分身**（L5）
- ➕ 结论：**这门课结束时做到第二步就够了**，后面三步是接下来的方向。
