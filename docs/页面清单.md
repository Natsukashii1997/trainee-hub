# 页面清单（v2.0 骨架版）

第 3 步 UI 施工的依据。对象、命令编号和级别都以 [PRD](PRD.md) 上篇为准：命令见第 4 节，级别见第 10 节。

- **级别：** **A** = 真实接口、真实持久化；**B** = 可交互原型（入口、布局、数据展示和操作流程都确定，用前端示例数据，不建表、不接接口）；**C** = 只占位，写明以后做什么。
- **给谁：** 管 = 管培生；带 = 带教；管理 = 有管理权限的带教。骨架期带教可以进所有页面（PRD 2.3），表里写的是这一页**为谁设计**。
- **路由**是新结构的建议路由，第 3 步实现时可以微调，但改了要同步本表。
- **原型来源**写现有原型里可以复用的页面（路由与文件），对应关系见[资产处置清单](research/2026-11-08-v2/资产处置清单.md)。

## 核心路径（第 3 步验收用）

两种角色都要能走通：

1. 管培生：首页 → 新建项目（P1）→ 带教在首页确认立项（W2）→ 管培生在项目详情新建节点并开始（P2、P3）→ 提交 V1（P3）→ 带教从待办进入评审「需改进」并写下一步行动（W3 → P3）→ 管培生首页看到「最重要的下一步」（W1）→ 修改再交 V2（P3）→ 带教评审通过、认定关联培养任务、提炼能力证据（P3）→ 管培生在任务详情看到认定（T2）→ 管培生填写项目结论、带教确认结项（P2）→ 成长档案里能看到项目经历、成果和能力证据，并点回来源（T3）。
2. 受阻支线：管培生在节点标记受阻（P3）→ 带教首页「待我判断」出现（W2）→ 带教响应，节点仍受阻（P3）→ 管培生解除受阻（P3）。

页面状态逐一检查：空数据、待提交、待评审、需修改、已通过、受阻、已结项。
