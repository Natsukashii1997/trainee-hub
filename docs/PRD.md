## 1. 定位

管培生团队的工作台：把**培养路径、飞书资料、AI 资产与贡献**聚合在一处，管培生、带教人和管理员每天都用。

- 第一版只服务管培生团队（约 12 人一期）。数据结构预留"团队/部门"维度，以后可扩展到全公司，但全公司版不在本期范围。
- 不设单一主线，六个板块同等重要。对管培生，培养路径是第一位；对管理员，AI 赋能同样重要。
- 内容由常浩一人维护；带教人可提建议；管培生只读，只提交自己的产出和贡献。具体维护节奏以后再定。

## 2. 角色

| 角色 | 能做什么 |
|---|---|
| 管培生 | 看自己的路径与任务、提交产出、使用和贡献 AI 资产、看团队公开内容 |
| 带教人 | 看所带管培生的进度、点评产出、贡献资料与资产 |
| 管理员 | 维护全部内容与路径模板、审核贡献、看全局数据、分配角色 |
| 同事 | 浏览公开内容（AI 资产库、资料、作品集）、可贡献；看不到培训私有数据。第一版可与带教人合并，但定义上单列 |

- 登录：**只用飞书登录**（飞书内免登），只有公司飞书成员能进。不做账号密码登录。
- 角色由管理员在后台指定，新登录的人默认是"同事"。
- 所有可见性规则在**服务端**执行，不能只靠前端隐藏。

## 3. 信息架构

一级导航 6 个：**首页、成长、知识、AI、团队、激励**。顶栏有全局搜索（⌘K）和通知；头像进入"我的档案"。工具导航不单列，放在首页侧栏或页脚。

| 板块 | 页面 |
|---|---|
| 全局 | 全局搜索（一次搜资料、AI 资产、FAQ、作品集）、通知中心 |
| 首页 | 我的今天（首屏按角色切换）+ 团队动态 |
| 成长 | 路径总览（模板）、我的路径与进度、任务详情（要求 + 提交 + 点评）、带教看板、轮岗日历、考核（轻测记录、阶段评估、答辩材料包） |
| 知识 | 资料库（按标签筛选，点开跳飞书）、FAQ、作品集（列表 + 详情） |
| AI | AI 首页（Tidings 入口 + 内部精选）、资产库、资产详情、提交资产、AI 学习路径、用例墙 |
| 团队 | 成员列表、个人档案、公告与动态、活动、周报汇总 |
| 激励 | 贡献榜（月榜、总榜）、我的积分明细、兑换商城、我的兑换申请 |
| 管理后台（仅管理员） | 成员与角色、路径模板编辑、个人路径分配、审核队列（资产、资料、作品集）、公告发布、积分规则与加权、兑换处理、标签维护、知识库同步设置、机器人接口密钥 |

### 3.1 首页

布局为"首屏放个人、下方放团队动态"，首屏按角色切换（视觉稿已定，见附录 A）：

- **管培生**：今日焦点（今天和明天截止的两件事，带倒计时或完成度）→ 我的进度（进度环 + 阶段 + 轮岗六站）→ 本周任务表 → 最新点评、"这一步可以用"（AI 推荐）、当前岗位资料 → 团队动态、贡献榜、Tidings 入口。
- **带教人**：焦点放"等得最久的待点评"和"需要跟进的逾期"→ 带教看板（每人岗位、本周提交、最近评价、状态）→ 待点评队列、本周带教安排、我贡献的资产、团队动态。
- **管理员**：焦点放"审核队列"和"有逾期的人"→ 指标条（按时提交率为主指标，配趋势；平均进度、本月新上架资产、本周活跃）→ 全员进度、审核队列（可直接通过或退回）、连接状态（机器人接口、知识库同步、多维表格迁移）、最近公告、贡献榜。

### 3.2 个人档案（全站汇总点）

每个人一页，自动汇总：成长时间线、路径进度、提交过的产出、点评、贡献的资产、参与的活动、积分与徽章。其他模块产生的数据都记到具体的人名下。

- 对本人、带教人和管理员完整可见；对其他同事只展示公开部分（贡献、作品、进度状态），隐藏考核和点评。

## 4. 成长

### 4.1 路径结构

- 三层：**阶段 → 模块（轮岗岗位）→ 任务**。阶段示例：入职、通识、轮岗、定岗。
- **路径模板**由管理员维护，所有人可见；**个人路径**从模板派生，带上这个人的起止日期、轮岗顺序、每个模块的带教人。
- 轮岗日历不单独维护，由所有人的个人路径汇总生成。

### 4.2 任务

- 字段：名称、说明、要求（标准）、产出形式（文档、路演、表格、复盘）、截止时间、带教人、关联资料（来自知识板块）、推荐 AI 资产（来自 AI 板块）。
- 两种类型：**路径任务**（属于某个模块）和**周期任务**（日报、周报、月度物料、轻测，贯穿整个培养期）。"我的进度"分两栏展示。
- 产出以**飞书文档链接**提交，工作台不存文件。
- 状态流转：未开始 → 进行中 → 已提交 → 需修改 / 已通过；超过截止时间自动标"逾期"。
- 点评：带教人写文字评语，加三档评价（优秀 / 达标 / 需改进），不打分数。

### 4.3 考核

- 轻测记录：机器人出题，成绩写回工作台。
- 阶段评估：每阶段结束时带教人填写（三档 + 评语），管理员确认。
- 定岗答辩材料包：从个人档案一键汇总全部产出、点评和贡献。

### 4.4 可见性

- 进度状态（走到哪一步）对团队公开。
- 产出内容、点评、考核只给本人、带教人和管理员。
- 优秀产出经本人同意后进入作品集，对外展示。

## 5. 知识

- 资料本体留在飞书现有的"管培生知识库"空间。工作台自动同步目录，以**资料卡片**展示（标题、链接、摘要、标签、关联阶段或任务），人工补标签、挂到任务。文档正文不进工作台，访问权限由飞书判断。
- 标签四个维度，资料、AI 资产、作品集共用：
  - 阶段/模块：直接引用路径结构，不另外维护；
  - 主题：行研、营销、客服、内容、投放、教学、AI、通用技能等；
  - 类型：SOP、模板、案例、培训材料、制度规范、工具指南；
  - 岗位：老师线、客户线、市场等。
  - 后三个维度是固定列表，由管理员维护，贡献者只能选不能新建。
- FAQ：提问统一在飞书找带教机器人；机器人审核入库的问答在工作台展示，可按标签筛选和搜索。工作台不做提问入口。

## 6. AI

- 内部资产四类：**Skill、Prompt、工作流/SOP、用例**（用例展示在用例墙）。
- 字段：标题、类型、一句话说明解决什么问题、适用岗位和场景标签、使用方法（Skill 给可复制的安装指令，Prompt 展示全文可一键复制）、示例输入输出、作者、版本、更新时间、关联的成长任务。
- Skill 文件直接存在工作台（上传或粘贴），格式沿用 `my-skills` 的 SKILL.md 规范（开头 YAML 含 name、description）。管培生不需要会用 GitHub。
- 贡献流程：任何人提交 → 管理员审核（通过上架 / 退回修改）→ 上架后可收藏、标记"我用过"、留言。**审核通过时写入作者的贡献记录**。
- 外部发现：Tidings（`https://tidings.natsukashii.cn`）**只做跳转入口**，不做数据打通。

## 7. 团队

- 成员档案字段：姓名、头像、入职日期、当前阶段或岗位、带教人；本人填写自我介绍和擅长领域；其余自动汇总。
- 公告只由管理员发；动态流自动生成（新资产上架、通过阶段评估、新案例入库、活动预告），不出现考核结果。
- 活动：分享会、路演、读书会。日程读飞书日历，结束后挂飞书妙记回放链接。第一版不做报名。
- 周报：机器人收周报，工作台挂到本人档案时间线；团队页按周汇总，只显示谁交了、谁没交。

## 8. 激励

- 原则：**积分只奖励对团队的贡献，不奖励完成本职培训任务**（那由考核负责）。
- 计分行为（分值以后定）：资产上架（Skill > 工作流/SOP > Prompt > 用例）、资产被他人标记"我用过"（按次累计、设上限）、资料贡献、FAQ 补充、担任分享会主讲、优秀产出入选作品集。管理员审核时可手动加权。
- 兑换物以 AI 工具额度、学习资源、特权荣誉为主，实物为辅；预算由常浩向公司申请。第一版流程是"线上申请，管理员线下发放"，不对接支付或采购系统。
- 排行设月榜和总榜，只按贡献积分排名。徽章作为不可兑换的荣誉，展示在个人档案上。
- 贡献记录从一期就开始存，三期上线积分时按历史补算。

## 10. 带教机器人接口

机器人（`~/Documents/AI 项目/outputs/管培生带教-AI协同`）负责飞书里的推送和对话，工作台负责展示和沉淀。机器人改为通过工作台接口读写，不再直接读写多维表格。

- 认证：后台签发的接口密钥，按权限范围限制。
- 一期需要的接口（草案）：
  - 读：成员与角色、个人路径与当前任务、即将到期和已逾期的任务；
  - 写：提交记录（飞书链接）、周报、轻测成绩、入库的 FAQ。
- 切换方式（过渡切换）：
  1. 工作台上线后，从多维表格 `project_base` 一次性导入历史数据（项目、任务、成员）；
  2. 机器人逐个功能切到工作台接口；
  3. 到截止日期后，多维表格只读归档。
- 全程不做双向同步。机器人的改造在机器人那个项目里做，不在本仓库。

## 11. 技术方案

- 自己开发网站：前端 React + Vite，后端 Node（TypeScript），数据库 PostgreSQL，用 Docker Compose 打包。
- 开发期在本机运行（只监听 127.0.0.1）；上线部署到公司服务器（服务器环境待常浩确认）。
- **只做电脑版**（≥1280px），不做窄屏适配。

## 12. 分期

| 期 | 范围 |
|---|---|
| 一期 | 飞书登录与角色、个人档案（基础）、成长路径（模板、个人路径、任务、提交、点评、带教看板）、AI 资产库与贡献审核、Tidings 入口、首页（三种角色）、管理后台基础功能、机器人接口 |
| 二期 | 知识库同步、资料卡片与标签、FAQ、考核模块、全局搜索、团队板块（公告、活动、周报）、作品集；机器人过渡切换与此并行 |
| 三期 | 积分、排行、兑换、徽章、用例墙、AI 学习路径 |

## 13. 成功标准

- 主指标：**阶段产出按时提交率**（管理员首页首位展示）。
- 辅助指标：平均培养进度与计划的差距、本月新上架资产数、周活跃人数。

## 14. 待定事项

- 内容维护的节奏与分工（第 1 节）。
- 积分的具体分值、兑换物清单与预算。
- 公司服务器环境（系统版本、能否用 Docker、域名与 HTTPS）。
- 培养路径的正式内容：目前散落在会议笔记里，需要常浩整理成"阶段 → 模块 → 任务 → 要求 → 产出"的结构后录入路径模板。
- 机器人接口的字段细节，与机器人项目对齐后定稿。

## 附录 A：视觉规范（01 器）

来源：[docs/design/home-01.html](design/home-01.html)。新页面一律沿用，以下是从视觉稿里提取的规则。

### A.1 结构与层次

- 应用外壳：左侧侧栏（252px）直接铺在底色上；主区是一整块浮起的白色面板（圆角 18px，四周留 10px），面板内顶部是 58px 操作栏（面包屑、视角切换、通知、主按钮）。
- 层次三层：**底色 → 主面板 → 卡片**。卡片在面板内用 1px 描边区分，不叠重阴影；"焦点条"用浅灰底卡片，悬停时变白并浮起。
- 内容区用 12 栏网格，间距 14px；常用跨度 4/5/7/8/12。
- 每屏一个强调块：深色卡片只用于"这一步可以用"这类 AI 推荐。

### A.2 色板

| 用途 | 值 |
|---|---|
| 底色 | `#E8EAEE` |
| 面板 / 卡片 | `#FFFFFF` |
| 浅灰填充 | `#F5F6F8` |
| 描边 | `#E7E9ED` |
| 正文 | `#14161A` |
| 次级正文 | `#3B4048` |
| 弱化文字 | `#6B707A` |
| 强调（钴蓝） | `#3446E0`，浅底 `#ECEEFD` |
| 语义：通过 | `#2F7A58` / `#E3F1E9` |
| 语义：进行中、提醒 | `#A8670C` / `#F8ECD8` |
| 语义：截止、逾期 | `#BF3F2C` / `#F9E3DF` |
| 语义：中性 | `#62666D` / `#EEF0F2` |

语义色与强调色分开使用：状态只用语义色，钴蓝只用于当前项、链接和主强调。

### A.3 字体

- 界面：Geist + Noto Sans SC（中文）。
- 数字、日期、代码：Geist Mono，数字列使用等宽数字（`tabular-nums`）。
- 字号：页面标题 30px/600；卡片标题 14px/600；正文 13.5–14px；辅助 12–12.5px；指标数字 30–32px Geist Mono。
- 装饰性大字（如周次"W45"）用 112px、极浅灰 `#F0F1F4`，只做背景，不承载信息。

### A.4 组件

- 圆角：面板 18px，卡片 16px，焦点卡 16px，图标块 9–13px，按钮 9px，状态标签全圆角。
- 按钮：主按钮黑底白字（悬停上浮 1px）；次按钮白底 1px 描边；小按钮 28px 高。
- 状态标签：圆点加文字，底色用语义浅色。
- 表格：表头 11.5px 弱化色；行高约 48px；悬停整行浅灰并带圆角。
- 人员：圆形头像，取名字首字，同一人颜色固定。
- 动效：只用 0.2–0.3s 的颜色、描边、位移过渡；不做入场动画；尊重"减少动态效果"设置。
