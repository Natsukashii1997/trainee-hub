# 营销战役 AI 协同 MVP｜使用手册 V4

适用范围：营销战役 V4 单群试点；“数码宝贝世界”是唯一 UAT 群。该群所有测试都必须真正 `@机械邪龙兽`；未来在正式“月度策略同步”群中，常浩发送月度方案时无需 `@`，机器人会按消息结构自动识别。

> 这份手册写给不懂技术的业务人员。正常使用只需要在群里发消息、核对卡片、点击按钮和在多维表格上传附件，不需要运行程序。

> **现行状态（2026-08-29）：** `07｜月度折扣方案` 已在 Base revision `112` 完成编号结构迁移并通过定向只读验收；本地全量回归 `145` 项通过。当前九表 V4 旧合同全量验收为 `ok=false`、`111` 项通过、`17` 项失败，原因是用户手工重构后的真实 `01／02／03` 表与旧合同发生漂移，并连带影响旧 SKU 跨表校验；不得为了让旧验收变绿而恢复用户已删除或修改的结构。2026-08-27 月度方案真实写入 UAT 属于 revision `112` 之前的历史证据，revision `112` 后尚未重新执行真实月度写入 UAT。企业级通用底座仍需第二个真实业务场景迁移验证。

## 1. 最简单的理解

设计提需遵循以下安全规则：

```text
你在群里发完整请求
→ 系统校验 5 项必填信息
→ 写入营销战役 AI 协同台并回读
→ 按主表自动生成的“提需时间”取 Asia/Shanghai 创建月份，同步外部对应月份设计需求表并回读
→ 两边一致后返回绿色成功卡
```

机器人不会因为“看懂了大概意思”就猜字段。缺少任一必填项时两张 Base 都不写；5 项全部明确合法时，完整消息本身就是执行依据，不再要求二次确认。

**唯一例外是月度策略同步：**常浩发出某一业务线的完整月度方案后，系统先对本条消息整批预校验；全部通过就直接写入并回读，不再出现预览确认卡。任一预校验问题都会让本条消息保持 0 写入。大学辅导和国际课程通常分两条消息发送，彼此独立。

当前支持五类使用方式：

| 你要做什么 | 群消息开头 | 是否写表 |
|---|---|---|
| 向设计提出物料需求 | `@机械邪龙兽 向设计提需` | 信息完整后直接写主表与外部对应月份设计需求表，并分别回读 |
| 新建、补充、改派或维护内部任务 | `@机械邪龙兽 新建任务`等任务请求 | 机器人只返回任务事项表直达链接；你在 Base 手工填写 |
| 登记或更新月度策略 | UAT 群由常浩 `@机械邪龙兽` 后发送；正式月度群由常浩直接发送 | 只处理消息中出现的业务线，预校验通过后直接 upsert 并回读 |
| 即时查询进度或风险 | `@机械邪龙兽 查询……` | 只读，不写表 |
| 自动接收营销战役周度总览 | 无需发送消息或 `@` | 每周一 10:00（Asia/Shanghai）主执行；10:10/10:30 只在失败时静默补偿；收到一条完整 Markdown / 富文本消息；只读四张核心表、非卡片、无按钮、同周最多成功一条 |

其中“向设计提出物料需求”已经完成实现与预放行部署，但在本轮人工 UAT 通过并由常浩确认放行前，只能用于 UAT，不应投入真实业务。任务事项已改为 Base 手填最短路径；旧机器人建任务和任务状态按钮只保留为历史证据，不再是当前用法。

多维表格入口：[营销战役 AI 协同台](https://vm94j8bzy7.feishu.cn/base/LgqpbDFz8a9XmNs3TxccAP0Hn7b)

## 2. 使用前确认六件事

1. UAT 只能在“数码宝贝世界”群操作，所有测试消息（包括月度策略）都要真正 `@机械邪龙兽`，并必须由常浩发送。正式“月度策略同步”群上线后才使用无需 `@` 的自动识别。
2. 营销战役、营销主题和 SKU 应先存在于多维表格，群消息使用表里的准确名称。
3. UAT 阶段的提需人、审核人、任务负责人和验收人统一使用常浩账号；设计负责人由外部设计需求 Base 的实际协作安排维护，不通过群卡片领取。
4. 一条消息一次写完整；不要先发一半，再用下一条消息补一半。
5. 设计提需的日期建议写成`2026-08-30`或`8月30日`；只要月日可结合上下文唯一解析即可。即使消息带几点几分，系统也忽略时间，只保留日期；“下班前”不再映射为 18:30。该日粒度覆盖内容物料后续的设计同步、催办、审核、终稿交付和完成回执；任务事项 DDL 仍按任务表自身规则处理。
6. 不要在群里发送 App Secret、API Key、验证码、密码或客户隐私。

## 3. 向设计提需

### 3.1 可以直接说自然语言

```text
@机械邪龙兽 向设计提需：我要做“2026秋季开学风险提醒长图”，使用场景是朋友圈，物料规格是三宫格，8月30日交付，提需文档是 https://请替换为真实可访问的飞书文档链接。关联灵活学Lite和安心学Max，属于“第1周｜开学风险识别”主题。
```

自然语言里必须明确说清 5 项：

- 物料名称；
- 使用场景，只能精确写为 `朋友圈`、`私信`、`其他` 之一；
- 物料规格，只能精确写为 `海报`、`单图`、`九宫格`、`六宫格`、`三宫格`、`其他` 之一；
- 交付 DDL，只需明确年月日或可唯一解析的月日；
- 提需文档链接，必须是可访问的 `http://` 或 `https://` 链接。

选填：优先级、关联 SKU、所属主题。未填优先级时默认 P1；SKU 和主题不填也可以建单。多个 SKU 用顿号、中文逗号或英文逗号分隔，并使用 SKU 目录中的准确名称。

物料大类由机器人自动确定，不需要在消息里填写：

- `朋友圈 → 营销物料`；
- `私信 → 常规物料`；
- `其他 → 其他`。

设计提需只保存日期。消息写了`18:30`、`晚18点30分`或“下班前”时，系统忽略时间表达，只取明确的日期；只写“下班前”但没有日期时，仍视为 DDL 不完整。主表“交付DDL”和外部表“期望交付时间”统一以`yyyy/MM/dd`显示；成功卡使用业务化日期，例如`8月30日`。

同一规则贯穿整条内容物料跨部门链路：主表中的`交付DDL`、`设计完成时间`、`审核时间`、`完成时间`以及外部表的`期望交付时间`，业务界面均以`yyyy/MM/dd`显示；催办、待审核、终稿交付和完成回执卡只展示`8月31日`这类日期。系统仍可在提需时间、消息/卡片发送时间、同步时间、AI 运行/审计时间和状态更新时间中保留精确时分，用于技术审计，不把这些精确时间当作业务日期展示。

如果更习惯逐行填写，也可以使用下面的同义格式：

```text
@机械邪龙兽 向设计提需
物料名称：2026秋季开学风险提醒长图
使用场景：朋友圈
物料规格：三宫格
交付DDL：8月30日
提需文档链接：https://请替换为真实可访问的飞书文档链接
优先级：P1
关联SKU：灵活学Lite、安心学Max
所属主题：第1周｜开学风险识别
```

不要再填写旧字段“物料形式”“使用场景/规格”“需求说明”。这些字段不属于设计提需 V2，也不能代替任何必填项。

### 3.2 看到卡片后怎么做

1. 如果收到黄色“信息不完整”卡：核对卡片是否一次列全所有缺失、歧义或非法项。此时 Base 必须零写入；补齐后重新发送一条完整消息。
2. 如果收到绿色成功卡：核对物料名称、类型需求、交付 DDL 和“查看设计提需文档”。该卡只会在主表和外部月份表都写入并回读一致后出现。
3. 如果收到红色或橙色同步失败卡：不要重发同一需求。主表记录会保留，系统或维护人员只重试外部同步。
4. 设计提需没有确认按钮，也不会再出现额外领取按钮。设计人员直接在外部对应月份设计需求表中处理。

### 3.3 三类提需结果卡

| 卡片 | 什么时候出现 | 你怎么处理 |
|---|---|---|
| 信息不足卡 | 任一必填项缺失、含糊、枚举非法、链接非法或 DDL 不明确 | 按卡片一次补齐全部问题；本轮不写表 |
| 需求提报完成卡 | 主表和外部月份表均写入并逐字段回读一致 | 核对三个摘要块和提需文档链接；无需再点击 |
| 同步失败卡 | 主表可能已经写入，但外部月份表写入或回读未完成 | 不要重发；等待系统安全重试或交给维护人员 |

### 3.4 从提需走到完成

```text
需求已同步至外部月份设计需求表
→ 设计人员在外部表处理
→ 制作中
→ 待审核
→ 已完成
```

退回规则：审核人点击“退回修改”后，状态回到“制作中”；设计人员上传新终稿后，系统再次进入审核流程。系统不记录复杂审核轮次；具体怎么改，在群话题或线下沟通即可。

角色动作：

| 当前状态 | 谁操作 | 做什么 | 下一状态 |
|---|---|---|---|
| 需求已同步 | 设计 | 在外部设计需求 Base 中按团队规则处理 | 制作中 |
| 制作中 | 设计负责人 | 打开记录，把最终文件放入“终稿附件” | 系统送审 |
| 待审核 | 审核人 | 查看终稿，点击“审核通过”或“退回修改” | 已完成 / 制作中 |
| 已完成 | 业务人员 | 如值得反复复用，在 Base 勾选“需入中台” | 流程结束 |

重要边界：

- 参考资料放在“参考附件”；最终设计稿放在“终稿附件”。
- 机器人每 60 秒检查一次终稿附件是否存在，只看“有没有”，不读取或分析图片内容。
- 上传终稿后，系统会发新的“待审核”卡并 @审核人；旧制作卡不再作为最新操作入口。
- 审核通过后原审核卡收口为不可操作的绿色完成态，不再发送提需人二次确认卡。
- 制作催办、待审核、终稿交付和完成回执中出现的业务日期都只显示年月日；主表`设计完成时间`、`审核时间`、`完成时间`也统一按`yyyy/MM/dd`显示。底层系统事件时间可另外保留时分用于审计。
- 如需换设计负责人，直接在实际承载该角色的多维表格修改对应人员，不新建第二条物料。
- “需入中台”只是候选标记；本期不建设独立营销资产库工作流。

## 5. 月度策略同步

### 5.1 先记住两个群的边界

- **数码宝贝世界：**唯一 UAT 群。施工、格式调试、卡片验证和模拟数据全部留在这里。
- **月度策略同步群：**未来的正式输入群。现在绝不向该群发测试消息、测试回执或模拟数据。未来放行后，它也只用于常浩发布正式方案；机器人通过 `reply-in-thread` 进入该条原促销方案消息的“1 条回复”话题，只返回一条成功或失败文字，不主动推送其他内容。

### 5.2 实际发送方式

大学辅导和国际课程固定为两条消息分别发送。常浩锁定的是**视觉结构和字段命名**，不是截图里的具体业务内容：`📅月份`、`【业务线】`、编号 SKU、`试听价格 / 正价价格 / 新签活动 / 续费活动`这些层级与标题保持不变；每个月实际出现哪些 SKU、出现几个 SKU、价格是多少、方案写几行、方案内容是什么，都按当月真实情况变化。在 UAT 群先真正 `@机械邪龙兽`；在未来正式“月度策略同步”群由常浩直接发送，不必 `@`。

大学辅导可以单独发送：

```text
📅月份：2026-09

🟥【大学辅导】
1. 灵活学Lite
  a. 试听价格：¥199
  b. 正价价格：¥4300
  c. 新签活动：无
  d. 续费活动：
     1 购买课时≥20课时，立减¥200
     2 购买课时≥30课时，立减¥500

2. 论文稳Pass
  a. 新签活动：全款立减¥1000
```

国际课程稍后作为另一条独立消息发送：

```text
📅月份：2026-09
🟦【国际课程】
1. 请使用 SKU 目录中的准确名称
  a. 试听价格：按该 SKU 当月真实值填写
  b. 正价价格：仅适用的 SKU 填写
  c. 新签活动：按当月真实方案填写
  d. 续费活动：按当月真实方案填写
```

识别与写入规则：

1. 只允许常浩发送。UAT 群必须真正 `@机械邪龙兽`；正式月度策略群无需 `@`。
2. 正式发送沿用上述固定视觉层级与固定标题。机器人会识别富文本加粗、下划线、红蓝方块、项目符号、灰底代码块以及中英文冒号；颜色只负责视觉，真正的业务线锚点是 `【大学辅导】` 与 `【国际课程】`。
3. 一条消息只能有一个明确月份，建议写为 `YYYY-MM`。
4. 一条消息至少包含一个业务线。大学辅导、国际课程可以分别发送，也兼容同条发送。缺席的业务线代表本轮不处理，不报错、不清空、不改历史记录。
5. 每个 SKU 单独一个方案块，最终对应 Base 中的独立一行；相同方案也不能合并 SKU。系统只处理消息中实际出现的 SKU，不要求每月提供截图中的固定 SKU 数量或完整清单，也不会因为本月少了某个 SKU 而清空其历史记录。
6. 每个 SKU 都使用 `试听价格`、`正价价格`、`新签活动`、`续费活动` 四个目标字段。价格不适用时留空；新签活动或续费活动未提供时，系统统一写入 `无`。`论文稳Pass` 没有试听价格，该字段必须留空。
7. SKU 必须使用 SKU 目录中的准确名称，且必须放在它真实所属的业务线段落下。
8. 方案内容完全按当月实际内容填写，可长可短、可换行续写、可带项目符号或灰底编号块，不要求复刻截图示例。一个字段标题之后的所有正文，在遇到下一个 `a./b./c./d.` 字段标题、下一个编号 SKU 或下一条业务线前，都归属于该字段。例如大学辅导截图中灰底块归入`续费活动`；国际课程截图中灰底块归入`新签活动`。机器人不会根据方案语义自行改换字段；灰底块内部即使出现 `1.`、`2.` 也只视为方案正文，不会误建 SKU。

### 5.3 系统怎么写表

```text
收到一条业务线方案消息
→ 只校验这条消息实际出现的业务线
→ 任一问题：判定同步失败，本条消息整批 0 写入
→ 全部通过：按“月份 × 业务线 × SKU”直接 upsert
→ 每条写入后逐字段回读
→ 全部一致：只回复“月度促销方案同步成功 | 营销战役表”
→ 任一失败：只回复“月度促销方案同步失败 | 营销战役表”
```

- 同月同业务线同 SKU 已存在：更新原记录。
- 同月同业务线同 SKU 不存在：新建一行。
- 同月同业务线同 SKU 已有多条：本条消息校验失败，0 写入，先人工合并重复记录。
- 先发大学辅导、后发国际课程时，第二条只新增或更新国际课程，不会覆盖第一条大学辅导记录。
- 这不是“只更新本轮提到的字段”协议；每次都以归一化后的四类事实覆盖该月份、该 SKU 的当前行。
- 不提供写入前确认按钮。发出模板就代表常浩确认按该内容执行。
- 回读会核对月份、业务线、SKU、试听价格、正价价格、新签活动、续费活动、同步人、来源消息、同步时间和数据环境等事实。
- 飞书对同一消息 ID 重投时，系统不做第二次 upsert，也不再回复第二条文字。**手工重发相同文本是一条新消息，不是幂等重投**。
- `方案编号`是 Base 公式生成的稳定业务身份，隐藏的`技术字段｜方案序号源（勿改）`只为公式提供自增源；Agent、机器人、Workflow 和人工业务操作均不得写入、覆盖或纠正这两个字段，也不得自行计算“最大编号 + 1”。新建方案只写`方案名称`和获准的业务字段，由 Base 自动生成编号；`record_id`只用于技术定位，不是业务编号。

### 5.4 两种文字回执

月度策略同步不发送任何卡片。机器人通过 `reply-in-thread` 进入常浩原促销方案消息的“1 条回复”话题，并只回复一条 Markdown 文字：

| `月度促销方案同步失败 | [营销战役表](https://vm94j8bzy7.feishu.cn/base/LgqpbDFz8a9XmNs3TxccAP0Hn7b?table=tblaUHNEhPhYjfJw)` | 预校验失败、字段缺失、部分执行失败或回读失败中的任一种 | 点击蓝色“营销战役表”链接核对；不要把本轮当作整批成功，也不要盲目重复发送，由维护人员结合 Base 与运行记录判断处理方式 |

1. **锁定环境：**只打开“数码宝贝世界”；不打开、不发送、不测试“月度策略同步”群；每条测试都真正 `@机械邪龙兽`。

9. **完成证据收口：**保留成功与失败文字回执截图、原消息链接、Base 记录链接和测试前后记录数。确认全部证据都来自“数码宝贝世界”，未在正式输入群留下任何 UAT 痕迹。

## 6. 查询进度与风险

可以直接问：

```text
@机械邪龙兽 查询当前营销战役进度和风险
```

也可以使用“巡检、检查、进度、风险”等表达。机器人会即时返回本次问题所需的只读事实与分析，通常包含：

- 进行中战役；
- 周度主题；
- 未完成任务；
- 未完成物料；
- 待审核；
- 已登记的风险或重点对象。

即时查询与定时周度总览是两个入口：即时查询由群成员 `@机械邪龙兽` 发起；群内“发周报/周度总览”不会触发正式周度推送。正式周度总览无需 `@`，由系统在每周一 10:00（Asia/Shanghai）主执行，10:10、10:30 仅在前序未成功时静默补偿，并向测试群最多推送一条成功的完整 Markdown / 富文本消息。周度总览不是卡片，没有按钮，也不会修改业务记录。

周度总览固定读取`02｜营销战役`、`04｜任务事项`、`05｜营销主题与节奏`、`06｜内容物料`四张核心表，并依次展示：统计周期与数据截止时间、核心数据、战役情况、风险与阻塞、待决策事项、Todo、AI 建议、数据缺口和多维表格/看板链接。总览只把 Base 已登记内容当作事实；群里说过但没有上表的事项必须列为“未登记/无法确认”，不能补写成事实。关键来源读取失败时，消息必须说明缺口与受影响结论，不能输出虚假的“整体正常”。

任务指标固定按以下口径展示：

- 有效任务总数：全部任务中排除`已取消`；
- 已完成：有效任务中状态为`已完成`；
- 未完成：有效任务总数减去已完成；
- 完成率：已完成 ÷ 有效任务总数；
- 有效任务为 0：显示`0/0（—）`，不显示误导性的 0%；
- 风险任务：仍单独展示，不被完成率指标隐藏。

同一自然周只允许一条成功总览。维护人员的受控补发仍命中同周幂等，不得生成第二条重复消息。

“每日综合 DDL 汇总”（任务、物料、逾期、战役关键节点 T-3）当前没有启用。不要等待每日推送；关键节点事实源和发送时间将在最终结构冻结后再确认，详见[待最终配置能力清单](./待最终配置能力清单.md)。

## 7. 不同颜色代表什么

| 颜色 | 含义 | 你该做什么 |
|---|---|---|
| 黄色 | 待补信息或其他待确认事项 | 核对信息，补齐或点击当前动作 |
| 蓝色 | 正在执行 | 查看进度；按卡片提示继续 |
| 橙色 | 待审核 | 审核人做专业判断 |
| 绿色 | 写入回读一致或流程已完成 | 无需重复操作 |
| 红色 | 已安全停止，需要人工处理 | 停止点击，先核对 Base |

同一类卡片可以搭配多个浅色块；颜色帮助扫读，但最终状态一定同时用文字写清楚。

周度总览不属于卡片，因此不使用本表的卡片颜色语义。

## 8. 看到异常时怎么处理

### 8.1 @机器人后没有回复

1. 确认是在“数码宝贝世界”群。
2. 确认真的 @ 到机械邪龙兽，不是只输入名字。
3. 确认消息使用了本手册的标准开头。
4. 确认所有字段在同一条消息中。
5. 等待一分钟；仍无回复时交给维护人员检查。

不要连续发送多条相同请求。

如果发的是月度策略同步，请改按以下顺序检查：确认发送人是常浩；若在“数码宝贝世界”做 UAT，确认真正 `@机械邪龙兽`；确认消息含一个明确月份、一个明确业务线、至少一个 SKU 及其方案字段；确认消息类型是文本或富文本。施工和 UAT 期间不得转去正式“月度策略同步”群尝试。

### 8.2 卡片说“信息不足”

本轮没有写表。按卡片一次补齐全部缺失字段，再重新发送完整消息。不要只在话题里补一句。

### 8.3 找不到战役、主题或 SKU

打开多维表格，从对应表中复制准确名称后重发。名称不唯一时系统也会停止，避免写错对象。

### 8.4 设计提需提示“外部同步失败”

这代表营销战役 AI 协同台主表可能已经写入，但外部月份设计需求表尚未写入或回读成功。不要重发同一需求，也不要手工再建一条主表记录。系统或维护人员应读取主表自动生成的“提需时间”，按 Asia/Shanghai 取创建月份并定位`{M}月营销组需求表`，只重试外部五个字段；两边回读一致前不能补发绿色成功卡。

### 8.5 卡片过期或提示状态已变化

打开卡片中的记录链接，确认当前状态，只操作最新卡。不要继续点击旧卡。

### 8.6 提示“只有某角色可以操作”

检查记录里的提需人、设计负责人、审核人、任务负责人或验收人。如需改派，直接修改对应人员字段，然后从当前状态继续。

### 8.7 上传终稿后没有送审

确认文件放在“终稿附件”而不是“参考附件”，等待一个巡检周期。仍未推进时，确认附件存在后点击“备用：已上传，提交审核”；不要反复点击。

### 8.8 Base 已变化但卡片没更新

立即停止操作。以 Base 为准，并把以下五项交给维护人员：

1. 群消息或卡片截图；
2. 发生时间；
3. 业务对象名称；
4. 多维表格记录链接；
5. 点击的按钮和看到的提示。

不要手工修改状态版本、卡片消息 ID、附件指纹或幂等信息。

## 9. 九张表各自负责什么

| 表 | 唯一职责 | 谁主要使用 |
|---|---|---|

角色通过不同视图只看自己关心的字段和记录，但各业务事实只保留一份，不为每个角色复制一张表。

## 10. 什么可以手工维护

可以按业务需要修改：

- 战役、用户策略和周度主题内容；
- 任务完成说明、附件和交付链接；
- 物料参考附件、终稿附件和人员改派；
- 物料完成后的“需入中台”；
- 结果、反馈和经验学习。

不要自行修改：

- 状态版本；
- 卡片消息 ID；
- 附件指纹；
- 幂等信息；
- 月度折扣方案的`方案编号`和隐藏的`技术字段｜方案序号源（勿改）`；
- 已由卡片状态机控制的状态，除非维护人员正在执行明确的故障恢复。

## 11. 怎样判断真的完成

不要只看机器人说了“已处理”。完成必须同时满足：

1. 对设计提需而言，营销战役 AI 协同台主表记录存在且回读正确；
2. 系统使用主表自动生成的“提需时间”，按 Asia/Shanghai 取创建月份定位外部`{M}月营销组需求表`，且外部记录的`需求内容 / 需求人 / 期望交付时间 / 相关需求物料 / 项目场景`逐字段回读正确；“上表月份”只是该创建月份的业务简称，不是独立可写字段；
3. 外部`项目场景`映射必须是`朋友圈 → 朋友圈`、`私信 → 私信海报`、`其他 → 其他`，不得凭 DDL 月份或其他字段猜月份或场景；
4. 只有两边都写入并回读成功时，群内才出现绿色卡片`已确认 | 完成提需并同步多维表格`，并展示三个等宽块：物料名称、类型需求、交付 DDL；DDL 只显示日期，例如`8月31日`；
5. 绿色卡片底部必须是`写入状态：已写入 | 查看设计提需文档`，后半段链接到本次提需文档；
6. 外部同步失败时保留主表、只重试外部同步，不重复创建主表，不发绿色成功卡；
7. 状态已经进入预期的下一步或终态，后续卡片与 Base 状态一致；
8. 重复消息或重复点击不会再创建或推进一遍；
9. 双表成功后，系统尽力补充最小 AI 执行记录，便于找到外部写入结果或异常；日志失败只进入维护回查，不阻塞或撤销已确认的双表成功。任务事项手工维护不生成 AI 执行记录。
10. 内容物料从提需、设计同步到催办、审核、终稿交付、完成回执的业务日期均只到年月日；系统审计时间可保留时分，任务事项 DDL 不受影响。
