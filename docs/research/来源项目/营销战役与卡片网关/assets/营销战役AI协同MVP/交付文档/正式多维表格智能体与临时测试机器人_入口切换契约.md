# 营销战役 AI 协同：入口切换契约

> [!IMPORTANT]
> 当前实时状态由项目 [README](../README.md)统一维护。本文定义三阶段入口关系：**当前 UAT 用机械邪龙兽的营销战役第二身份；企业自建机器人/DeepSeek 路线暂停；长期正式入口仍是专属多维表格智能体。**

## 1. 当前唯一有效结论

| 阶段 | 入口 | 状态 | 允许做什么 |
|---|---|---|---|
| 当前封闭 UAT | 机械邪龙兽的“营销战役第二身份” | 待按新手册完成真实 UAT | 仅在「数码宝贝世界」群、仅常浩；固定动作走确定性预览确认；普通营销问答走独立营销会话 |
| 暂停备用 | 企业自建应用「营销战役测试AGENT」+ DeepSeek | **已暂停、未配置、未运行** | 不启动 listener，不配置 Secret/Key，不入群，不消费事件，不做 UAT |
| 长期正式 | 专属多维表格智能体「营销战役 AI 协同台」 | 待额度恢复后迁回验收 | 复用同一 Base、动作、卡片、审计和 UAT 契约，不重建业务底座 |

当前 UAT 的身份隔离不是“换一个机器人名称”，而是在同一个机械邪龙兽运行壳内建立明确的营销业务边界：

```text
常浩在「数码宝贝世界」明确 @机械邪龙兽
  ├─ 命中已登记固定动作
  │   → 只读预检 → 一张预览卡 → 原发起人确认
  │   → 确定性执行 → Base 回读 → 原卡更新 → AI 执行记录
  ├─ 普通营销问答
  │   → 独立营销会话 → 只读事实检索 → 事实/推断/建议分层回答
  └─ 带教、其他业务、越权或无法确认的请求
      → 不继承、不拼接、不回落；明确拒绝或要求重新进入正确场景
```

机械邪龙兽以往的管培生带教对话、记忆、Prompt、工具结果和结论，不得作为营销战役第二身份的上下文。营销会话也不得把营销事实反向写入带教会话。

## 2. 始终不变的协同底座

以下内容不绑定某个机器人或模型：

1. 业务对象与关系：营销战役、任务事项、周度主题与节奏、内容物料、审核与版本、结果复盘、营销资产、口径事实和 AI 执行记录。
2. 唯一 ID 与关联规则：战役、主题、物料、版本、资产和运行分别有稳定身份，不依赖聊天标题或模型记忆识别。
3. 字段、状态机与门禁：什么条件允许进入下一状态，什么情况受阻，什么必须人工确认。
4. 事实来源与版本：价格、促销折扣、正式口径、审核版本和终稿证据可追溯、可失效，不被模型推测覆盖。
5. 动作协议：识别对象 → 查重 → 校验 → 预览 → 人工确认 → 执行 → 回读 → 回执 → 审计。
6. 卡片协议：黄色待确认、蓝色执行中、绿色已完成、红色受阻或失败、灰色已取消；同一轮只保留一条有效结果。
7. 幂等、恢复与审计：重复消息或重复点击不重复创建；事实不明时转人工复核；每次运行留下运行 ID、来源、确认人、动作和回读结果。

## 3. 当前机械邪龙兽第二身份的强制边界

### 3.1 身份与范围

- 只接收「数码宝贝世界」群内、常浩账号明确 @机械邪龙兽的营销请求。
- 固定业务动作必须命中登记的动作名、字段规则、状态门禁和权限校验。
- 普通营销问答只读，不因用户使用“帮我改”“顺便更新”等表达自动转为写操作。
- 不能读取、引用或延续管培生带教会话；用户主动要求“接着刚才带教内容”也必须拒绝，并提示这是营销战役隔离会话。
- 非目标群、非授权人、旧卡、相反按钮、重复点击和不确定来源一律不能改变业务数据。

### 3.2 固定动作的唯一完成定义

只有以下证据同时成立，才可回复“已完成”：

1. 只读预检通过，并明确展示将写入的对象、字段、版本和风险；
2. 原消息发起人点击当前有效预览卡确认；
3. 确定性工作流执行成功；
4. Base 写后回读与预期一致；
5. 原卡片就地更新为终态，没有重复结果卡；
6. AI 执行记录可用运行 ID 回查请求、确认人、动作、写入对象和回读结果。

任何一步缺失、超时或结果不确定，只能报告“受阻 / 待人工复核 / 部分完成”，不得把计划、卡片已发送或模型判断说成业务完成。

### 3.3 普通营销问答的唯一完成定义

- 明确回答的是营销战役范围问题；
- 每条业务事实能指向当前可访问的 Base 记录或正式来源；
- 推断与建议单独标记，不伪装成事实；
- 不写 Base、不发流程卡、不改变状态；
- 不出现管培生带教语气、任务、结论或旧会话片段。

## 4. 已暂停的企业机器人 / DeepSeek 路线

企业自建应用「营销战役测试AGENT」及 DeepSeek 适配层目前只保留为技术备用材料，**不是当前入口**：

- 未配置真实 App Secret；
- 未配置真实 DeepSeek API Key；
- 独立 listener 未启动；
- 未核验入群、Base 授权或真实端到端闭环；
- 不得与机械邪龙兽同时消费「数码宝贝世界」事件；
- 不得把离线测试通过描述成该机器人已在线。

如未来重新启用，必须形成新的明确决策并重新做权限、身份、事件、幂等和真实 UAT；不能直接照旧文档启动。

## 5. 迁回专属多维表格智能体时的处理

| 组件 | 迁回时如何处理 |
|---|---|
| 营销战役 Base 及九张表 | 原地保留，不迁移、不复制 |
| 历史业务记录 | 原地保留 |
| AI 执行记录 | 原地保留，用「执行智能体 / 入口阶段」区分机械邪龙兽第二身份和正式智能体 |
| 动作名称、必填字段、状态门禁 | 原样保留 |
| 卡片信息层级、颜色语义和确认规则 | 原样保留 |
| 飞书入口身份 | 从机械邪龙兽第二身份切换为专属多维表格智能体 |
| 普通问答会话 | 切换到专属营销智能体会话，仍禁止拼接带教上下文 |
| 企业机器人/DeepSeek 备用代码 | 保持停用；确认无在途事件后可卸载，不影响 Base |

## 6. 迁回正式入口的七步验收

1. 冻结机械邪龙兽营销第二身份的新请求，确认没有“执行中”事件。
2. 在多维表格智能体中配置最终 Soul、动作白名单、字段映射、消息去重和问答隔离规则。
3. 将群入口、角色群推送、卡片回调和 Base 权限绑定到正式智能体。
4. 使用同一组 UAT 记录走通：问答隔离、提需、预览确认、建档、设计接单、版本审核、终稿确认、复盘、资产候选和审计回查。
5. 对每个动作做重复消息、重复点击、越权人员、旧卡、过期口径和超时恢复测试。
6. 确认 Base 原记录 ID、关联字段和历史 AI 执行记录未变，新记录能标识正式入口。
7. 全部通过后，才停止机械邪龙兽的营销第二身份路由；不删除 Base，不删除历史审计。

## 7. 验收红线

出现以下任一情况，均不能宣布当前 UAT 或未来迁回完成：

- 机械邪龙兽营销问答出现、引用或延续管培生带教上下文。
- 需要复制 Base 数据到另一套表才能运行。
- 两个机器人或两个 listener 同时消费同一群事件，造成双写或重复卡片。
- 未经有效预览确认就写 Base。
- 确认卡点击后不能回读 Base 并证明状态已变更。
- 模型输出可以绕过动作白名单、人工确认或权限门禁。
- 已完成、已取消或已失效的卡片仍能重复改变业务结果。
- AI 执行记录无法区分请求来源、执行入口、运行 ID、确认人和最终回读结果。

## 8. 一句话定义

**当前用机械邪龙兽的隔离营销第二身份完成真实 UAT，长期迁回专属多维表格智能体；企业机器人/DeepSeek 路线暂停，而 Base、确定性动作协议和可审计闭环始终是底座。**
