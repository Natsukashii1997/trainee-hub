## 1. 建设边界

- 飞书原生：多维表格承载业务事实与状态，群机器人作为交互入口，自动化处理确定性动作，卡片承载确认与回执。
- 本期只建设营销战役 MVP，不建设机械邪龙兽总控，不生成元 Skill。
- 正式环境与 UAT 物理隔离；表内继续保留「数据环境」字段作为二次门禁。
- 业务表严格为 9 张：SKU目录、营销战役、战役—用户策略、任务事项、营销主题与节奏、内容物料、月度折扣方案、结果与复盘、AI执行记录。
- 不设置独立 Brief 表、审核历史表、发布任务表、资产库表；角色工作面通过视图与卡片实现。

## 2. 核心对象关系

```text
SKU目录 ───────────────┐
                      ├─ 战役—用户策略（战役 × 用户 × 待办事项 × SKU）
营销战役 ──────────────┤
  ├─ 任务事项（内部推进线）
  ├─ 营销主题与节奏（周度传播线）
  │    └─ 内容物料（跨部门生产与确认线）
  └─ 结果与复盘（学习线）

SKU目录 ─ 月度折扣方案（月份 × 业务线 × SKU）
AI执行记录 ─ 以对象类型、对象 ID、记录链接关联全部对象
```

## 3. 关键业务口径

- 战役目标单独保留。
- 用户策略采用：`WHO｜目标用户`、`WHY｜待办事项`、`WHAT｜主推SKU`、`WHEN｜战役起止日期`；不设置牵强的 WHERE。
- 同一战役允许多个目标用户；同一目标用户允许多个待办事项；不同待办事项可关联不同 SKU。
- 任务事项仅管理内部推进，不承载物料生产。
- 任务事项采用最短路径：使用者直接在 Base 手工填写、补充、改派和维护状态。机器人识别到任何任务维护请求时，只返回任务事项表直达链接；不生成草稿、不创建或修改任务、不写 AI 执行记录、不提供任务状态按钮。
- 内容物料提需只要求真实协作所需的最少字段；用户不再填写“物料形式”“使用场景/规格”“需求说明”三个旧字段。
- 设计上传终稿附件后触发审核；机器人不读取图片内容。
- 审核只记录当前结果，不记录轮次与逐版修改历史；退回后回到制作中。
- 审核通过即完成物料流程，不再设置提需人二次确认阶段或卡片；审核退回后回到制作中，上传新终稿后重新送审。
- 内容物料跨部门对接链路中的所有业务日期统一为日粒度：交付 DDL、外部设计需求的期望交付日期、催办卡中的物料到期日、审核业务日期、终稿交付日期和完成回执日期，只保存或展示年月日。Base 日期字段统一显示为`yyyy/MM/dd`，卡片显示为`8月31日`这类业务化日期；输入含时分时忽略时分。系统自动生成的提需时间、消息/卡片发送时间、同步时间、AI 运行/审计时间和状态更新时间属于技术时间，可以保留时分。任务事项 DDL 仍按任务表自身规则处理。
- 不发送设计接单卡或“我来接单”按钮。设计团队在外部设计需求表承接需求，设计负责人直接在 Base 人员字段中确定；改派也直接修改人员字段，状态不变。
- 物料分为营销物料与常规物料；价格折扣版本只在「月度折扣方案」按月份、业务线、SKU 记录。
- 资产沉淀只在内容物料中设置「需入中台」勾选，不建设独立资产库。

### 3.1 设计提需协议 V2

设计提需支持带明确语义的自然语言，也支持逐行键值输入。无论输入形式如何，写入前都必须得到同一组确定事实。

**5 项必填：**

1. `物料名称`：非空、指向一项具体交付物；
2. `使用场景`：精确三选一，只能是 `朋友圈`、`私信`、`其他`；
3. `物料规格`：精确六选一，只能是 `海报`、`单图`、`九宫格`、`六宫格`、`三宫格`、`其他`；
4. `交付 DDL`：只要求一个明确、唯一的交付日期。消息中即使包含几点几分或“下班前”，也只提取并保留日期；没有明确日期，或日期存在多个候选、无法唯一解析时，视为必填信息缺失；
5. `提需文档链接`：必须是可访问的 `http://` 或 `https://` 链接。

**3 项选填：**

- `优先级`：不填时默认 `P1`；
- `关联 SKU`：使用 SKU 目录中的准确名称，可多选；
- `所属主题`：使用现有营销主题的准确名称。

**系统派生：**

- `朋友圈 → 营销物料`；
- `私信 → 常规物料`；
- `其他 → 其他`。

物料大类由系统根据使用场景派生，提需人不填写、不覆盖。SKU 和主题为空时不阻断建单。

**失败与成功边界：**

- 任一必填项缺失、语义歧义、枚举非法、链接非法或 DDL 无法确定，本轮均不创建、不更新业务记录；机器人必须在一张黄色信息不足卡中一次列全所有问题。
- 五项必填全部合法时，完整原始消息就是执行依据；不发送写入前预览卡，也不要求二次确认。
- 成功必须同时满足：内容物料写入并逐字段回读一致；按主表提需时间的 Asia/Shanghai 创建月份定位外部月份设计需求表；外部五字段同步并回读一致。
- 任一必填项有问题时，两张表均零写入；主表已成功但外部同步失败时保留主表检查点，重试只补外部同步，不重复创建主表。
- 内容物料表的`交付 DDL`与设计需求表的`期望交付时间`必须写入、回读为同一日期；两处均不承载时分。成功卡中的`交付 DDL`只显示日期，例如`8月31日`。
- 后续物料催办、审核、终稿交付和完成回执如写入或展示业务日期，也必须沿用同一日粒度；不得在这些业务日期中重新带回小时或分钟。
- 任一回读字段缺失或不一致，结果为失败或待人工核对，不发送成功卡。

### 3.2 月度策略同步协议

**revision 112 编号与写入边界：** `方案编号`为第一列只读公式字段，是稳定业务身份；`方案名称`为可编辑标题；`record_id`为稳定技术主键；隐藏自动序号源只供编号公式使用。Agent、机器人、Workflow 和人工业务操作均不得写公式编号或隐藏序号源，不得自行执行“最大编号 + 1”；创建或更新只写`方案名称`及获准业务字段。

**入口与环境边界：**

- 唯一 UAT 群是「数码宝贝世界」；施工、测试、UAT 与模拟数据验证全部只能在该群进行。
- 施工与 UAT 期间，绝不向「月度策略同步」群发送测试消息、测试回执或模拟数据。
- 「月度策略同步」群只是未来的正式输入群：只接受常浩发布的正式月度方案；机器人必须通过 `reply-in-thread` 进入该条原促销方案消息的“1 条回复”话题，并只返回一条成功或失败文字。不在该群主动推送、定时广播或发送其他业务卡片。
- UAT 和未来正式输入均只允许常浩触发。UAT 在「数码宝贝世界」必须真正 `@机械邪龙兽`；正式「月度策略同步」群不要求 `@`。系统按明确月份、至少一个业务线段落、SKU 块和方案字段识别，不要求固定首行或固定模板；不满足结构特征的普通聊天静默忽略。

**消息结构：**

1. 必须且只能包含一个明确月份，标准格式为 `YYYY-MM`。
2. 一条消息至少包含 `【大学辅导】` 或 `【国际课程（国课）】` 中的一个业务线段落；实际业务默认两条消息分别发送，也兼容同条包含两条。只处理本条消息出现的业务线，另一业务线缺席不报错、不清空、不修改已有记录。
3. 每个 SKU 必须是独立方案块，写入 Base 后是独立一行；即使多个 SKU 方案完全相同，也不得合并。
4. 每个 SKU 的事实统一写入 `试听价格`、`正价价格`、`新签活动`、`续费活动` 四个字段。价格是否必填按 SKU 规则判断，不适用则留空；未提供的新签活动或续费活动自动写入字面值 `无`。例如「论文稳Pass」没有试听价格，其 `试听价格` 留空。
5. SKU 名称与业务线必须与 SKU 目录完全一致；同一条消息内不得重复出现同一 SKU。

**执行与回执不变量：**

- 系统先对本条消息进行格式、月份、已提交业务线、SKU 目录、业务线归属、SKU 价格规则以及“月份 × 业务线 × SKU”唯一性预校验。
- 任一预校验问题都会判定本次同步失败；整批不创建、不更新任何月度方案，也不写 AI 执行记录。对外只回复固定失败文字，不发送信息不完整卡，也不追加问题明细。
- 预校验全部通过后直接按 `月份 × 业务线 × SKU` upsert：已存在则更新原记录，不存在则新建一行，不另做写入前确认。
- 每行写入后必须回读并核对记录名称、月份、业务线、SKU 关联、四类事实字段、同步人、来源消息 ID、同步时间与数据环境；只有整批全部一致才能返回成功文字。
- 同一来源消息 ID 重投时，不做第二次 upsert，也不再回复第二条文字。重新发送相同文本是新消息，不等于幂等重投。
- 预校验通过后，若执行或回读中仅部分 SKU 成功，成功项保留，不伪装成整批成功，也不盲目自动回滚或重放；对外仍只回复固定失败文字，不发送部分失败卡、不追加成功或失败 SKU 明细。

月度策略对外回执严格只有两种，且只能通过 `reply-in-thread` 进入原促销方案消息的“1 条回复”话题，在话题中发送一条 Markdown 文字：

- 全部写入并回读一致：`月度促销方案同步成功 | [营销战役表](https://vm94j8bzy7.feishu.cn/base/LgqpbDFz8a9XmNs3TxccAP0Hn7b?table=tblaUHNEhPhYjfJw)`；
- 任何失败，包括预校验失败、字段缺失、部分执行失败或回读失败：`月度促销方案同步失败 | [营销战役表](https://vm94j8bzy7.feishu.cn/base/LgqpbDFz8a9XmNs3TxccAP0Hn7b?table=tblaUHNEhPhYjfJw)`。

“营销战役表”必须为蓝色可点击链接。两种结果的话题中均只保留这一条固定 Markdown，不发送卡片、不追加明细、不发送额外总结；同一来源消息只回复一次。

## 4. 状态机

- 营销战役：战役准备 → 执行中 → 待复盘 → 已完成；异常终态：已取消。
- 任务事项：待开始 → 进行中 → 待验收 → 已完成；验收退回回到进行中；异常终态：已取消。该状态由使用者在 Base 手工维护，不由机器人按钮推进。
- 营销主题：待开始 / 进行中 / 已结束，由日期与自动化维护；异常终态：已取消。
- 内容物料：待设计接单 → 制作中 → 待审核 → 已完成；审核退回回到制作中，上传新终稿后重新进入待审核；异常终态：已取消。

## 5. 健康规则

1. 任一未结束对象的「阻塞原因」非空：阻塞。
2. 否则任一未完成任务/物料已逾期或 48 小时内到期，或战役「待决策事项」非空：需关注。
3. 其余：正常。

## 6. 自动化闭环

> 以下为冻结的自动化规则。当前 `status` 已确认终稿附件巡检与周度任务调度健康且运行包为当前版本；非卡片周度消息协议已经完成真实群 UAT。技术运行健康与周度消息协议通过均不替代其他业务路径所要求的真实触发 UAT。

1. 群消息自然语言提需 → 解析并校验 5 项必填 → 信息不足时一次列全，且主表与外部设计需求表均零写入 → 信息完整时直接写入内容物料并回读 → 按主表提需时间路由外部月份表并同步 5 字段 → 外部回读 → 双表一致后只发送一张绿色成功卡。
2. 新物料初始状态暂沿用 Base 枚举“待设计接单”，但不发送接单卡；设计团队在外部设计需求表处理，设计负责人直接在 Base 人员字段中确定。
3. 设计人员手动上传终稿附件 → 自动进入待审核 → 群卡片 @审核人；终稿交付业务日期与卡片中的截止日期均只到年月日。
4. 审核通过 → 已完成，并将原审核卡收口为不可操作的绿色完成态，不再生成提需人确认卡；审核退回 → 制作中，上传新终稿后重新送审。如记录或卡片展示审核或完成业务日期，只到年月日。
5. 已完成物料可按需勾选需入中台；完成回执中的业务日期只到年月日。
6. 任务事项由使用者直接在 Base 维护；机器人收到新建、补充、改派或状态维护请求时，只返回[任务事项表直达链接](https://vm94j8bzy7.feishu.cn/base/LgqpbDFz8a9XmNs3TxccAP0Hn7b?table=tblMK7GxGkyQUviP)，不产生任何任务写入或 AI 执行记录。
7. 到期前 48 小时与逾期检查；自动维护健康状态。触发器可以按系统时间运行，但物料催办中展示的到期日只到年月日。
8. 营销战役周度总览固定为独立只读定时任务：每周一 10:00（Asia/Shanghai）主执行，10:10、10:30 仅作静默失败补偿，无需群内 `@` 或人工触发；只读`02｜营销战役`、`04｜任务事项`、`05｜营销主题与节奏`、`06｜内容物料`四张核心表，向测试群推送一条完整飞书 Markdown / 富文本消息。它不是卡片，不使用卡片色块，不提供按钮，也不修改业务记录。消息必须包含统计周期和数据截止时间、核心数据、战役情况、风险与阻塞、待决策事项、Todo、AI 建议、数据缺口及多维表格/看板入口；事实、推断和建议分层表达。关键来源读取失败时必须标记数据缺口及受影响结论，不得宣称“整体正常”。任务指标口径为：有效任务总数 = 全部任务减去`已取消`；已完成 = 有效任务中状态为`已完成`；未完成 = 有效任务总数减去已完成；完成率 = 已完成 ÷ 有效任务总数。有效任务为 0 时显示`0/0（—）`；风险任务仍单独展示。同一自然周最多一条成功总览；10:00 成功后后两次调度不联网、不重复发送；人工受控补发也必须命中同周幂等。
9. 高影响写操作按各自冻结规则先预览、确认后执行；完整且合法的设计提需和月度策略同步是直接写入入口，不增加二次确认。所有写入都必须回读，幂等键阻止重复写入。
10. 设计提需以双表逐字段回读一致作为绿色成功卡闸门；月度策略同步以整批逐字段回读一致作为成功文字闸门。任一回读不确定都必须回复固定失败文字，不得宣称成功。

“每日综合 DDL 汇总”（任务、物料、逾期、战役关键节点 T-3）仅列入[待最终配置能力清单](./待最终配置能力清单.md)，当前未配置、未启用。战役关键节点的事实源与发送时间必须在最终结构冻结后另行确认。

## 7. UAT 规则

- 测试群：数码宝贝世界。
- 「数码宝贝世界」是唯一 UAT 群。月度策略所有测试消息、文字回执和模拟数据都必须留在该群；禁止在「月度策略同步」群进行任何施工或 UAT。
- 测试负责人、提需人、设计负责人、审核人、验收人统一使用常浩账号。
