# 营销战役 AI 协同 MVP｜卡片视觉与交互规范 V4

> 当前状态：本规范对应的设计提需 V2 卡片已完成实现与预放行部署，自动检查通过；“数码宝贝世界”真实群人工 UAT 尚未完成，因此以下内容是当前被测规范，不是正式放行证明。

## 1. 设计目标

卡片不是把表格字段搬进聊天框，而是让当前角色在 5 秒内看清：

1. 这是什么对象；
2. 现在处于什么状态；
3. 哪些事实必须马上核对；
4. 当前判断和下一步是什么；
5. 应该打开哪里、点击什么。

所有卡片统一使用飞书 Card 2.0。不同场景可以调整内容排布和浅色块组合，不要求所有卡片长得完全一样；状态语义、字体层级、按钮规则和业务边界必须一致。

## 2. 一张卡的五层结构

### 第一层：状态头部

- 标题：`状态｜业务对象名称`。
- 副标题：业务流程、当前角色或关键时间。
- 头部颜色表达状态，不表达个人偏好。
- 最多 3 个短标签，避免标签墙。
- 不显示记录 ID、文件 Token、事件键、open_id、Prompt 或错误堆栈。

### 第二层：关键指标

- 最多优先展示 2—3 个短值，例如优先级、DDL、当前状态、SKU 数量。
- 指标值使用加粗或状态强调色。
- **指标的小标签可以使用浅灰色小字**，例如“优先级”“截止时间”“待补字段”。
- 指标块可搭配 2—3 种相容的浅色，不要求整张卡只有一个颜色。
- 指标不是业务人员身份卡，不用于放长文本。

### 第三层：角色与业务事实

设计提需成功卡必须高对比展示三个等宽信息块：

1. **物料名称**；
2. **类型需求**：使用场景 + 物料规格；
3. **交付 DDL**：设计提需只展示日期，不展示几点几分。

进入角色协作后，卡片还必须按当前状态高对比展示 **提需人**、**设计负责人**、**审核人**。以上关键字段的**字段名和字段值都必须使用黑色加粗**，不得做成浅灰字。没有可读姓名时显示“已指定”或“待分配”，不显示人员 ID；设计负责人由外部设计需求 Base 维护，不提供群卡片领取动作。

同类关键事实也使用黑色高对比，例如任务负责人、验收人、所属战役、所属主题。空值不展示，不用大量“暂无”填满卡片。

### 第四层：当前判断、正文与链接

- 用浅色焦点区承载“当前判断”“下一步”“验收标准”或“完成说明”。
- 区块标题黑色加粗；说明正文使用黑色正常字重，保证可读性。
- 结论在前，必要事实或说明在后。
- 长文本只展示完成决策所需的部分，完整内容通过明确链接查看。
- 设计提需成功卡底部保留“查看设计提需文档”；后续制作、审核和交付工作面再按需要提供记录或终稿入口。
- 链接文案写清动作和对象，例如“打开提需文档”“打开记录上传终稿”“打开记录查看终稿”“查看交付物”。
- 不显示裸 URL，不使用“点这里”“详情”等模糊文案。

### 第五层：系统说明与操作

- 更新时间、数据来源、UAT/正式环境、状态版本和防重复说明使用浅灰小字。
- “只检查附件，不读取图片内容”等系统边界可以放在灰色说明区。
- 灰色说明只保留当前动作必需信息，最多 4 行。
- 按钮位于卡片底部；一张卡最多一个最强主操作。
- 正常流转优先更新原卡，不再额外发送一段重复摘要。

**日期粒度不变量：**内容物料跨部门对接链路中的业务日期——提需交付 DDL、外部设计期望交付日期、催办到期日、审核业务日期、终稿交付日期、完成回执日期——全部只显示年月日。Base 使用`yyyy/MM/dd`，卡片使用`8月31日`这类业务化日期。输入或底层事件含时分时，业务卡不展示时分；消息/卡片发送时间、同步时间、AI 运行/审计时间、状态更新时间等系统时间可在灰色说明区保留时分。任务事项 DDL 不受本规范影响。

## 3. 字体规则

图标或 emoji 与标题文字组合时，二者之间固定保留 **一个半角空格**，形成一致的视觉呼吸感。例如写成 `✅ 物料名称`、`1️⃣ 使用场景`，禁止写成 `✅物料名称`、`1️⃣使用场景`。这条规则适用于指标标题、字段标题、步骤标题和状态短语；图标单独成列或单独作为 Header icon 时不额外补空格。

| 内容 | 样式 | 示例 |
|---|---|---|
| 卡片标题、当前判断、下一步 | 黑色加粗 | **待审核｜开学风险提醒长图** |
| 物料名称、使用场景、物料规格、物料大类，以及当前状态涉及的提需人、设计负责人、审核人 | **黑色加粗** | **物料规格** / **三宫格** |
| 其他决定操作的关键事实 | 黑色加粗 | **所属战役** / **秋季开学战役** |
| 当前判断、验收说明、正文 | 黑色正常字重；小标题加粗 | **当前判断**：信息齐全，可以创建 |
| KPI 值 | 加粗或状态强调色 | **P0**、**8月30日** |
| KPI 小标签 | 可浅灰小字 | 优先级、截止时间 |
| 系统时间、来源、环境、版本、系统边界 | 浅灰小字 | 更新时间 10:15｜状态版本 5 |

禁止：

- 把业务人员姓名、物料大类、使用场景或物料规格做成浅灰字；
- 用灰字承载用户必须马上核对的信息；
- 为了“高级感”降低核心事实的对比度；
- 把所有内容都加粗，导致没有层级。

## 4. 配色语义

| 场景/状态 | 头部主色 | 可搭配内容色块 | 语义 |
|---|---|---|---|
| 设计提需信息不足 | 黄色 | yellow-50、orange-50、grey-50 | 等待补齐后重新发送 |
| 设计提需外部同步失败 | 红/橙色 | red-50、orange-50、grey-50 | 主表可能已记录，外部同步待恢复 |
| 制作中、进行中 | 蓝/水蓝 | blue-50、wathet-50、grey-50 | 正在执行 |
| 待审核 | 橙色 | orange-50、yellow-50、grey-50 | 需要专业判断 |
| 已完成、写入回读成功 | 绿色 | green-50、turquoise-50、grey-50 | 已闭环或已写入 |
| 异常停止 | 红色 | red-50、orange-50、grey-50 | 已停止，需要人工处理 |

颜色约束：

- 头部使用一个状态主色；正文可以有 2—3 个浅色块形成层级。
- 红色只用于真正无法继续的异常；“缺少信息但尚未写入”使用黄色。
- 不用颜色代替文字；任何状态必须明确写出。

营销战役周度总览不属于卡片体系，不套用卡片头部、色块或按钮规范；其 Markdown / 富文本可以使用标题、分隔线、表格、列表、加粗和状态 Emoji 辅助扫读，但不能伪装成卡片。

## 5. 链接规则

| 卡片 | 应出现的链接 | 不应出现的链接 |
|---|---|---|
| 信息不完整卡 | 提需文档链接本身有效时可保留“打开提需文档” | 无效链接、确认创建、虚假的 Base 记录入口 |
| 设计提需成功 | “查看设计提需文档” | 裸 URL、记录 ID、额外领取入口 |
| 设计提需同步失败 | 有效提需文档链接、必要的人工核对入口 | 绿色成功语义、重复执行按钮 |
| 物料制作中 | “打开提需文档”“打开记录上传终稿” | 要求机器人识别图片内容的链接 |
| 物料待审核 | 正文中的`查看设计Brief | 具体文档链接`：整行使用 12px 辅助文字，左侧标签为浅灰色，右侧真实文档名为蓝色可点击链接；终稿图片直接随卡展示 | 额外的 Brief 按钮、只有文件名或无法定位对象的文字 |
| 物料已完成 | “打开提需文档”“打开记录查看终稿” | 只有文件名、无法定位对象的文字 |
| 任务事项入口回复 | [“打开 04｜任务事项”](https://vm94j8bzy7.feishu.cn/base/LgqpbDFz8a9XmNs3TxccAP0Hn7b?table=tblMK7GxGkyQUviP) | 任务草稿、任务记录预览、任务状态按钮 |
| 月度策略文字回执 | 固定的蓝色可点击文字[“营销战役表”](https://vm94j8bzy7.feishu.cn/base/LgqpbDFz8a9XmNs3TxccAP0Hn7b?table=tblaUHNEhPhYjfJw) | 裸 URL、记录 ID、额外入口或卡片按钮 |
| 周度总览（非卡片消息） | 消息末尾可附“营销战役 AI 协同台”或相关看板的蓝色文字链接 | 按钮、修改状态入口、批量写入入口 |

只有有效的 `http://` 或 `https://` 链接才进入卡片。

## 6. 按钮规则

### 统一组件与尺寸

- 所有操作入口统一使用飞书 Card 2.0 原生 `button`，不得再用 `interactive_container` 或彩色色块模拟按钮。
- 单按钮使用 `width: fill` 占满卡片内容区；双按钮放在同一个两列等分栏中，两列权重均为 1、按钮均为 `width: fill`。
- 单按钮与双按钮组的左右外边界必须完全对齐；双按钮严格等宽。所有按钮统一使用 `size: medium`、零外边距和原生圆角、内边距及文字居中规则。
- 原生按钮没有绿色类型；正向主操作使用 `primary_filled`（蓝色），退回或拒绝使用 `danger_filled`（红色），普通跳转按主次关系使用 `primary_filled`、`primary` 或 `default`。

### 主按钮

- 每张卡最多一个主按钮。
- 代表当前角色最自然的下一步。
- 示例：“审核通过”。设计提需结果卡和任务事项不提供状态按钮。

### 普通按钮

- 用于非破坏性的备选路径。
- 示例：“返回补充”“打开记录上传终稿”“备用：已上传，提交审核”。
- 备用提交只用于附件巡检未触发的情况，不能变成日常主路径。

### 退回按钮

- 使用危险样式，并弹出二次确认。
- 文案写清后果，例如“退回后回到制作中”。
- 本期只记录结果，不要求在卡片里填写详细退回原因；具体修改在线沟通。

### 权限与防重复

- 设计提需完整消息直接执行，不存在提需确认按钮；同一来源消息必须幂等。
- 设计负责人在外部设计需求 Base 中维护，不通过群卡片领取。
- 审核校验审核人角色；任务推进与验收由使用者在 Base 手工维护，不通过卡片执行。
- 每个动作同时校验当前状态和状态版本。
- 旧卡、重复点击和并发点击不能重复创建或重复推进。

## 7. 各类卡片的内容要求

设计提需入口严格只有三类结果卡：信息不完整卡、需求提报完成卡、同步失败卡。完整消息不再发送写入前预览卡；设计人员直接在外部对应月份设计需求表处理，不再增加领取卡片。

### 全局移动端响应式基线

- 电脑宽屏继续使用已经确认的 2×2、三列或双按钮并排布局；
- 手机等窄屏中，任何并排色块或按钮必须按电脑端的业务阅读顺序，逐块变成全宽单列并从上到下排列；不得继续压缩并排，不得裁字、遮字或横向溢出；
- 信息不足卡、提需完成卡、待审核卡、审核退回卡和审核通过卡全部遵守同一规则；
- 奇数个色块直接以实际数量纵排，不得为凑齐电脑端双列而插入空白占位块；
- 单列正文、辅助小字、图片与链接不改变既有顺序；历史已发送卡片不会被追溯改写，新发送与后续状态更新卡使用本规则。

### 7.1 信息不足卡

- 黄色头部，标题固定为`待确认 | 设计提需信息不足`；不增加重复副标题。
- 标题下使用一条与内容等宽的浅灰窄长块，单行显示`缺少必填字段：n`，其中数字使用红色。
- 窄长块下面保留适当留白，再显示`👇 请一次性补齐下方必填信息`。
- 缺失项在电脑宽屏使用两列网格；四项缺失时为两列两行、四个长宽完全一致的浅色块。同一行两块并排，块宽、块高、内边距和彼此间距不随文字多少变化；手机等窄屏必须按编号顺序改为全宽纵向排列，不得压缩、裁字或产生空占位块。字段标题黑色加粗，选项或示例使用黑色正常字重。
- 四块下方展示`✅ **提需示例：**`和完整自然语言示例；“设计 Brief 需求模板”使用真实蓝色文档链接。
- 底部显示`写入状态：未写入`，其中“未写入”使用红色。
- 一次列全全部缺失、歧义、枚举非法、链接非法或 DDL 不明确的问题。
- 只给一个下一步：补齐后重新发送完整消息。
- 不放“确认写入”，不出现绿色或成功语义。

### 7.2 需求提报完成卡

只有以下全部完成后才能发送：主表写入并回读；读取主表自动生成的“提需时间”，按 Asia/Shanghai 取创建月份（业务简称“上表月份”）；定位外部`${M}月营销组需求表`；只同步`需求内容`、`需求人`、`期望交付时间`、`相关需求物料`、`项目场景`；外部逐字段回读一致。这两张表的写入和回读是成功卡的唯一闸门；最小 AI 执行记录在业务完成后留痕，日志失败不阻塞或撤销成功卡。

- 使用绿色头部；
- 主标题固定为`已确认 | 完成提需并同步多维表格`；
- 标题下在电脑宽屏只放一行三个等宽信息块，依次为**物料名称**、**类型需求**、**交付 DDL**；手机等窄屏必须按同一顺序改为三个全宽纵向色块；
- 电脑端三块长宽、内边距和间距完全一致，不随文字多少改变；手机端每块占满内容宽度，块间保留一致纵向间距；
- 类型需求固定拼接为`使用场景 + 物料规格`，例如`朋友圈 + 九宫格`；
- 交付 DDL 只显示日期，例如`8月31日`；即使原消息含时间也不显示几点几分；
- 底部固定为`写入状态：已写入 | 查看设计提需文档`；
- “查看设计提需文档”必须是本次提需文档的真实蓝色链接；
- 不放确认、返回、领取或重复同步按钮；不另发重复文字摘要。

### 7.3 设计提需同步失败卡

主表已写入但外部月份表创建或回读失败时，使用红色或橙色，不得使用绿色或“已完成”标题。必须明确：主表是否已记录、外部失败环节、主表“提需时间”按 Asia/Shanghai 得到的创建月份、当前为待重试，以及“不要重新发起同一需求”。系统保留主表记录并只重试外部同步；双表恢复一致前不发送成功卡。

### 7.4 物料制作中卡

必须包含：**提需人**、**设计负责人**、**审核人**、**物料大类**、**使用场景**、**物料规格**；提供“打开提需文档”，明确把终稿放入哪个字段；提供“打开记录上传终稿”和备用提交；灰字说明只检查附件是否存在。若展示交付 DDL 或催办到期日，只显示日期，例如`8月31日`，不显示时分。

### 7.5 物料待审核卡

必须包含：**提需人**、**设计负责人**、**审核人**、**物料大类**、**使用场景**、**物料规格**；正文固定保留`设计终稿已正式提交，请审核人查阅下方成图，完成对应审核流程`，紧接下一行使用`查看设计Brief | 具体文档链接`：整行与`视觉预览 | 连接真实记录`同为 12px 辅助信息层，左侧标签使用浅灰色，右侧显示具体文档名称并保持蓝色可点击。两行置于同一紧凑信息组，不能受卡片正文的大间距影响而分离。不设置 header 副标题，不展示测试说明，不再提供独立的 Brief 按钮；终稿图片直接随卡展示，并保留原生“审核通过”“退回修改”按钮。终稿交付日期、审核截止日期或审核业务日期如出现，只显示年月日；主表`设计完成时间`和`审核时间`的业务界面统一为`yyyy/MM/dd`。

电脑端信息色块保持 2×2，手机端按`物料名称`→`类型需求`→`提需人`→`审核人`全宽纵排；两个审核按钮在手机端按`审核通过`→`退回修改`全宽纵排，不能挤在同一行。

### 7.6 审核通过后的卡片收口

审核通过后不生成提需人二次确认卡。原审核卡必须原位更新为不可操作的绿色完成态，移除“审核通过”“退回修改”等业务按钮；不得另发紫色待确认卡或提需人确认入口。

审核通过与审核退回后的三项状态色块，电脑端保持三列，手机端统一按`当前状态`→`交付 DDL`→`优先级`全宽纵排。

### 7.7 物料完成卡

- 绿色头部。
- 明确“审核已通过，物料流程已完成”。
- 保留“打开提需文档”和查看终稿的记录入口。
- 完成回执日期只显示年月日；主表`完成时间`的业务界面统一为`yyyy/MM/dd`。
- 不再放业务流转按钮。
- 灰字提示可按需在 Base 勾选“需入中台”。

### 7.8 任务事项直达回复

任务事项当前不使用预览卡、状态卡或完成卡。机器人识别到新建、补充、改派或状态维护任务请求时，只返回一条简洁回复和[“打开 04｜任务事项”](https://vm94j8bzy7.feishu.cn/base/LgqpbDFz8a9XmNs3TxccAP0Hn7b?table=tblMK7GxGkyQUviP)直达链接，并说明“请在 Base 直接填写或修改”。

不得出现：

- 任务草稿或写入前预览；
- “确认写入”或“创建成功”语义；
- “开始任务”“提交验收”“验收通过”“退回继续”等状态按钮；
- 声称已写任务、已改派、已修改状态或已写 AI 执行记录。

此前的任务预览卡和任务状态卡属于历史能力，已被当前 Base 手填规则取代，不再作为当前卡片模板。

### 7.9 月度策略文字回执

月度策略不使用任何卡片，也不提供“确认写入”“返回补充”或重试按钮。常浩发送的完整月度消息本身就是执行确认；系统整批预校验通过后直接按`月份 × 业务线 × SKU`写入并回读。

对外回执严格只有两种，均通过 `reply-in-thread` 进入原促销方案消息的“1 条回复”话题，并在话题中只回复一次：

1. **全部写入并回读一致：**`月度促销方案同步成功 | [营销战役表](https://vm94j8bzy7.feishu.cn/base/LgqpbDFz8a9XmNs3TxccAP0Hn7b?table=tblaUHNEhPhYjfJw)`；
2. **任何失败：**`月度促销方案同步失败 | [营销战役表](https://vm94j8bzy7.feishu.cn/base/LgqpbDFz8a9XmNs3TxccAP0Hn7b?table=tblaUHNEhPhYjfJw)`。失败包括预校验失败、字段缺失、部分执行失败和回读失败。

“营销战役表”必须使用飞书 Markdown 渲染为蓝色可点击链接。回执不带月份、业务线、SKU 数、创建数、更新数或失败明细，不追加说明、总结或第二条消息。同一来源消息 ID 重投时不重复写入、不重复回复；大学辅导与国际课程分两条消息发送时，各自通过 `reply-in-thread` 进入自己的原消息“1 条回复”话题，且话题内只有一条固定 Markdown。

2026-08-27 真实 UAT 已验证这一呈现规范：源消息 `om_x100b66378ddd20a4c4cece514395f94` 的唯一成功回执 `om_x100b6637a1893534c244a69535c0d82` 位于话题 `omt_19f5b4f82ccf5be0`，`thread_message_position=0`；源消息最终只显示 1 条话题回复，无卡片、无明细、无第二条消息。

### 7.10 营销战役周度总览（非卡片消息）

周度总览已退出飞书 Card 2.0 范围。它是每周一 10:00（Asia/Shanghai）主执行、10:10/10:30 静默失败补偿的只读任务，无需群内 `@` 或人工触发；同一自然周向群里最多推送一条成功的完整飞书 Markdown / 富文本消息，不使用卡片容器，不提供任何按钮。

数据范围固定读取四张核心表：

1. `02｜营销战役`；
2. `04｜任务事项`；
3. `05｜营销主题与节奏`；
4. `06｜内容物料`。

消息固定按以下顺序组织：

1. 标题、统计周期、数据截止时间和事实源；
2. 核心数据：进行中战役、任务 KPI、进行中主题、未完成物料、待审核物料、风险/阻塞数量；
3. 战役情况：阶段进展、关键变化和本周节点；
4. 风险与阻塞：对象、影响、负责人和下一动作；
5. 待决策事项：需谁在何时前作出什么决策；
6. Todo：按优先级列出本周动作、负责人和 DDL；
7. AI 建议：与已确认事实分开表达；
8. 数据缺口：缺失字段、未登记事项或读取失败；
9. “营销战役 AI 协同台”或看板的蓝色文字链接。

任务 KPI 口径固定为：有效任务总数 = 全部任务中排除`已取消`；已完成 = 有效任务中状态为`已完成`；未完成 = 有效任务总数减去已完成；完成率 = 已完成 ÷ 有效任务总数。有效任务为 0 时展示`0/0（—）`；风险任务仍在风险区单独展示。

消息必须区分“Base 已确认事实”“AI 分析/建议”和“数据缺口”。关键来源读取失败时，必须明确指出缺口及受影响结论，不得用空数据推断“一切正常”。同一自然周最多保留一条成功总览；人工受控补发也必须遵守同周幂等，不得重复刷群。

当前不设计“每日综合 DDL 汇总卡”。该能力仍待最终配置，未启用；关键节点事实源和发送时间确认前，不得把草图或示例卡作为运行中能力展示。

### 7.11 异常卡

- 真正停止才使用红色。
- 说明停止原因、是否发生业务写入、以哪里为准和下一步怎么做。
- 不展示内部工具日志、堆栈、凭据或 Prompt。

## 9. 发送前检查

每新增或修改一种卡片，逐项检查：

1. 只看标题和颜色，能否识别当前状态；
2. 是否只保留 2—3 个真正重要的指标；
3. 物料名称、使用场景、物料规格、物料大类，以及当前角色信息的字段名和值是否全为黑色加粗；
4. 当前判断和下一步是否先出现；
5. 灰字是否只用于系统时间、来源、环境、版本与系统说明；内容物料业务日期是否只到年月日且没有被误当成系统精确时间；
6. 是否隐藏空字段、人员 ID、记录 ID、文件 Token、幂等键和内部实现；
7. 链接是否能打开正确对象，文案是否明确；
8. 是否最多一个主按钮；
9. 退回是否二次确认并说明后果；
10. 是否校验操作者、当前状态和版本；
11. 正常流转是否更新卡片，而非重复发送摘要；
12. 所有目标 Base 的写入、回读和卡片状态是否一致。
13. 设计提需卡是否始终提供有效的“打开提需文档”链接；
14. 信息不足卡是否一次列全问题并保持双表零写入；成功卡是否只在主表与外部月份表逐字段回读一致后出现。
15. 所有“图标/emoji + 标题文字”是否统一保留一个半角空格，且没有紧贴显示。
16. 成功卡是否使用固定标题、三个等宽信息块和固定底部文案，且没有任何额外领取或确认按钮。
17. 提需、设计同步、催办、审核、终稿交付、完成回执中的业务日期是否全部只显示年月日；只有系统运行与审计时间可以保留时分。

## 10. 不允许的做法

- 用浅灰字展示人员、物料大类、使用场景或物料规格；
- 用一大段文字替代“指标—事实—判断—链接—动作”的结构；
- 整张卡只用一种同浓度色块，造成没有层级；
- 先发卡，再补发一条完全重复的文字；
- 在设计提需成功前显示尚不存在的记录链接或绿色完成语义；
- 给所有按钮都用主色或危险色；
- 让机器人读取终稿图片后自行判断审核是否通过；
- 用卡片代替多维表格事实源；
- 只因为动作已发出就声称结果已经完成。
- 在当前卡片中继续展示或要求填写旧字段“物料形式”“使用场景/规格”“需求说明”。
- 主表已经写入、但外部月份设计需求表失败时发送绿色成功卡。
- 把“上表月份”当作独立可写字段，或用交付 DDL 月份代替主表自动生成的“提需时间”创建月份选择外部表。
