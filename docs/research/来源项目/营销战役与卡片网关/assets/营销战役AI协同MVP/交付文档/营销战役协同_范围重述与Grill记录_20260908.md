# 营销战役协同｜范围重述与 Grill 记录

状态：2026-09-08 用户以“回复一致”确认完整共识。Q1—Q6、完整业务链路与最小补充规则已确认，可进入具体设计；本文件是业务共识，具体任务模板及实施版本尚未发布，不构成迁移或线上操作记录。旧范围与此冲突时以本轮用户明确说明为准，旧现场取证仍保留其时点价值。

## 用户本轮明确的方向

1. 营销战役属于标准化程度较高的项目推进场景；营销战役名称、人工选定的负责人和开始时间齐全后，才能一键生成标准流程任务。负责人和初始排期由用户决定。
2. 营销专属多维表格智能体负责进度查询与日报、周报、月度汇报；周期汇报面向正在进行的战役，已结束战役不纳入默认周期汇报。通常同一时间只有一场进行中。
3. 机械邪龙兽未来退出营销相关任务执行，转为带教机器人；整体项目汇报需要时，将营销作为一个板块引用汇报。
4. 已实现的飞书卡片交互得到用户认可，保留审核、通过／退回等交互方案；承接方变化只验证受影响能力，不能无故推倒重做。
5. AI 的专业业务分析集中在营销策略：输入包括目标用户、待办事项、痛点、主推 SKU，依据知识库营销策略板块作综合分析。
6. 营销知识按时间、人群、国家及实际需求等条件组织；具体知识后续由用户补充，不在此轮虚构内容。
7. 策略经人确认或反馈修改；本场全部适用策略确认后，进入主题节奏。
8. 主题节奏由人填写，内容物料也由人填写；智能体主要承担物料提需、交互、审核流转和表格回写。
9. 月度促销方案继续支持识别回填。
10. 未被本轮否定的旧边界继续保留：业务负责人、物料对接人、审核人三角色；具体终版审核及指定交接；交付后 AI 自动总结，不增加二次签收、人工复盘、私域跟踪。

## 对上一版评估和实施路线的纠正

- 撤销将 AI 自动生成完整文案、设计需求、物料组合和排期作为项目必须完成能力的推定。已有九月文字和图组保留为历史成果，不再作为新范围中 AI 专业生产的必验分母。
- 策略质量仍需验收；主题及物料的内容质量由相应人工职责负责，系统验收信息完整、状态正确、流转与交付可追溯。
- 撤销将机械邪龙兽当前营销执行链当作最终架构的默认假设。先核定专属智能体与确定性自动化的承接分工，再决定旧能力的复用、迁移和退役；不能继续照旧交接先恢复旧执行器。
- 不把上述目标分工写成已迁移。现有本地证据仍指向机械邪龙兽临时执行；本地已有迁回契约，但未证明专属多维表格智能体的现行绑定与完整运行状态。
- 旧九月 UAT 是特定内容和旧分工的样本，后续哪些步骤与成果可以复用，须按新范围映射；不默认重新生产旧文字包，也不把旧测试成功全部作废。

## 还原的三条业务线

工作主线：人明确战役名称、负责人和开始时间 → 标准化新建并生成任务 → 输入与营销知识 → AI 策略候选 → 人确认／修改 → 全部适用策略确认 → 人填主题节奏 → 人填物料需求与内容 → 制作、提交与终版审核 → 指定交接 → 自动过程总结。

过程管理线：从同一营销事实源读取任务、责任、期限、物料和决策状态，提供按需问答；日／周／月汇报面向当前进行中的战役，通常为一场。带教整体汇报引用营销摘要，不另行执行营销任务。

月度事实线：读取正式促销方案 → 识别月份、业务线、SKU、价格及活动 → 校验 → 回填 → 回读及结果回执。该线提供当期事实，不与管理月报或策略创作混为一谈。

## 经整体共识确认的补充原则（源于助手建议）

- 策略说明包含实际场景判断、需求与痛点优先级、SKU 适配理由、核心主张与策略选择、来源和限制；不扩写为主题排期和物料正文。
- 月份、国家与年级是匹配条件，实际学习阶段和明确事件优先；不得从“九月”直接推断所有学生处于同一阶段。
- 明确本场适用策略集合，防止新增草稿不断改变“全部通过”的范围；策略退回保留理由和版本，变更后只处理受影响内容。
- 汇报按管理任务分层：日报关注当前战役的当天动作和阻塞；周报关注本周里程碑、延期和待决策；月报关注当前战役本月的推进与过程问题。三个周期均遵守 Q6 的进行中范围；精确发送时间、接收对象及摘要格式留待配置前集中落实。
- 内容缺失不假定已经完成；具备明确证据的事件自动推进，人工阶段的完成声明方式见 Q4。
- 原促销识别规则作为核对底稿，区分新增与更正，回写不重复，历史已批准策略不因当期促销更新被静默改写。

## 第一轮已确认决定

Q1 标准任务底稿：用户选择“先按这次场景重新梳理任务，再对照旧模板”。不得先固定五阶段十一任务，不得把旧模板数量反向套到新流程。

Q2 “待办事项”含义：用户确认指目标用户要完成的事情，与营销团队的项目任务区分。

Q3 知识不精确匹配时的策略边界：用户确认允许基于已有知识有依据地类比，作为待确认策略；明确差异和假设，缺失产品或促销事实不得作承诺。未选择自动补充外部资料。

Q4 人工填写阶段如何完成：用户确认明确业务事件自动推进，人工填写一次提交完成，系统检查必要信息后推进。不是字段一有内容就认定完成，也不要求所有步骤重复人工标记。

## 第二轮已确认决定

Q5 标准化新建的前置条件：用户明确负责人和初始排期由自己选定；只有营销战役名称、负责人、开始时间齐全后，才能进入标准化新建。不能让 AI 自主指派负责人或决定启动时间，也不能把三项必要输入延后到生成任务之后补齐。用户明确的必填负责人不擅自扩展为三角色全部必须在创建前选定。

Q6 定时汇报的范围：用户明确汇报仍在进行中的战役，通常同一时间只有一场，其余已结束。将助手此前较宽泛的营销全局总览建议收敛为进行中战役的进度汇报；日／周／月均围绕正在发生的战役。

两轮六项方向问题均已回答，当前不再追加一轮访谈。精确任务清单、人工填写各任务初始日期的位置、汇报时间和接收对象在共识后形成具体配置稿；不因用户选择战役开始时间而新增自动计算各任务工期的要求。

据 Q5—Q6 提出的最小配套规则（已随“回复一致”整体确认）：

- 三项输入未齐时明确提示缺项，保留可继续填写的内容；齐全后才允许生成，重复触发不重复建任务。
- 按战役正式状态确定汇报对象，不用最近创建、最近修改或月份标签代替“进行中”。新建前置齐全只证明可以生成任务，不自动证明战役已开始推进。
- 没有进行中战役时不周期性发送空报；主动询问时说明当前没有进行中战役。偶有多场进行中时分别列清，不能静默漏掉其中一场；不因“通常一场”新增限制并行的业务规则。
- 已结束战役保留记录和交付时的自动过程总结；默认停止该战役的日／周／月进度汇报。归档和主动历史查询不扩展为新的持续跟进工作。

## 按新场景推导的业务草图（业务共识已确认）

每场战役的固定主任务表示整场推进阶段；每条策略、每份物料各自承担具体执行事项。报告和月促销维护作为持续能力保留，周期报告的对象为当前进行中战役，不应随每次新建重复生成一套报表或促销维护待办。

| 业务段 | 需要得到的结果 | 主要责任和推进方式 |
| --- | --- | --- |
| 明确战役与策略输入 | 目标、范围、用户待办、痛点及 SKU 足够支持分析，关键限制可识别 | 人提供事实；智能体整理并提示必要缺口 |
| 形成并定案策略 | 本场适用策略全部确认，修改意见已处理 | AI 综合分析；业务负责人决定；具体策略分别跟踪 |
| 提交主题与节奏 | 已填写本场传播主题和节奏 | 人填写，一次提交；提交完成后更新对应任务 |
| 提交物料内容与需求 | 明确应交物料及制作所需内容，形成查漏依据 | 人填写，一次提交；卡片组织提需与信息交接 |
| 分物料制作、终审与交接 | 每份物料按自己的就绪程度制作，具体版本经人审核并指定交接 | 人制作和审核；既有卡片与自动化记录、回写、推进；退回重审受影响版本 |
| 全场交付收尾 | 对照完整应交清单，成果齐全、终版通过且可访问、指定交接完成 | 根据证据汇总完成；AI 自动过程总结 |

这六段是业务梳理，不是把模板冻结成六条任务。之后再按可独立负责、交付和认定完成的工作拆任务，并对照旧模板判断保留、合并、修改或删除。

补充边界：仅局部策略确认不得进入主题节奏；全部策略定案后，满足输入的物料可以各自制作、审核和交接，不强迫所有物料等待最慢一份。人工提交计划不等于制作完成；审核通过不自动等于指定交接已发生；同一物料不要求在两张表重复维护两份状态。

## Q4 落到具体业务动作后的含义

以下场景说明已随整体共识确认；不冻结按钮、字段或技术方案。

| 场景 | 能够证明什么 | 如何推进 |
| --- | --- | --- |
| 负责人只填写了部分主题或节奏 | 已有草稿 | 保留草稿，不自动认定本阶段完成 |
| 负责人提交主题节奏，必要信息校验通过 | 人工计划已完成提交 | 自动完成对应计划任务，无须再去任务表重复标记 |
| 人工提交一份完整物料需求及内容 | 本份物料具备提需条件 | 按既有协作方式组织交接与制作；不认定制作已经完成 |
| 审核人通过某个具体版本 | 该版本已通过专业审核 | 自动更新审核结果及相关进度；不提前认定指定交接已发生 |
| 已审核终版完成约定的指定交接，并有可核对结果 | 本份物料已交付 | 自动更新物料交付状态及战役汇总，不增加二次签收 |
| 应交清单中的全部物料均满足交付条件 | 本场交付已完成 | 汇总收尾，生成基于事实的自动过程总结 |

卡片负责表达操作，业务记录负责保存事实。显示了成功消息不能单独证明正式表格已经正确更新；重复提交、重复点击及过期卡片不得重复推进。

## 策略怎样达到可用质量（整体确认的质量原则）

策略的专业性体现在论证与取舍，不能用篇幅、文案数量或物料数量代替。建议每条策略至少让负责人看清六件事：

1. **适用情境。** 哪类用户、什么实际阶段、要完成什么事情、优先解决哪个痛点。
2. **依据与推断。** 输入事实、知识库依据与类比判断分别是什么；说明适用条件、差异、假设和缺口。
3. **SKU 适配机制。** 具体困难需要什么支持，SKU 的哪项已知能力能提供支持，适配的前提及限制是什么。主推 SKU 与需求不匹配时明确指出，不能强行推荐。
4. **策略选择。** 优先强调什么价值，主要消除什么理解障碍或顾虑，为什么采取这个方向；存在备选时给出推荐及理由。
5. **人工工作的依据。** 主题节奏、物料内容需要保留什么重点、遵守什么事实口径、避开什么无依据承诺。交付这些约束，不替人编写下游内容。
6. **可定案结论。** 负责人能明确采用、要求修改或不采用；修改后能够辨认改了什么以及最终确认的是哪个版本。

策略推导链：实际情境 → 用户要完成的事 → 具体障碍及优先级 → 所需支持 → SKU 的已知能力及适配限制 → 本次价值重点与营销取舍 → 人确认。

例如用户给定“美国、大一、九月、考前”，应以已给定的考前任务判断需求；月份只是背景，不能改写为统一的开学需求。具体障碍仍需由输入及知识支持。若某项 SKU 能力尚未被资料证明，就只能指出待补事实，不能据此许诺考前效果。

## 三条业务线之间怎样协同（整体确认）

- **知识与当期事实提供依据。** 营销知识说明适用条件和方法；SKU 目录说明产品能力；月度促销记录提供当期价格、活动和有效范围。三者共同支撑策略，但不互相替代。
- **主流程形成可查询的事实。** 策略定案、计划提交、制作版本、审核与指定交接，形成战役的真实推进记录。
- **问答与报告读取这些事实。** 回答当前节点、下一动作、责任人、期限、阻塞和待决策；标明依据更新时间。没有记录就说明信息缺失，不用推测填满报告，也不把任务完成比例当作营销效果。
- **机械邪龙兽在整体汇报中引用营销板块。** 营销专属智能体提供该板块的进展与异常；机械邪龙兽按带教整体汇报需要引用，不重新派发或修改营销任务。具体承接能力及连接方式在共识后核验。
- **促销事实更新有独立处理。** 来源明确、字段完整且校验通过时识别回填并回读；有冲突或歧义时说明具体缺口。促销变更影响已确认策略时提示影响，由人决定策略是否修订，不能静默覆盖旧定案。

## 最小补充规则与完成判断（整体确认）

1. **以应交清单防漏项。** 清单来自人工明确提交及后续明确变更。不能只检查当前已经创建的物料，因为漏建项会因此消失。
2. **变更只重查受影响部分。** 策略、促销或物料版本改变时，明确影响哪些已确认结论及未完成事项；不沿用失效审核，也不无差别重启整场战役。
3. **异常必须能继续处理。** 输入缺失提示缺什么；人工步骤未提交保持未完成；写回失败不报成功；重试不重复生成事项或重复发送同一结果。
4. **汇报必须能指导行动。** 按 Q6，日／周／月均围绕当前进行中战役，分别侧重临近动作与阻塞、本周里程碑和待决策、本月推进与过程问题；时间和接收对象在配置前落实。
5. **业务终点保持清楚。** 本轮跟进到指定物料交付及自动过程总结，不自行加入投放、私域使用、成交归因或人工复盘；任务完成也不证明营销业务目标已经达成。

后续验收应分别证明标准任务能生成、策略可供决策、卡片动作正确反写、各物料能独立走到交付、问答及各周期汇报与正式记录一致、月促销能从真实来源正确回填，并证明营销专属入口承接后分工成立。这是完成结果的梳理，尚非实施用例或新的完成度评分。
