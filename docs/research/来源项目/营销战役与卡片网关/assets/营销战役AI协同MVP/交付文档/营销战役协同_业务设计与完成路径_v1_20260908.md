# 营销战役 AI 协同｜业务设计与完成路径

版本：业务设计 v1.0 · 2026-09-08。适用读者：业务负责人、物料对接人、审核人及项目实施协作者。

> [!NOTE]
> **业务共识已确认；本文将其转为可审阅的具体设计。**“5 项固定主任务＋逐条策略＋逐份物料”是本轮提出的模板设计，尚未发布为线上模板。文中的目标行为和验收条件不表示相应功能已经实现。现状依据为 2026-09-08 12:02—12:08 的核验及后续本地范围校对。

## 一、项目要实现的结果

营销战役是标准化程度较高的项目推进场景。项目要实现的是：人确定战役名称、负责人和开始时间后，一键获得完整的标准推进事项；AI 依据营销知识准备可供负责人决策的策略；人在策略定案后填写主题节奏与物料内容；系统协助提需、制作流转、终版审核、指定交接与回写，并持续回答进度和生成进行中战役的日、周、月汇报。

这套协同成立，依赖四类能力明确分工：**知识库提供判断依据，多维表格保存正式事实，工作流执行条件明确的动作，专属智能体负责理解、策略准备和协作反馈。**人的决定及实际交付行为，通过提交、定案、审核、交接等明确事件成为系统事实，随后才能被任务汇总和报告使用。

当前最需要补齐的是这条连续业务链的可用性。已有表结构、初始化机制、卡片及局部运行证据，具备复用基础；但尚不足以证明新范围下，专属入口能够从新建一直稳定推进到交付收尾。因此完成度应逐项看“用户结果是否实现、当前运行是否通过、真实证据是否闭合”，不再用表数量、代码数量或旧分项均值给出一个看似精确的百分比。

| 完成后的用户体验 | 可观察的证明 |
| --- | --- |
| 新建不再逐条抄任务 | 三项前置齐全后，生成当前模板的全部主任务、所属战役和依赖；重复点击不多建 |
| 策略能供负责人作决定 | 每条建议讲清情境、用户任务、痛点、SKU 适配、依据和取舍，负责人能够采用或指出修改点 |
| 人填写一次就能推进 | 人工成果提交且必要信息合格后，关联任务自动更新；无需再去任务表重复声明完成 |
| 每份物料都能查到真实去向 | 能区分制作中、哪个版本待审、谁退回、哪个终版通过、是否完成指定交接 |
| 当前战役进度随时可知 | 问答及日、周、月汇报读取同一组正式记录，能指出下一动作、责任、期限和阻塞 |
| 日常使用不依赖开发者代操作 | 使用者通过表格和卡片完成日常动作，失败能看懂并能从已完成处继续 |

**本轮范围**包括标准化新建、策略分析与定案、人工计划与物料输入、物料协作及回写、问答与周期汇报、月度促销识别回填、自动过程总结，以及支撑这些结果的重复处理防护、状态核验与异常恢复。AI 自动生成主题、排期、全文案、设计需求和物料组合退出必做范围；投放执行、私域使用、转化归因、人工复盘、独立资产库及第二业务场景不属于本项目完成条件。

## 二、完整链路：工作推进、过程管理、月度事实

三条线共用同一营销事实源。工作推进形成事实；过程管理解释这些事实并提示行动；月度事实为策略提供当期价格和活动依据。三条线互相支持，但不能相互冒充完成。

**读图顺序：**先看创建前置，再看策略定案这一整场闸门；随后看人工提交与逐份物料推进。物料 A 已准备好即可先制作，物料 B 的输入仍可继续补齐。整场结束时再按完整应交清单汇总，不用最先交付的一份代表全部。

> **业务主线：**三项前置 → 一键生成主任务 → 人提交策略输入 → AI 准备策略 → 人逐条定案 → 全部适用策略通过 → 人提交主题节奏 → 人提交应交清单及各份制作输入 → 分别制作、具体版本终审、指定交接 → 全清单交付完成 → 自动过程总结。

**过程管理线**贯穿进行中的战役，提供即时问答、日／周／月报告和必要提醒。报告不负责另造业务事实，也不负责代替未发生的审核或交接。

**月度事实线**从正式促销来源识别月份、业务线、SKU、价格与活动，校验后回填并回读。它按来源事件运行，不要求先新建战役；更新后的事实可被当前策略引用，已批准策略受到影响时提示负责人处理。

## 三、新标准任务：5 项主任务与两类明细

### （一）为什么这样拆

主任务只表达整场需要交付的阶段结果；策略记录保存每条策略的论证和定案；物料记录保存每份物料的输入、制作、审核和交接事实。这一拆法既让负责人看到完整推进路径，又避免同一物料在任务表和物料表维护两套竞争的状态。

五项主任务是从本次人机分工推导出的建议数量。策略生成和确认合在一个主任务，是因为负责人真正需要的是“本场策略已定案”；逐份制作、审核和交接汇总为一个主任务，是因为整场结果是“物料交付完成”。合并主任务没有省掉里面的业务事件，明细仍能独立查看、退回与推进。

| 主任务 | 主要责任 | 本任务完成的唯一结果 |
| --- | --- | --- |
| T1 提交策略分析输入 | 业务负责人提供事实，智能体检查缺口 | 策略分析所需输入已提交且必要信息齐全 |
| T2 形成并确认本场策略 | AI 准备，业务负责人定案 | 本场适用策略全部完成当前版本确认 |
| T3 提交主题与节奏 | 人工填写者提交，业务负责人对计划负责 | 人工主题节奏已提交且必要信息校验通过 |
| T4 提交应交物料及制作输入 | 业务负责人明确范围，物料对接人组织逐份输入 | 完整应交清单已提交，清单内各份制作输入均已就绪 |
| T5 完成本场物料交付 | 物料对接人组织制作与交接，审核人终审 | 应交清单中每份物料均满足终版、审核、可访问和交接条件 |

新建生成五项主任务及关联，不凭空生成策略内容、物料数量或人工排期。报告、问答、促销同步属于持续能力；自动总结属于系统收尾结果，都不随每次新建复制成固定人工待办。

### （二）T1：提交策略分析输入

**开始条件：**战役及主任务已创建。创建时提供的信息直接复用，不要求再次填写名称、负责人和开始时间。

**建议输入结构：**战役目标；目标用户及已知国家、年级和实际阶段；用户要完成的事情；用户痛点及已有证据；主推 SKU；影响分析的时间、产品或活动限制。国家、月份等按场景提供，不能为了表单齐全要求无关维度必填。若缺少某事实会改变策略方向，应一次列清缺口；未知信息明确保留未知。

**完成信号：**人提交分析输入，系统检查能否支持分析。只填几个字段保留为草稿；已有材料足够时不重复索要。智能体可以整理信息和指出缺口，但不能把自己推测的产品能力补成用户事实。

### （三）T2：形成并确认本场策略

**开始条件：**T1 的必要输入已提交。AI 按可独立决定是否采用的策略单元形成记录，一个战役可以有多条策略。不同策略之间若只有修辞差异，不必机械拆成多条。

每条记录关联情境、用户待办、痛点、SKU、依据、限制及当前版本。业务负责人通过卡片确认、要求修改或明确不采用；退回必须能说明具体修改理由。修改后能辨认变化，并确认新的版本。

**完成信号：**负责人明确本场适用策略集合，其中全部策略的当前版本已确认。未处理草稿不能被 AI 自动忽略；不采用项须保留人的决定。适用集合为空或集合尚未确定时，不允许因“没有未通过项”误判完成。仅部分策略通过，不开放 T3。

### （四）T3：提交主题与节奏

**开始条件：**T2 完成。人填写传播主题、关联策略、时间范围或顺序，以及实际执行所需安排。系统可以校验漏填、时间冲突或关联失效，不替人生成主题及排期。

**完成信号：**负责填写的人一次提交，必要信息合格，系统记录正式提交并完成 T3。已填内容但未提交仍是草稿。提交后发生实质变更，记录新版和影响，不悄悄沿用旧提交去解释新内容。

### （五）T4：提交应交物料及制作输入

人先明确本场要交付哪些成果，再逐份填写内容、需求、规格、关联主题、人工选定的日期与必要制作安排。既有内容或链接直接引用；具体字段按物料类型使用，不要求所有物料套相同内容表单。

**应交清单是查漏依据。**推荐在现有战役范围字段和物料记录中保留“哪些项已纳入范围、范围何时提交、每项关联哪份物料”的关系，具体字段形式在实施规格中落定；本设计不预设新增一张清单表。无论使用何种存储形式，都必须能发现“范围里要求交付，但对应物料尚未建立”的项。

**单份推进信号：**某份物料的人工输入已提交并通过必要校验，即可进入制作。**整场完成信号：**清单范围已明确提交，且其中全部制作输入就绪，T4 才完成。不能用“当前已经创建的物料都填好了”替代这项判断。

> [!IMPORTANT]
> **T4 与 T5 允许重叠。**T4 尚在补齐其他物料时，已就绪的物料可以制作、送审甚至交付。T5 不能配置成“只有 T4 全量完成后才允许开始”；T5 的整场完成则必须等待完整应交清单全部满足。

### （六）T5：完成本场物料交付

每份物料分别经历输入提交、制作、提交具体版本、终审、指定交接。审核人决定版本质量，物料对接人协调修改、定版与交接；系统处理卡片、状态及回写。一个“完成”按钮不能同时代替制作、审核和交接的全部证据。

**单份交付完成**要求：当前确认版本的成果确实存在且可访问、审核通过明确指向这个版本、约定的指定交接已经发生且结果可核对。审核通过可自动推进到待交接；若既有交接动作能同时形成可核验证据，可自动记录，不再增加负责人二次签收。

**整场交付完成**要求：应交清单已正式提交且非空，全部有效应交项均映射到满足上述条件的物料，不存在尚未处理的范围变更或失效确认。取消制作不自动等于完成交付；只有负责人明确调整交付范围，才能将该项移出本场完成判断，并保留变更理由。

## 四、让策略真正可用：输入、依据、推导、定案

### （一）知识分工

| 来源 | 应提供什么 | 不能代替什么 |
| --- | --- | --- |
| 营销知识库 | 不同实际阶段、用户需求、障碍和适用策略；成立条件、例外和使用限制 | 不能代替本场用户事实，也不能证明当期价格 |
| SKU 目录与正式产品资料 | 规范 SKU、业务线、已知能力、适配条件及明确限制 | 不能因主推需要临时创造能力或效果承诺 |
| 月度折扣方案 | 相应月份、业务线和 SKU 的有效价格、活动与适用范围 | 不能自动证明某种策略适合某类用户 |
| 本场输入 | 目标、实际情境、用户待办、痛点、主推 SKU 和现实约束 | 不能把希望得到的结论当作已证实需求 |

营销知识后续由用户补充。建议每个知识条目能说明“适用情境—用户要完成的事—主要障碍—策略及理由—适用产品能力—限制—来源及有效范围”。这是知识准备规范；本文不虚构具体国家、年级、学期或产品的营销规律。

### （二）分析链与质量标准

```text
实际情境 → 用户要完成的事 → 具体障碍与优先级
→ 所需支持 → SKU 已知能力及适配限制
→ 本次价值重点与策略取舍 → 人确认当前版本
```

“美国、大一、九月、考前”应先依据已给定的考前任务分析需求；九月只是背景，不能直接套成统一的开学需求。知识中没有精确匹配时，允许基于已有依据类比，但要说明相似点、差异和待确认假设。若关键产品能力或促销事实缺失，则指出缺口，不把类比延伸成效果或权益承诺。

每条策略应交付六件事：适用情境与需求优先级；依据和推断的区分；SKU 如何提供所需支持及其限制；核心价值主张和选择理由；给人工主题与物料工作的事实口径、重点和禁区；供负责人采用、修改或不采用的明确结论。

**验收看论证和可决策性。**只有人群标签、套话主张或无依据的 SKU 推荐，不算策略可用；长篇文字也不能替代推导。主推 SKU 与需求不匹配时必须指出。依据须能回到真实来源或版本，人工最终确认仍不可被模型自评分替代。

### （三）已批准后发生变化

策略版本改变时，原批准只证明旧版本。系统列出受影响的主题、物料与事实口径，由人处理必要修改，再对受影响结果重新确认；无影响的已完成物料保持原事实。促销方案更新先作为新事实保存并提示影响，不静默重写旧策略、旧审核或历史成果。

## 五、物料与卡片：一次操作形成一个真实结果

继续复用用户已认可的卡片交互。需要优化的是卡片与业务事实、具体版本、责任和下一步之间的对应关系，而不是无故重做全部样式或增加审批层级。

| 人的动作／业务事件 | 系统应该形成的结果 | 不能提前认定的结果 |
| --- | --- | --- |
| 提交主题节奏 | 校验后保存正式提交，更新 T3 | 物料已经制作完成 |
| 提交一份物料输入 | 本份输入就绪，进入既有提需或制作流转 | 全清单输入已齐或本份已交付 |
| 制作方提交终稿 | 记录确切版本，给审核人当前版本审核入口 | 附件存在即质量通过 |
| 审核人退回 | 保存理由，回到修改，后续新版本重新送审 | 旧卡仍可通过新版本 |
| 审核人通过 | 当前具体版本通过，推进指定交接 | 没有交接证据也算交付 |
| 约定交接实际完成 | 回写本份交付事实，更新整场汇总 | 其他未交物料也完成 |
| 同一动作再次点击 | 返回已有结果或提示状态已变化 | 重复建记录、重复推进或覆盖新状态 |

卡片最少让使用者看清：哪场战役、哪份物料或策略、当前版本及状态、现在需要谁做什么、成果或记录入口、动作后的结果。制作输入不足时具体指出缺项；退回后展示可执行的修改意见；完成后的旧卡不再提供有效修改动作。

**只有正式记录回读一致才报告写入成功。**如果表格已更新但卡片反馈失败，应补反馈；不能整条流程重跑。若写入结果不明，先查询该对象是否已变更，再补未完成部分。错误应定位到对象与下一步，而不是向非技术使用者暴露程序日志。

业务负责人负责目标、策略、交付范围及重大变更；物料对接人负责制作组织、反馈、终稿和指定交接；审核人负责具体终版质量。实际制作人员沿用已有制作协作安排，不额外增加一层管理角色。创建前必填负责人不扩展为三角色均必填；某个动作需要谁负责，就在动作发生前核验相应人员是否明确。

## 六、一键新建、排期与战役状态

**创建入口建议：**在战役表单或战役记录中填写名称、人工选定的负责人和开始时间，点击“生成标准任务”。缺任一项时保留已填内容并提示缺项；齐全后生成当前采用版本的主任务和关系。日期由人决定，系统不按开始时间擅自推算工期。

任务级责任和日期建议集中放在该战役的“初始安排”工作面，由人逐项选定，已有明确值直接沿用。系统不把战役负责人无条件填成所有任务执行人。此工作面是推荐交互，具体使用现有视图、表单还是卡片，由实施核验选择最简单可用的方式。创建的三项前置不追加为“所有任务负责人和所有截止日期必须提前填齐”。

未填写截止日期的事项显示“未排期”，不算逾期；人改期后按新日期判断提醒，保留必要变更信息。逾期表示时间偏差，不自动改成业务“阻塞”，更不能改变真实制作或审核状态。

**战役创建成功与进入进行中分开。**新建只证明任务已建立；推荐沿用战役正式状态作为启动依据，由有权人标明进行中，再纳入周期汇报。具体映射到现有哪个状态值在实施前核对，不用最近创建、开始时间已到或最近修改代替正式状态。

整场交付完成后进入业务结束状态，停止该场周期汇报。自动总结独立显示生成中、成功或待重试；生成失败不倒退已成立的交付事实。暂时没有应交物料、策略全不采用或战役被取消时，不走自动“成功交付”，应保留真实的未完成或取消原因。

## 七、问答与日／周／月汇报

### （一）统一汇报对象与事实口径

默认只处理正式状态为进行中的战役。通常只有一场；没有进行中战役时不周期性空发，主动问询时说明当前没有进行中战役。偶有多场时分别列清，不能静默选择最近一场，也不新增“系统只允许一场”的限制。

一个回答至少能说明：当前推进到哪里，已经完成什么，尚未完成什么，下一动作、责任人和人工期限是什么，卡在哪个决策或缺口，信息更新到何时。没有记录时说明未知；未填日期不能被算成按期，读取失败不能回答整体正常。

| 能力 | 应帮助人判断什么 | 主要输出 |
| --- | --- | --- |
| 即时问答 | 现在的真实进度与下一步 | 指定战役／策略／物料的当前结果、待办、责任、期限、阻塞和记录入口 |
| 日报 | 今天及临近节点需要处理什么 | 当天已发生变化、待处理审核、临近交付、阻塞与所需行动 |
| 周报 | 本周推进相对安排有什么偏差 | 本周里程碑、计划与实际、延期、待决策、下一阶段动作 |
| 月报 | 当前进行中战役本月推进得怎样 | 本月完成与遗留、过程问题、范围或排期变化、当前待决策 |
| 带教总项目汇报的营销板块 | 营销作为整体项目之一处于什么状态 | 战役名称、阶段、关键结果、主要风险、待决策与更新时间 |

日报、周报、月报都围绕进行中战役。月报不等于本月所有已结束战役的历史复盘；月度促销同步也不等于月报。精确发送时间、时区、接收对象及无新增进展时的展示方式，在调度配置前一次落实，不自行新增发送安排。

### （二）进度怎样表达才不误导

推荐先展示阶段结果，再展示两类数量：已定案适用策略／全部适用策略；已交付物料／全部有效应交物料。五项主任务的完成数量可作辅助，但五项工作量并不相等，不能把“完成四项”解释成“营销完成 80%”。不同大小物料的数量占比也不代表工作量或营销效果。

报告中的每个数字应与相同战役、相同截止时点和相同清单范围一致。范围变更引起分母变化时说明原因；部分数据读取失败时标明缺口，已有可确认事实仍可输出，不能填补猜测。

### （三）提醒控制

任务与物料的临期、逾期和待处理事项由一个明确执行方负责，避免云端流程与本地监控重复催办。提醒要带真实对象、责任、日期、下一动作与有效入口；完成、取消或风险解除后停止相应提醒。同一周期重试只补失败结果，不重复发成功报告。

## 八、月度促销识别回填

这条链解决“正式促销事实怎样准确进入表格”，不承担策略创造。它与主流程解耦，但为策略提供可核对的当期事实。

```text
正式来源消息 → 识别月份、业务线与 SKU
→ 提取价格／新签活动／续费活动 → 整批预校验
→ 新增或更正指定记录 → 逐字段回读 → 原消息话题内一条固定文字回执
```

继续以现有“月份 × 业务线 × SKU”为记录定位原则，四类正式字段为试听价格、正价价格、新签活动、续费活动。只处理本次来源明确出现的业务线和 SKU；不因消息未提及就清空其他记录。对符合既有结构和必填校验的 SKU 方案，价格不适用时留空；未提供的新签活动或续费活动按既有协议写字面值“无”，不沿用旧活动，也不额外要求来源声明“确实无活动”。若已有正文却无法确定字段归属、内容解析失败或必要信息缺失，则按预校验失败处理，不能把解析失败当成正常省略。

来源明确、必要字段符合上述规则且整批预校验通过时，按现有直写回填路径处理，不增加写入前预览确认。月份、SKU、字段归属或更正意图存在歧义，均不得猜测写入。任一预校验失败，本批业务记录及 AI 执行记录均为零写入；具体缺口和排错信息只保留在本地维护证据，不追加到群回执。

对外通过 `reply-in-thread` 进入原促销方案消息的“1 条回复”话题，只发送一条固定 Markdown 文字：全部写入且逐字段回读一致时为“月度促销方案同步成功 | 营销战役表”；预校验、执行或回读任一失败时为“月度促销方案同步失败 | 营销战役表”。其中“营销战役表”须为指向当前营销 Base 的蓝色可点击链接。不发卡片，不追加新增、更正或失败明细，不发额外总结；同一来源消息 ID 重投不再次执行写入，也不回复第二条文字。

执行或回读中出现网络异常、部分成功或结果不明时，不伪装成整批成功，也不盲目自动回滚或重放。维护者先逐条查询正式记录，核对已成功项、未完成项和原授权范围，再按既定恢复机制及明确授权处理未完成部分；不能因收到重复消息就自动重跑整批。恢复依据与结果保留在本地维护证据，不追加第二条话题回执。月促销更新影响已定案策略时，在营销协作记录中标明影响对象，由人决定是否改策略；同步事实不等于批准新的营销承诺。

用户报告该链已修复，本地也存在识别、回填及真实包装入口预检证据。因此不能继续沿用旧失败结论；但截至已保存核验，尚缺修复后同一真实消息到正式字段回读的完整证据，仍需单独验收。

## 九、专属智能体与带教机器人的承接边界

| 协作主体 | 目标责任 | 与营销事实的关系 |
| --- | --- | --- |
| 营销专属多维表格智能体 | 策略准备、问答、报告、卡片协作和促销识别 | 读取同一 Base 与知识，调用经核验的业务动作 |
| 确定性工作流／执行器 | 前置校验、建任务、状态流转、回写、回读、去重与恢复 | 对明确条件执行动作，保存真实结果 |
| 人 | 选定责任和日期、提供事实、填写计划与内容、定案、审核及交接 | 对判断和实际业务行为负责 |
| 机械邪龙兽带教机器人 | 带教与整体项目汇报 | 按需要引用营销事实与摘要，不再承担营销日常执行 |

营销专属智能体是面向业务的协作入口，底层确定性动作可以复用已有实现。能否直接承接定时执行、附件处理和卡片回调，必须按实际平台能力逐项验证；不能因为入口名称叫“多维表格智能体”就假设所有动作已具备，也不能因为本地没找到完整证据就断言该智能体不存在。

入口迁移顺序应是：核验目标专属入口及可调用动作 → 打通受控样本 → 核验同一事件只有一个执行责任方 → 处理在途事项 → 切换正式营销承接 → 确认新入口稳定后退出机械邪龙兽营销执行。机器人退出执行不等于删除 Base、历史任务、已交付成果或审计证据。

Codex 操作飞书资源仍使用既定 codex 应用身份；产品层的专属智能体分工不自动改变 Codex 的应用绑定。真实消息和卡片外发、正式入口切换按各自明确授权执行；文档设计本身不冒充已经迁移。

## 十一、实施路径：每一步以可观察结果结束

| 阶段 | 本阶段交付 | 通过条件 |
| --- | --- | --- |
| 1 固定设计与承接责任 | 本设计定稿、实际字段映射、新模板版本方案、专属入口能力清单 | 每个动作有唯一执行方；任务和完成条件清楚；真实缺口与产品决定分开 |
| 2 跑通标准化新建 | 三项校验、五项主任务、依赖、人工安排入口、异常恢复 | 缺项不生成，齐全正确生成，重复不多建，日期不被 AI 编造 |
| 3 跑通策略到人工提交 | 真实知识读取、策略输出与定案、主题提交、应交清单及逐份输入 | 全部适用策略确认才能放行；人工一次提交即可更新关联结果 |
| 4 跑通逐份物料交付 | 提需、制作、具体版本终审、指定交接、全清单汇总及自动总结 | 局部就绪可先行，漏项不收口，退回与重试正确，交付事实可信 |
| 5 补齐持续管理 | 即时问答、日／周／月报告、有效提醒、月度促销回填 | 均读取同一事实；范围和数字正确；定时去重；同一促销来源回读闭合 |
| 6 完成专属入口与独立使用验收 | 正式承接、旧营销执行退出、操作说明、异常接管与恢复证据 | 同一代表性战役从新建到交付由非技术使用者在正式入口连续完成 |

专属入口能力探明必须在第一阶段完成，逐段联调贯穿后续工作，不能留到全部代码写完才发现平台不支持所需动作。最后阶段完成正式切换和使用验收，不代表此前所有测试都继续依赖旧机器人。

实施采用最小闭环逐段完成。先证明一个动作从入口到正式表格和结果反馈真实成立，再连接下一段；不先大改所有表、恢复所有旧流程或增加大批字段。已通过且不受变更影响的历史行为可以复用证据，受影响部分按同一候选版本重新验证。

**知识依赖需要独立管理。**结构、状态和动作可以先施工；专业策略质量的最终验收必须有用户提供或确认的营销知识与 SKU 事实。示例知识仅能用于测试检索和缺口处理，不能用合成策略宣称正式业务质量通过。

| A13 自动收尾失败 | 全部物料真实交付后，总结生成失败再重试 | 交付事实保持成立，总结状态可见且可补生成 |
