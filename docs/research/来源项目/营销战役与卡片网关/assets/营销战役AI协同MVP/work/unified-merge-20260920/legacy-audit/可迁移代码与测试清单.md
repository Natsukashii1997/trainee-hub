# 可迁移代码与测试清单

本清单用于新统一底座施工取件。所有条目都只表示“可迁移逻辑”，不表示可以复制原文件后直接运行。

## 1. 月度折扣同步

### 可迁移函数

| 文件 | 函数/类 | 迁移价值 | 改造要求 |
|---|---|---|---|
| `v4_runtime.py` | `looks_like_monthly_strategy_sync`、`parse_monthly_strategy_sync` | 识别结构化月度方案、归一化月份与业务字段 | 去除旧群路由、旧 SKU 别名和旧表字段绑定 |

| `v4_runtime.py` | `Engine._monthly_discount_fields` | 生成价格、活动、同步人、来源消息字段 | 全部字段 ID 重新绑定 |

## 4. 初始化、幂等、回读与执行记录

### 可迁移文件

| 文件 | 核心职责 | 改造要求 |
|---|---|---|
| `task_initialization_orchestrator.py` | 增量补任务、补关系、Release 漂移拦截、最终权威回读 | 新模板/项目/任务字段重绑 |
| `task_initialization_operation_ledger.py` | 业务键、租约、执行结果复用、需补偿状态 | 删除硬编码旧 Base/战役表；新 SQLite 从空库开始 |
| `task_initialization_recovery.py` | 只读恢复预检、plan hash、事实变化后拒绝旧计划 | 新网关与新 Release 坐标 |
| `task_initialization_poller.py` | 有界、串行的候选发现与初始化 | 绑定新 `工作项目`，禁止与旧轮询器并行 |
| `v4_runtime.py` | `RuntimeStore.begin_event/complete_event/mark_business_completed/mark_card_update_pending` | 抽成统一事件运行库 |
| `v4_runtime.py` | `Engine._log_once`、`Engine._safe_log` | 绑定统一执行记录表；日志失败不能重做业务动作 |

### 关键测试

- `test_task_initialization_orchestrator.py`：重复执行零新增、部分补偿、Release/模板漂移、关系回读失败不完成；
- `test_task_initialization_operation_ledger.py`：同业务键单租约、持久复用、过期接管、错误脱敏；
- `test_task_initialization_recovery.py`：只读预检、stale plan hash、显式 apply、只有回读通过才成功；
- `test_task_initialization_poller.py`：稳定 operation ID、空候选零动作、有界串行、单项失败不阻塞其他项；
- `test_v4_runtime.py::TestAuditLog`：最小执行记录字段。

## 5. 必须删除或重绑的旧耦合

### 旧 Base 与字段坐标

- `config.json`：旧 Base token、九表 ID、所有 field/view/role ID、旧 chat_id；
- `v4_runtime.py` 顶层 `DEFAULT_TABLES`/字段常量与 Settings 默认值；
- `task_initialization_base_gateway.py`：旧 Base、战役表、任务表和字段合约；
- `task_initialization_operation_ledger.py`：业务键中硬编码的旧 Base/战役表；
- `strategy_flow.py`、`human_submission_flow.py`：旧 campaign/strategy/task/theme/material 表常量；
- `human_submission_workflow_install.py`：旧 Workflow 目标表和日志表。

### 旧独立项目模型

- `config.json.scene_identity.mode=exclusive_in_target_chat`；
- `AGENTS.md` 中“数码宝贝世界”专属身份、非营销请求拒绝和独立事实域规则；
- 独立营销周报 LaunchAgent 与旧四表报告入口；
- 旧月度专属群作为唯一授权入口的规则；
- `service.py`、`intake.py`、`group_scene_actions.py` 等旧 V3/独立 listener；
- `delivery_contract.py` 及任何“审核通过即完成”的旧物料状态机；
- 旧 SQLite、旧卡片消息、旧 pending/retryable 事件和旧 UAT 数据。

### 不可直接部署

- `.52`、`.53` release 包均绑定旧 Base 和旧场景；
- 最新源码候选 `final_accepted=false`、`production_ready=false`；
- 新底座必须重新生成字段绑定、运行清单和从空状态开始的运行库。
