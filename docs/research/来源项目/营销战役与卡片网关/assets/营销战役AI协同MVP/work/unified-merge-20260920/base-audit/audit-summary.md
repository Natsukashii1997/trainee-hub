1. `营销战役推进`目前只存在于`标准项目模版`目录，是 17 行任务模板；`营销战役策划`目录中没有独立的运行表，`工作项目`中也没有营销项目实例。

因此，当前 Base 层可评价为：**统一项目底座可复用，营销模板已录入，营销运行对象和物料闭环尚未建成。**

### 4.3 产品模板的复用证据与风险

AI 动作记录中有 7 条项目标准化启动事件（其中 6 条普通启动、1 条直接完成），成功记录显示曾按产品模板生成 45 条任务（17 个一级任务、28 个子任务）。这证明外部机器人初始化链路存在并可作为营销模板展开的参考。

但`产品项目推进`表的 45 条模板记录已全部关联项目 `T1 需求诊断、方案生成与提需一体化`，且已写主责任人。它不再是完全中性的模板数据。继续沿用时应明确模板事实源与运行实例分离，否则真实项目修改会污染后续初始化。

## 七、SKU 与月度折扣

### 产品SKU目录

7 条 SKU 均为“使用中”，字段包括：SKU名称、业务线、产品类别、别名/关键词、SKU状态、月度折扣方案。

问题：`月度折扣方案`是普通文本，仅存`08,09`一类月份串。对同时属于两条业务线的`灵活学Lite`，目录值为`08,08,09,09`，无法从目录侧区分业务线与对应折扣记录。

### 月度折扣方案

15 条正式记录：8 月 8 条、9 月 7 条；字段包括填写日期、月份公式、业务线、SKU名称、新签活动、续费活动、试听价格、正价价格、确认人、数据环境。

已具备按“月份 + 业务线 + SKU”存储正式方案的基础，但仍缺少：与 SKU 目录的 Link、来源/同步批次、原始文件或消息引用、同步时间、幂等键、回读状态。当前 SKU 使用 Select 而不是 Link，月度同步只能依赖文本匹配，名称变更会产生漂移风险。

## 八、日报/周报、卡片与工作流

- Base 中没有“项目日报”或“项目周报”表，也没有相应字段或原生 Workflow。
- AI 动作记录中没有匹配“日报/周报/营销/物料/折扣”的事件记录。
- 工作项目与任务事项已有生成统一项目报告所需的基础数据：推进中项目、负责人、任务完成度、未完成/逾期任务、日期和交付物。
- 因此营销战役无需另建一套日报/周报模型；只要实例化为`工作项目`记录并把 17 条营销任务写入`任务事项`，现有项目报告逻辑可把它作为普通项目纳入。
- 卡片交互不应被描述为 Base 按钮绑定：本 Base 相关表没有按钮字段，原生 Workflow 为 0。卡片发送、按钮回调、权限判断、状态更新、写后回读和消息更新必须由机械邪龙兽外部运行层实现，并复用`AI动作记录`做幂等与审计。

## 九、实施优先级（供主任务承接）

### P0：主流程阻断

1. 定义营销项目实例化规则：在`工作项目`建 1 条营销项目，在`任务事项`生成 17 条实例任务；不要把模板记录直接当运行任务。
2. 给工作项目建立可靠的项目类型/模板标识，并纠正营销反向关联字段的错误名称。
3. 将`内容物料`从空壳补成可运行状态机，随后接机械邪龙兽卡片回调和写后回读。
4. 让机械邪龙兽统一使用新 Base 的表/字段坐标；当前 Base 内没有原生 Workflow 可直接接管。

### P1：口径与稳定性

1. 月折扣表的 SKU 改为或补充 Link→SKU目录，以 Lookup 取代目录中的月份文本串。
2. 清理任务表空白记录并修正`任务数量`口径；复核完成度分母。
3. 将产品模板从真实项目关联中剥离或冻结模板版本，避免模板污染。
4. 为外部动作统一设置幂等键、数据环境、回读状态和真实操作者留痕；现有`AI动作记录`字段可复用。

### P2：使用体验

1. 给营销模板增加结构/顺序字段或稳定模板序号，保证展开顺序不依赖记录返回顺序。
2. 增加营销项目与内容物料的业务视图：进行中战役、待提交、待制作、待审核、待交接、待验收、已完成。
3. 修正`任务状态看板`名称或分组配置，使视图语义一致。
