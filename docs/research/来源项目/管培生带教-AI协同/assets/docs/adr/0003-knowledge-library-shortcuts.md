# ADR 0003：知识入库以原知识库归档为结果

日期：2026-09-09。状态：用户再次明确边界，单份 Wiki 归位已验；后续直接进入多入口接入。

## 当前有效要求

用户所说的知识入库，重点是在现有管培生知识库中整理资料。外部文档添加快捷方式，保持原文及原维护位置。多维表格中的入库动作记录不是必选项，本次不接该表，不强制新建整理稿或方案文档。

用户可观察结果：在测试群提交资料，看到原文入口、推荐的完整栏目路径、标题和归类理由；常浩批准该版方案后，在管培库对应位置看到快捷方式并收到可打开的库内链接。

## 当前切片

1. 仅常浩在测试群明确提交单份外部 Wiki 文档；正文和引用内容不能触发入库命令。
2. 读取资料和实际目录，选择管培库内一个原生父节点；审核卡直接展示方案。
3. 支持批准、修改位置和取消。修改位置或相关资料、目标发生变化后重新审核；旧卡不能批准新方案。
4. 只添加快捷方式，不复制或改写外部原文，不移动来源，不扩展库外权限。
5. 后台保存提交、精确方案、审核关联及写入回执，用于防重和失败恢复；不写知识入库 Base 表。
6. 创建前检查同源重复和目标仍在管培库；未知结果先查回，不盲目重建。创建后查回来源、标题、父节点、空间与可读链接，全部吻合才报告完成。

正式目标空间固定为 `7672588453183261977`。常浩的管理员授权不替代对每份具体位置和方案的批准。

## 语义与后续范围

快捷方式入库表示组织归档通过，不表示原文全部事实已审定、正文永久冻结或所有成员自动有权读原文。机器人正常回答沿用现有设置，不新增整库“已审事实”标记。

用户再次明确“知识入库而已，知道他放到知识库哪里就可以了”。库内正文补充、新建、改写、事实审查、冲突治理及有效知识索引改造均不属于当前知识入库要求；此前把内容加工列为整体必做目标是代理误扩范围，现撤销。T1 修改候选停止，不交用户审核或发布。其他文件类型、附件或多份资料未验，不暗中复制正文，不以未实现正文加工阻塞下一环节。问答答案审核及归档流程保持独立有效。
