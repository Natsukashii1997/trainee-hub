## 日常使用只需四步

| 步骤 | 常浩怎么做 | 应看到的结果 |
|---|---|---|
| 1．正常提问 | 在测试群输入 `@`，从飞书候选列表选中机械邪龙兽，再提出问题 | 收到机器人正常回答；日常问答表随后留下本次问题与回答，群内出现答案审核卡 |
| 2．审核回答 | 点卡片上的「查看完整问答」，阅读全文后选择通过或修改方式 | 通过后进入保存确认；按原则改稿会形成新版，仍需再次审核 |
| 3．确认保存 | 在归档审核卡中核对完整问答及保存位置《管培生带教问答集》，点击「确认本方案入库」 | 卡片先显示「已确认，等待写入核验」；实际保存并核对成功后显示「已完成入库核验」 |
| 4．阅读和复用 | 点击「打开问答集」，或使用下方固定链接 | 已确认保存的问题与最终回答持续累积在同一份文档；篇幅较长时可用飞书文档内搜索查找问题 |

只打出机器人名字不算实际 @。审核卡中的正文可能是摘要，确认前请点「查看完整问答」读全文；待审全文位于《待审核问答》。**「答案已审核通过」和「问答已保存」是两个步骤**，通过答案后仍需处理随后出现的归档审核卡。

## 审核卡按钮怎么选

| 按钮 | 适合什么情况 | 需要填写什么、之后会怎样 |
|---|---|---|
| 通过本版 | 当前完整回答可以接受 | 可以不填意见；之后另行确认保存 |
| 以导师定稿替换 | 你已经写好完整最终答案 | 填入完整定稿，按原文替换；这份导师定稿直接视为已审核通过，不再要求你重复审核同一份定稿 |
| 按原则改稿 | 你想给修改方向，让机器人重新组织回答 | 填写修改原则；机器人生成新版本后发新审核卡，等待你再次审核 |
| 退回重答 | 当前回答不能接受，需要重新回答 | 填写退回理由；旧版会标为已否决，后续以最新审核卡为准 |
| 确认本方案入库 | 归档卡中的完整问答和保存位置都正确 | 可以不填意见；确认后才执行保存，完成状态以查回结果为准 |
| 退回归档方案 | 展示的归档内容或保存位置不正确 | 填写具体意见，先退回本方案；不要把退回当作已经保存 |

每张卡只对应当时展示的回答或保存方案。修改后使用最新卡片，已结束的旧卡无需再点。纠正回答会回到原问题所在位置，并说明替代的旧答案；这些必要提醒保留在聊天中，问答集正文仍只呈现问题与最终回答。

## 超过 1000 字的导师定稿

卡片输入框每次最多 1000 字。完整定稿超过 1000 字时，不要删减后提交，使用回复消息入口：

1. 在飞书中**回复当前待审的答案审核卡**。
2. 首行写 `@机械邪龙兽 定稿`，其中 @ 必须从飞书候选列表选中机器人。
3. 从下一行开始粘贴完整最终答案，以纯文本发送。

正文的空白和换行按原文保留。这次提交代表你的最终定稿，会直接作为已审答案替换原回答；之后仍会单独确认保存。当前不支持用附件或文档链接代替定稿正文。

如果全文超过消息接收限制，系统会保留待审状态，不截断后冒充完整定稿。请保留原稿，让 Codex 核对；不要自行拆成多条定稿提交。该长消息入口的真实验证进度，以阶段状态为准。Codex 不代替常浩点击导师审核按钮。

## 遇到问题怎么处理

| 看到的情况 | 常浩怎么做 |
|---|---|
| 已收到普通答案，但没有日常表记录或审核卡 | 保留原消息交给 Codex 查回，不连续重发同一问题 |
| 卡片和全文内容不一致，或全文打不开 | 暂停这条审核，把对应卡片或链接交给 Codex 核对 |
| 点了「按原则改稿」后迟迟没有新版 | 保留原卡和修改原则，让 Codex 查回处理状态，不连续重复点击 |
| 答案已通过，但问答集里找不到 | 先看是否还有归档审核卡待确认；如果已显示保存完成仍找不到，把对应卡片交给 Codex |
| 一直显示等待写入、失败或待核验 | 保留现状，让 Codex 核对实际保存结果，不重新归档或删除原记录 |
| 旧卡显示已否决、已结束或已被替代 | 使用最新卡片，不反复点击旧卡 |
| 长定稿未提交成功或提示太长 | 保留完整原稿和提示交给 Codex，不删减、不拆分后连续提交 |
| 电脑睡眠、关机、断网或服务停止 | 让 Codex 检查并恢复，核对原问答后再继续 |

当前服务由这台 Mac 承载，使用时需保持电脑在线；休眠和断网期间不保证持续处理。常浩无需保持终端打开。部署、日志和恢复由 Codex 负责，不需要自行重新启动处理程序。

## 可选的本地检查

需要检查时，可以双击同目录的[本地自检.command](本地自检.command)。当前 Mac 已有 Python 3 和 Node.js，无需另行安装。看到「本地自检通过」表示本地检查成功；它不会发送飞书业务消息，也不能替代真实问答、审核和保存的验收。

如果双击无法运行、提示缺少软件或检查失败，直接把提示交给 Codex，无需自行编辑代码或处理报错。不要删除项目中的运行数据或重复启动服务。后续实施和待验事项统一查看[阶段状态](阶段状态.md)最上方，避免按历史记录重复操作。
