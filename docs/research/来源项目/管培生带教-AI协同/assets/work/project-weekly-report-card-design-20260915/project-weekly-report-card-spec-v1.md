# 项目周报交互卡片｜内容与交互规格 v1

## 1. 目标

让常浩在一张卡片中快速回答五个问题：本周整体推进得怎样、每个项目到哪里了、本周具体完成了什么、下周最需要关注什么、当前数据是否足以支持判断。

周报是基于多维表格生成的事实报告，不承担审批。卡片不设置“确认”“通过”或“已阅”按钮；需要追查或修正时，直接进入工作项目表或任务事项表。

## 2. 报告周期

- 推荐口径：上一自然周，周一 00:00 至周日 23:59，时区 Asia/Shanghai。
- 卡片必须同时显示报告周期和数据读取时点。
- 具体定时发送时刻仍保持待确认；本规格不提前设置自动发送时间。
- 第二期开始如需显示“较上周 +X%”，必须保存上期报告快照后计算；没有上期快照时不生成环比，不用当前值倒推。

## 3. 卡片内容结构

### 3.1 头部结论

- 类型：项目推进周报。
- 标题：`项目周报 | M月D日—M月D日`。
- 一句话摘要：只组合可验证事实，例如“本周完成 4 项，当前无逾期；T2 有 4 项任务将在 3 天内到期”。
- 状态标签：
  - 有未完成逾期任务：红色“有逾期”。
  - 无逾期，但有 3 天内到期任务、7 天内里程碑或影响判断的数据缺口：橙色“需关注”。
  - 上述情况均无：绿色“推进正常”。

### 3.2 总览指标

固定四项，顺序保持一致：

1. 推进中项目：工作项目中状态为“推进中”的项目数。
2. 总体完成度：纳入报告项目的已完成有效任务数 ÷ 有效任务总数，使用加权总数，不取各项目百分比的简单平均。
3. 本周完成：`是否完成=true` 且“实际完成时间”落在报告周期内的任务数。
4. 当前逾期：“逾期状态=进行中·已逾期”的任务数；已完成但历史上逾期的“已逾期”不计入当前风险。

指标下补充“已完成数 / 有效任务数”，让百分比可核验。

### 3.3 项目进展

每个推进中项目显示一行：

- 项目名称与当前状态。
- 完成进度条和“已完成 / 总任务”数。
- 本周完成任务数。
- 最近一个未完成里程碑及日期。
- 项目总负责人只在需要区分时显示；任务级责任人放在具体事项中。

排序优先级为：有逾期项目 → 有临近节点项目 → 其余项目；同级按最近截止时间排序。

### 3.4 本周完成

- 按项目分组，列出本周实际完成的任务名称、主责任人和实际完成日期。
- 同一项目同一天的短任务可合并为一行，避免卡片被过程事项淹没。
- 最多展示 4 行；更多内容显示“另有 N 项”，通过任务事项按钮查看。
- 没有实际完成时间的勾选任务不计入本周完成，并进入数据提示。

### 3.5 下周重点

- 纳入未完成且开始时间或截止时间落在下一个自然周的任务。
- 优先展示：里程碑 → 审核门禁 → 截止时间最近的普通任务。
- 每行显示所属项目、任务名称、主责任人和截止日期。
- 卡片最多展示 4 行，其余以“另有 N 项已排期”汇总。
- 项目下周没有明确排期时如实显示“暂无明确到期任务”，不由 AI 补写计划。

### 3.6 风险与数据提示

风险只使用结构化事实：

- 当前逾期：来自“逾期状态=进行中·已逾期”。
- 临近里程碑：节点类型包含“里程碑”、任务未完成且截止日在未来 7 天内。
- 临近截止：普通任务或审核门禁未完成且 3 天内到期。
- 数据陈旧：工作项目“最后更新时间”早于报告周期结束，或关键任务字段长期未更新。
- 数据不完整：缺任务名称、所属项目、主责任人、开始／截止时间、节点类型，或项目关联任务数与任务表查回数不一致。

数据问题与业务风险分开呈现，避免把“没填数据”写成“项目一定有风险”。

### 3.7 操作与页脚

- 主按钮：查看项目推进管理，打开工作项目表“按项目查看”。
- 次按钮：查看任务事项，打开任务事项表“按项目查看”。
- 页脚：报告周期、数据读取时点、接收人常浩。
- 不增加输入框、审批按钮或“已阅”按钮。

## 4. 多维表格字段映射

| 卡片信息 | 来源表 | 字段 |
| --- | --- | --- |
| 项目名称、状态、总负责人 | 工作项目 | 项目名称、状态、总负责人 |
| 项目完成度、任务总数 | 工作项目 | 任务完成度、任务数量、对应任务 |
| 数据新鲜度 | 工作项目 | 最后更新时间 |
| 项目级时间判断 | 工作项目 | 项目创建时间、项目截止时间 |
| 本周完成 | 任务事项 | 是否完成、实际完成时间、任务事项 |
| 下周计划 | 任务事项 | 开始时间、截止时间、是否完成 |
| 逾期风险 | 任务事项 | 逾期状态 |
| 里程碑与审核门禁 | 任务事项 | 节点类型 |
| 阶段位置 | 任务事项 | 环节阶段 |
| 责任人 | 任务事项 → 团队成员 | 主责任人 → 成员名／账号 |
| 交付物入口 | 任务事项 | 交付物 |

## 5. 当前数据快照示例

读取时点为 2026-09-15，工作项目 rev 314、任务事项 rev 1403、团队成员 rev 340，完整分页均为 `has_more=false`。

- 推进中项目：2 个。
- 项目汇总有效任务：109 项，已完成 72 项，总体完成度约 66%。
- 2026/09/08—09/14 实际完成：4 项。
- 当前进行中逾期：0 项。
- 未来 3 天内到期：4 项，均属于 T2。
- T1：35/46，约 76%；最近未完成里程碑为 10 月 8 日“开发阶段完成”。
- T2：37/63，约 59%；最近未完成里程碑为 9 月 27 日“开发阶段完成”。
- 两个项目均未填写项目截止时间。
- T2 在任务事项表中查到 64 条关联记录，但工作项目汇总为 63 条；多出的 1 条为空白任务记录，缺任务名称、负责人、排期、阶段和节点类型。卡片按项目汇总显示 63 条，并单独提示数据差异。

## 6. 卡片容量与异常边界

- 当前 2 个项目使用单卡即可。
- 推进中项目不超过 4 个时全部展示；超过 4 个时使用“总览卡 + 项目明细卡”，有逾期或临近里程碑的项目不得被折叠。
- 外部读取失败或分页不完整时不发送看似完整的周报，应显示“数据读取不完整，本期周报未生成”。
- 项目表保持只读；生成周报不修改状态、时间、负责人或完成情况。
- 周报只发送一次，不同时附发内容重复的普通文本消息。
