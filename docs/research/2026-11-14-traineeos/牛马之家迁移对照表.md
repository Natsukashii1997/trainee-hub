常浩 2026-11-14 定：牛马之家（niuma-home，常浩的个人工作台，本机常驻 5280）现有的带教模块迁入本工作台，管培生带教统一在一个工作台。本表逐项写清迁什么、怎么改造、不迁什么，是 PRD v2.1 第 17 节 D、F 阶段的依据。

- 依据（只读核对，2026-11-14）：牛马之家 `REQUIREMENTS.md`「带教」一行、`docs/项目推进与管培带教-需求草案.md`、`docs/API.md`「带教 · 培养路径」与 mentor 接口、`docs/培养路径/`、`docs/亚古兽/角色配置-V3/HERMES.md`。

## 2. 数据迁移

| 数据 | 来源 | 目标 | 怎么核对 |
|---|---|---|---|
| 方案模板 V2.4 | 牛马之家 `server/mentor-plans.mjs`、`docs/培养路径/管培生培养路径.md` | `path_template` / `stage` / `task_template`（加类型、线、评审方式） | 段数、工作日数、评审点数、合格线逐项相等 |
| 各人路径与调整 | 牛马之家本地 `v3_documents`（kind `mentor-path`） | `personal_path` / `task_instance`（计划起止）+ `deadline_change` | 每人每段的计划起止、调整次数相等 |
| 评审分数与结论、带教确认完成记录 | 同上（各段的进度记录） | `review`（按评审方式）+ 事件日志（来源记「导入」） | 每人已完成段数、各评审点分数相等 |
| 答疑记录 | 牛马之家 mentor 回复记录 + 多维表格「问答记录反写」 | `qa_record` | 条数按「有效提问」对账；重复标题、占位记录先列清单给常浩判断，不自动删 |
| 项目与任务事项 | 多维表格「AI管培工作台」 | `project`、`milestone` | 项目数、里程碑数；缺失字段如实留空，不自动补目标或截止 |
| 日志链接 | 牛马之家设置 | `user` 的日志链接 | 人数相等 |

导入一律先预览、再确认、导入后回读对账；导入事件来源记「导入」。

## 3. 状态合并

| 牛马之家 / 多维表格 | 本工作台 |
|---|---|
| 答案审核：待生成 / 待审核 / 待改稿 / 已通过 / 已否决 | 答疑记录 · 答案：待起草 / 待审核 / 需改稿 / 已通过 / 已否决 |
| 归档审核：未提议 / 待确认 / 已批准 / 已否决 | 答疑记录 · 归档：未提议 / 待确认 / 已收录 / 不收录 |
| 实际写入：未开始 / 执行中 / 待核验 / 失败 / 已查回确认 | 答疑记录 · 送达：未发送 / 已发送待核对 / 已核对 / 失败（由亚古兽的回执写入） |

三组状态分开存，任何一组都不能推出另一组（例如「已通过」不等于「已送达」）。

## 4. 切换步骤（F 阶段）

1. 本工作台完成 D、E 阶段，部署可用。
2. 冻结牛马之家带教模块的写入（常浩停止在那边操作）。
3. 导入第 2 节全部数据，逐项对账。
4. 亚古兽改接本工作台的机器人接口（在牛马之家与亚古兽各自的项目里改）。
5. 常浩在本工作台完成一轮真实带教动作：调一次安排、记一次评审、审一条答疑。
6. 通过后牛马之家带教模块改只读，过一段时间下线（在牛马之家仓库另开会话做）。
