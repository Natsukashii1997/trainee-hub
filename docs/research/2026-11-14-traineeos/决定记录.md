## 3. 直接吸收（不碰已定内容）

1. 知识区分「个人经验 / 待验证假设 / 正式规范」（第 12 节）。
2. 集成失败时显示同步状态和重试，不能把本地操作显示成已同步（16）。
3. 现有培养文档只作为可导入的模板，不决定产品结构（6.1）。
4. 不以签到、聊天次数、上传数量、使用时长衡量培养成效（1.3 已有，补措辞）。
5. 同一业务对象只维护一份权威记录，不同页面只是不同视角（1.4 已有，补培训安排的例子）。

## 4. Fable 5.2 独立评审的要点（已采纳）

- Hermes 进 P0 撞了 PRD 15.1「企业带教 Agent 不混入个人数字分身」：经常浩说明，带教用的是企业分身亚古兽，不是个人分身，冲突不成立；但「答疑」整体形态改为 ⑥。
- 「站 = 培养节点」映射错误：培养节点自带交付、评审、验收，对应的是培养任务（② 已按此定）。
- 「可直接吸收」里有 4 条碰已定内容（状态扩展、排期依赖、首页加块、能力维度）：已移入维持原定。
- 试点排得太晚：改为 ③ / ④。
- 其他补充：多评审人、交付物多处关联、待办对象、知识写回四处冲突（已列入维持原定）；#2 仍写「同事」角色，#6、#13、#17、#21 是 v1.1 口径（见第 5 节）；单人瓶颈，确认分批不超过 3 条。
